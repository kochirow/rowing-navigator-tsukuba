- [ ] これ以降は新機能を追加しない。修正対象を「公開ブロッカー」に限定する
- [ ] 現在の`git status --short`をレビューし、公開候補として1つのcommitにまとめる
- [ ] `version: 1.0.0+1`を初回提出番号として使うか確定する
- [x] Android/iOSの表示名を`Rowing Navigator`へそろえる

完了条件: commit hash、version/build番号、危険区域profile versionを記録し、以後の全試験で同じ版を使う。

### P0-B: 人が安全データを承認する

- [ ] 旧版と現行版の危険区域を地図上で重ね、岸・橋・島・流木を確認する

完了条件: 承認者、日付、確認したprofile versionを記録する。未承認座標を「公開済み安全範囲」として扱わない。

### P0-C: Firebase Consoleを本番状態にする

担当者がFirebase Consoleで次を手動実施する。

1. 開発用と本番用Firebase projectを分離する
2. Anonymous Authを有効にし、30日自動削除を無効のままにする
3. Firestore Database → RulesへRules Emulatorで合格した`firestore.rules`を反映し、公開する
4. Realtime Database → Rulesへ`database.rules.json`を反映し、公開する
5. Android 1台、iPhone 1台で匿名認証が成功することを確認する
6. 2台間で`live_positions`の位置共有、`temporary_obstacles`の共同編集、`managed_hazards`の更新を確認する
7. Rules Emulator 13件のログを保存し、実端末で未認証・別チーム・他UID操作が拒否されることを確認する
8. App CheckをMonitorからEnforceへ段階移行し、Spark使用量を監視する。Firestore TTLはbilling必須のため有効化しない

完了条件: 公開したrulesの日時と実機疎通結果を記録する。rulesファイルがリポジトリにあるだけでは未完了。

### P0-D: AndroidとiOSの公開署名を通す

#### Android（手動）

1. Play Console用のupload keystoreを作成し、復旧可能な場所へバックアップする
2. `android/key.properties.example`を`android/key.properties`へコピーする
3. `storeFile`、`storePassword`、`keyAlias`、`keyPassword`を設定する
4. keystoreと`key.properties`をGitへ追加しない
5. `flutter build appbundle --release`を実行し、`.aab`を生成する
6. Play Consoleでアプリを作成し、Play App Signingを有効化して内部テストへアップロードする

#### iOS（手動）

1. Apple DeveloperでBundle ID `jp.kosei.rowingnavigator.tsukuba`が登録済みか確認する
2. XcodeでTeam、Signing & Capabilities、Background Modes → Location updatesを確認する
3. `Runner.xcworkspace`を開き、Product → Archiveを実行する
4. Validate Appを通し、App Store Connectへuploadする
5. TestFlightで内部テスターへ配布する

完了条件: Google Play内部テストとTestFlightの両方から、公開候補と同じbuildをインストールできる。

## 最短ルートと推奨ルートの違い

| ルート | 配布順 | 公開前試験 | 向いている状況 |
|---|---|---|---|
| 最短 | 内部テスト → 2台一括試験 → そのbuildを一般公開審査 | 必須シナリオを1回の管理試験枠で全件合格 | 一日でも早く審査へ出したい |
| 推奨 | 内部テスト → 部内クローズドテスト → 一括試験 → 一般公開審査 | 複数練習日・複数端末で再確認 | 審査後の事故・緊急更新リスクを下げたい |

どちらでも、チーム/組織認可、署名、Firebase rules、危険区域承認、background/音声/2台通信、プライバシー申告は省略しない。詳細かつ最新の判定は[公開前チェックリスト](./store/公開前チェックリスト_2026-07-20.md)を正とする。

## 初版から外してよい項目

公開後に実装したい機能の正式な記録先は、[今後実装したい機能](./今後実装したい機能.md)とする。

- 旋回・加減速まで含む高度な予測
- 橋脚と通航口の精密分離
- 真の逆走判定
- R-tree等の性能最適化
- センサー融合
- 遠隔消音
- 監視Webページ
- バッテリー最適化や海外水域対応

これらは公開後の改善候補であり、現時点のストア公開ブロッカーではない。
