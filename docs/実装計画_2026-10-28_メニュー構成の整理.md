## 1. 探しにくい理由

| # | 問題 | 根拠 |
| --- | --- | --- |
| 1 | **「準備」が何でも入る箱になっている。** 練習(ワークアウト)、警告、危険区域、チームの4種類が同居し、名前から中身を当てられない。「チーム」は準備ではない | 中身の分からない見出しは読み飛ばされ、目的の物があっても探されない(NN/g「Category names suck」、information scent) |
| 2 | **「この端末」も同じ。** 設定(音量)、状態とプライバシー(端末とデータ)、読み物(使い方・このアプリについて)が混ざる | 同上 |
| 3 | **関係の深い物が離れている。** 「警告音の音量」は「警告の設定」と別の塊にある | Apple HIG: 使う頻度で並べても、論理的にまとまる物を引き離さない |
| 4 | **陸上でいちばん開く「練習記録」が中ほど(7番目)にある。** 準備の5項目を読み飛ばさないと届かない | 上から読むので、よく使う塊を上へ(Apple HIG、split menu の研究 Sears & Shneiderman 1994) |
| 5 | **見出しが目立たない。** 12px の灰色の文字と、背景とほぼ同じ色の線だけなので、13項目が1本の長い列に見える | 塊は見た目でも塊にする。区切り線は塊と塊の間に置き、1項目ずつには置かない(Material の navigation drawer) |
| 6 | **クレジット・オープンソースライセンスが「端末とデータ」の中にある。** 副題「GPS・安全機能の状態・プライバシー」から想像できない | 多くのアプリでは「このアプリについて」の中にある |

## 2. 方針

1. **見出しは「何が入っているか」を名詞で言う。** 「準備」「この端末」のような、用途で分けた曖昧な名前をやめる。
2. **塊の順番は、陸上でよく使う順。** 練習 → 警告と危険区域 → チーム → 使い方と情報。
3. **航行中の6項目の並びは変えない。** 漕ぎながら覚えた位置を動かさないため。陸上の並びは、航行中の6項目の順番を崩さないように組む(姿勢が変わっても、残る項目の上下関係が同じになる)。
4. **塊は見た目でも塊にする。** iOS の設定画面と同じように、塊ごとに角の丸い面へ入れる。
5. **副題の規則(2026-10-23 利用者決定)は守る。** 名前で分かる項目には説明を付けない。ただし「いま 80%」のような**状態**は出してよい(警告音の音量が前例)。

## 4. 実装

### 4.1 並びを1か所の純Dartに出す

`lib/features/home_map/map_menu_layout.dart`(新規)

```dart
enum MapMenuItemId { display, practiceRecords, workout, practiceLog, addHazard,
  warningSettings, warningVolume, calibrateFixedHazards, team, deviceStatus,
  usageGuide, aboutApp, developerDetails }

class MapMenuSlot { final MapMenuItemId id; final String? section; }

List<MapMenuSlot> mapMenuLayout(HomePhase phase, {required bool showDeveloper});
```

- どの姿勢で何をどの順・どの見出しで出すかを、ここだけで決める。`openMapMenu` は id から `MapMenuAction` を作るだけにする。
- いまは `if (isObserver)` が13か所に散っていて、並びの意図がコードから読みにくい。1か所にまとめれば、テストで並びを固定できる。
- 見出しの名前(「練習」など)もここに置く。

### 4.2 塊を面に入れる(`map_menu_sheet.dart`)

- 塊ごとに角の丸い面(`colors.canvas` の上に `colors.card`)へ入れ、面と面の間を空ける。見出しは面の外側の左上に置き、13px・太字にする。
- 見出しの無い項目(表示、航行中の全項目)は、今と同じ1枚の面にする。
- 1項目の高さは今と同じ(手袋・濡れた指でも押せる大きさを保つ)。

### 4.3 練習記録に未送信の件数を出す

- `SessionStoreService.countPendingBulkLogExports()`(新規): 記録のJSONを別 isolate で読み、`isBulkLogExportTarget` の件数を返す。
- 陸上の姿勢になったとき(地図を開いたとき・航行や監視を終えたとき)は保存を待って3秒後に、練習記録から戻ったときはすぐに数え直す。メニューを開くたびには数えない(読むのに時間がかかるため)。
- 0件なら副題を出さない。
- 安全経路には触れない。数えるのに失敗しても副題が出ないだけにする。

### 4.4 クレジットとライセンスを「このアプリについて」へ

- `about_app_screen.dart` の最後に版(`package_info_plus`)・クレジット・オープンソースライセンスのカードを置く。版が読めないときは「—」を出す(時間切れの Timer は置かない)。
- `device_status_screen.dart` からクレジットとライセンスを外す。「端末とデータ」は、状態・故障かな?と思ったら・プライバシーの3つにする(副題の言うとおりになる)。
- 「このアプリについて」は航行中のメニューに無いが、ライセンスを航行中に読む場面は無いので問題ない。

### 4.5 文書

- `CLAUDE.md` のメニューの説明と、使い方ガイド(`usage_guide/`)の中でメニューの場所を書いている文言を、新しい見出しに合わせる。
