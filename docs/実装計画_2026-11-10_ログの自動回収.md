# ログの自動回収(2026-11-10)

航行・監視を終えたら、その記録の診断ZIPを開発者の Google ドライブへ自動で送る。
これまでの「各自が LINE で送る」をなくす。

## 決めたこと(2026-11-10 利用者)

- 方式: **Google Apps Script(GAS)のウェブアプリを受け口にし、開発者のドライブへ保存する。**
  完全無料・カード登録なし・Firebase は Spark のまま。比較した案は下の「比べた案」。
- 送る時期: 航行・監視が終わったらすぐ、画面の裏で送る。
- 対象: 航行・監視の長さが **5分以上**(`autoLogUploadMinDurationSec`)。長さは記録の始まりから終わりまで。
- 同意の画面は出さない(部内向けのアプリで、利用者が直接伝える)。プライバシー画面の説明は更新する。

## 仕組み

```
航行・監視の終了
  └ SessionStoreService.finishedSessionIds / PracticeLogStoreService.finishedLogIds
      └ AutoLogUploadService(lib/services/auto_log_upload_service.dart)
          1. 送信待ちの列(SharedPreferences `auto_log_upload_queue_v1`)に足す
          2. 「まとめて送る」と同じ形のZIPを別 isolate で作る(bundle_manifest の automaticUpload は true)
          3. Firebase の ID トークン・App Check のトークン・名前を添えて GAS へ POST
          4. 送れたら送信済みの印(diagnosticsSharedAt)を付けて列から外す
      └ GAS(tool/gas/log_upload/Code.gs)
          1. ID トークンで Firestore の users/{uid} → teams/{teamId}/members/{uid} を読む(読めなければ断る)
          2. ALLOWED_TEAM_IDS があれば、そのチームだけ受け付ける(既定は空で、どのチームのメンバーでも受け付ける)
          3. 監視ログは、記録したチーム(recordTeamId)が今のチームと同じときだけ受け付ける
          4. <保存先>/<練習の日付>/<HHmm>_<名前>_<航行|監視>_<記録ID>.zip に保存
             説明の1行目 key=<チームID>/<UID>/<種類>/<記録ID> が同じファイルがあれば、ゴミ箱へ移して置き換える
```

- **送れなかったとき**: 列に残す。1分・5分・15分・1時間と間を空けて送り直す。アプリを前面に戻したときと次の起動でも送る。
  失敗した記録は列の最後へ回し、1件の不具合で他の記録が止まらないようにする。
- **評価・ひとこと**: 「今日の記録」シートを閉じたら同じ記録をもう一度送り、ドライブのファイルを置き換える。
  1回目を送っている最中に頼まれたら、送り終えた後にもう一度送る。列の読み書きは1本ずつ順に行う。
- **前のチームの記録**: 監視ログには他艇の航跡と名前が入るので、記録したチームと今のチームが違えば送らない
  (アプリでも受け口でも確かめる)。練習記録はチームを持たないが、中身は自分の航跡と他艇の仮の呼び名だけなので送る。
- **置き換えの探し方**: Drive の `title contains` は前方一致なので、末尾の記録IDでは探せない。
  日付のフォルダの中身を説明の key で完全一致させる(名前を変えても置き換わる)。
- **この版より前の記録**: 起動の10秒後に、送信済みの印が無い5分以上の記録を拾って送る(LINE で送って印を付けた記録は送らない)。
- **受け口の URL が空**(`autoLogUploadEndpoint`)なら何もしない。
- 安全経路(判定・警告・位置共有)は何も参照しない。送信の失敗で地図や航行を止めない。

### なぜ ID トークンで確かめるか

受け口の URL はアプリに入るので、誰でも知りうる。GAS は Firebase のトークンを自分では検証できないが、
Firestore REST にそのトークンで問い合わせれば、Firestore が本物かどうかと Rules(本人の users と members だけ読める)を確かめる。
偽のトークンや部外者のトークンでは読めないので、保存まで進まない。

アプリからはチームを作れるので、部外者が自分のチームを作れば「メンバー」になれる。
これを断れるのが `ALLOWED_TEAM_IDS` だが、**既定は空にして使わない**(2026-11-11 利用者決定)。
設定を誤るとログが保存されなくなる危険のほうが大きく、部外の記録が混ざっても困らないため。

## 受け口の用意(開発者が一度だけ行う)

1. https://script.google.com で「新しいプロジェクト」を作り、名前を `rowing-log-upload` などにする。
2. `コード.gs` の中身を全部消し、`tool/gas/log_upload/Code.gs` を貼り付けて保存する。
3. 「プロジェクトの設定」(歯車)で「appsscript.json マニフェスト ファイルをエディタで表示する」をオンにし、
   `appsscript.json` を `tool/gas/log_upload/appsscript.json` の中身に置き換えて保存する。
4. エディタ上部の関数の選択で `setup` を選び「実行」。許可の画面が出たら自分のアカウントで許可する
   (「このアプリは Google で確認されていません」→「詳細」→「(安全ではないページ)に移動」)。
   実行ログに保存先フォルダの URL が出る。
5. 「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」。
   次のユーザーとして実行:「自分」、アクセスできるユーザー:「全員」→「デプロイ」。
6. 表示された「ウェブアプリの URL」(`https://script.google.com/macros/s/.../exec`)を
   `lib/config/log_upload_config.dart` の `autoLogUploadEndpoint` に入れる。
7. ブラウザでその URL を開き、`{"ok":true,...}` が出ればデプロイはできている。
   これは GET の返事なので、ログインの確認・ZIPの保存・置き換えまでは分からない。
   それらは実機で5分以上の航行を終えて、ドライブにファイルが届くこと(と、評価を書くと置き換わること)で確かめる。
   届かないときは GAS の「実行数」で、`not_member` / `firestore 403` などの理由を見る。

### スクリプトを直したとき

「デプロイ」→「デプロイを管理」→ 鉛筆 →「バージョン: 新バージョン」→「デプロイ」。
URL は変わらない(「新しいデプロイ」を作ると URL が変わり、アプリの更新が要る)。

## 容量と無料枠

- 1練習の ZIP は 0.1〜1.2MB。1日10練習で月 150〜360MB。開発者のドライブ(有料プラン 5TB)に対して十分小さい。
- GAS(無料アカウント)の上限: 1回の実行6分、同時実行30、UrlFetch 2万回/日。1回の受け取りで Firestore を2回読むだけなので届かない。
- Firestore の読み取りは1回の受け取りで2回。Spark の5万回/日に対して無視できる。

## 比べた案(2026-11-10 調査)

| 案 | 無料の範囲 | カード登録 | 判定 |
|---|---|---|---|
| **GAS → Google ドライブ** | ドライブの容量 | 不要 | **採用** |
| Firestore に分割保存(2026-10-28 計画の F1) | 1GiB をアプリのデータと共有 | 不要 | 取り出しと削除の運用が要る |
| Cloud Storage(同 F2) | 5GB | 必要(2026-02-03 以降 Blaze 必須) | 「完全無料」から外れる |
| Supabase Storage | 1GB | 不要 | 1週間使わないと止まる |
| Cloudflare R2 | 10GB | 実質必要 | 認証用の Worker も要る |
| Discord Webhook | 1ファイル 10〜20MB | 不要 | URL を知れば誰でも投稿できる |
| GitHub リポジトリ | 数GB | 不要 | 書込トークンをアプリに入れることになる |

## 確かめていないこと

- 実機から GAS への送信と、ドライブへの保存・置き換え(受け口の URL が入った版で確かめる)。
  GAS の処理は Apps Script のサービスを模した Node のテストで確かめた(置き換え・チーム違い)。
- Firestore で App Check が Enforce のとき、GAS からの REST 問い合わせが App Check のトークンで通るか
  (アプリは毎回トークンを添える。通らなければ `firestore 403` が実行ログに出る)。
- GAS の doPost に送れる大きさの上限(公式の記載なし。体験談で 20〜30MB。いまの ZIP はその 1/20 以下)。
