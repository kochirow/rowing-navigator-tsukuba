# 実装計画 2026-10-20 使い方ガイドと初回案内

初めて使う人が、人に聞かずに出艇と監視まで進めるようにする。対象は次の3つ。

- A. 「故障かな？と思ったら」(仕様なのに故障に見える挙動の一覧)
- B. 「使い方」画面を、航行・監視・管理の役割ごとに組み直す
- C. 初回起動時の案内(4枚・スキップ可)

アプリ外の配布物(印刷用1枚・講習資料)は今回の範囲に入れない。

## 1. 前提

### 1.1 いまあるもの

- メニュー「使い方」(`lib/screens/usage_guide_screen.dart`)。1枚の長いページに、
  警告の3段階・警告の読み方・地図の色・橋脚の登録・警告音の試聴・このアプリの限界が並ぶ。
  秒数はナビの値を引数で受け取っており、設定と説明がずれない作りになっている。
- チーム参加画面(`team_onboarding_screen.dart`)。作成/参加の二択と利用規約。
- バックグラウンド位置情報の説明ダイアログ。航行スタート時に出る。
- 「端末とデータ」(`device_status_screen.dart`)。GPS精度・最終測位・安全機能の状態。
- アプリ外: `docs/配布/` の導入手順画像(Android/iOS)、`docs/store/サポートページ案.md`。

### 1.2 足りないもの

- 最初に何をすればよいかの順序。チームに入ると地図が出るだけで、次の一手が示されない。
- 役割の区別。漕ぐ人と陸で見る人ではやることがまったく違うが、説明は混ざっている。
  「橋脚の登録」のような管理者向けの内容が、初心者向けの警告の説明と同じページにある。
- 仕様上の静音や表示のみの挙動の説明。これを知らないと「鳴らない＝壊れた」と判断され、
  使われなくなる。設計原則4が防ごうとしている事態と同じ結果になる。

### 1.3 いまの説明が画面と合っていない

2026-09 の画面刷新で航行中の警告表示が変わったが、使い方画面の説明は刷新前のままである。

| 項目 | いまの説明 | 実際の航行画面 |
| --- | --- | --- |
| 警告の見た目 | 連続音は「太い枠が明滅」、断続音は「濃い色で表示」 | 予告も本警告も同じ見た目で、相手のいる側の画面の縁が赤く点滅する(`edge_alert_overlay.dart`)。向きが分からないときは縁の全周が光る |
| 警告の読み方 | 1行目が対象、2行目が「右 5秒」 | 警告バナーは航行画面から外した。対象は音声で告げる |
| 地図の色 | 種類ごとの色(岸・橋・中州…)の凡例だけ | 航行中は夜の配色に固定。固定の危険区域はすべて琥珀、岸は白い細線、他艇は赤、自艇は白(`hazard_palette.dart`・`boat_palette.dart`)。種類ごとの色は待機中と監視中の地図 |

B ではこれを画面どおりに直す。案内を足すより先に、間違った説明を正すほうが優先度が高い。

### 1.4 守ること

- 航行中の画面には何も足さない。漕手は航行中に端末を触れず、文章も読めない
  (DESIGN_PRINCIPLES 1.3、メモ navigation-screen-no-reading)。
  案内はすべて出艇前・監視中・メニューの中で完結させる。
- 案内を読み終えることを、航行開始・監視開始の条件にしない(不変条件5、原則1・2)。
- 秒数・速度などの数値は本文に直書きせず、`lib/config/` の定数かナビの値から差し込む。
  既存の使い方画面と同じ方式で、設定を変えたときに説明だけが古くなるのを防ぐ。
- 安全経路には触れない。追加する状態は「初回案内を表示済みか」の端末内フラグ1つだけ。
- 競技用語(SR・DPS・/500m・chrono)は言い換えない。

## 2. 一般的なアプリの調査

### 2.1 初回案内

Apple の Human Interface Guidelines(Onboarding)の要点は次のとおり。

- 別建てのチュートリアルは任意にする。初回にスキップされたら次回以降は出さないが、
  後からヘルプや設定の中で見つけられるようにしておく。
- 長い案内より、操作中のその場の短いヒントのほうが覚えやすい。必須の導入は短くする。
- 端末やOSの使い方は教えない。アプリ固有のことだけを扱う。

Material Design(旧版の Onboarding)は、初回体験を3つの型に分けている。

- Self-select: 最初に少数の選択をさせ、その後の体験を分ける。選択は意味があり、短いこと。
  アプリが推測できる好みは聞かない。
- Quickstart: 説明なしでアプリ本体へ入れる。見慣れたUIのアプリ向け。
- Top user benefits: 利点を最大3つ見せるカルーセル。Self-select と組み合わせない。

このアプリは「漕ぐ」と「陸で見る」で使い方が分かれるので、Self-select が合う。
利点のカルーセルは作らない。

### 2.2 トラブル対応の見出しと構成

日本の取扱説明書では「故障かな？と思ったら」が定着した見出しである
(Sony Xperia のヘルプガイド、au のオンラインマニュアル、docomo のスマホ故障診断の説明文)。
項目は利用者の言い方で書いた症状(「アプリが正しく動作しない」など)を見出しにし、
その下に確認することを並べる。

一般的なアプリのFAQ(LINE の通知トラブルを扱う解説記事など)の並びは、
基本の確認 → 端末(OS)側の設定 → アプリ内の設定 → 問い合わせ、の順が多い。

### 2.3 文言の方針

- 「困ったとき」「お役立ち情報」「ポイント」「大切なこと」は使わない。
  症状と対処を探しに来た人に、何のページかが伝わらない。
- トラブルの見出しは「故障かな？と思ったら」にする。
  このアプリで載せる項目の大半は「故障ではなく仕様」であり、見出しの意味と中身が一致する。
- 各項目の見出しは利用者が口にする症状にする(「音が鳴らない」「他の艇が地図に出ない」)。
  仕組みの名前(「低速静音」「陸上判定」)を見出しにしない。
- 本文は「理由」と「すること」の2段にする。「〜しましょう」「安心してください」は使わない。
- 章の名前はボタンの名前に合わせる(「航行」「監視」)。
  画面上の「航行スタート」「監視スタート」と同じ語なので、どこの説明かを探さずに済む。
- ボタンは一般的な語にする: 「スキップ」「次へ」「はじめる」。

## 3. A: 故障かな？と思ったら

使い方画面の1ページとして作る。「端末とデータ」画面の末尾からもこのページへ飛べるようにする
(現地で「鳴らない」と言われたとき、最初に開かれるのが「端末とデータ」なので)。

載せるのは「故障に見えるが仕様」の挙動と、本当に設定を直す必要がある挙動だけにする。
質問への答え(「常に許可」を求められる理由など)は、該当する章(航行)へ置く。

| 症状(見出し) | 理由 | すること |
| --- | --- | --- |
| 止まっている・ゆっくり進んでいると、橋や岸の音が鳴らない | 分速100m未満が続く間、橋・橋脚・岸・逆走の音を止めている。止まっている間は、固定の危険区域の音も止める。休憩中やコーチの指示を聞く間に鳴らないようにするため。画面の表示は続き、他の艇の警告は止めない(`lowSpeedAudioMute*`・`lowSpeedMutedCategories`・`stableStop*`) | 故障ではない。漕ぎ出せば戻る |
| 陸に上がったら音が止まった | 岸より陸側に30秒いると音だけ止め、画面上部に帯を出す。水面に戻れば測位1点で戻る(`ashoreConfirmationDuration`) | 故障ではない。水上なのに帯が出たら「音を戻す」を押す |
| 岸の近くを走っても鳴らない | 川幅が狭く岸は常に近いので、近いだけでは鳴らさない。このまま進むと当たる見込みが出たときに鳴る(`audibleProximityCategories`) | 故障ではない |
| 画面上部に「GPS」「受信」が出たのに音が鳴らない | 測位や通信の不調は画面表示だけで知らせ、音にはしない。読み上げると、本当に鳴るべき衝突警告と重なるため | 空が開けた場所へ出る。通信を確かめる。「端末とデータ」で状態を見る |
| 他の艇が地図に出ない | 同じチームでない、相手が航行スタートしていない、通信が切れている、のいずれか。途絶えた艇は30秒で地図から消える(`boatStaleTimeoutSeconds`) | 相手のチーム名を確かめる。画面上部の「受信」表示を見る |
| 警告が鳴ったのに画面の縁の一部が光らない | 回頭中や低速時は艇の向きが確かでないので、向きを出さず縁の全周を光らせる。誤った側を振り向かせないため(不変条件10) | 故障ではない。周りを見回す |
| 音がまったく出ない | 端末の音量・消音モード・Bluetooth の接続先のいずれか | 使い方の「警告音の試聴」で確かめる |
| 監視中に画面が消える | 監視中は画面を点けたままにしない。陸上では手で戻せるため。航行中は点けたままにする | 故障ではない |
| 監視中、止まった艇がいても音が鳴らない | 監視中の異常(3分止まっている・90秒更新がない)は、地図上の件数表示と艇一覧で知らせ、音は鳴らさない。トランシーバーの音声と重なるため(`stoppedAlertSec`・`lostAlertSec`・`coachAudibleAnomalyKindNames`) | 地図上の件数表示を押して艇一覧を開く |
| チームに入れなくなった | 端末の認証情報が消えた場合に起きる。再インストールすると戻せなくなることがある | 再インストールせず、招待コードで参加し直す |

霞ヶ浦でレーンの警告が出にくい件(DESIGN_PRINCIPLES 1.2b)は、霞ヶ浦で使う利用者が出てから載せる。

最後に問い合わせ先(サポートページ・通報フォーム。チーム参加画面と同じリンク)を置く。

## 4. B: 使い方画面の組み直し

### 4.1 構成

トップを目次にし、項目ごとにページを分ける。

```
使い方
├ (常に1行) このアプリが検出できるもの・できないもの
├ はじめての案内をもう一度見る      … C をここから再表示
├ 航行                              … 漕ぐ人
│   出艇前: 端末の固定・音量・航行スタートの設定シート・「常に許可」の理由
│   航行中: 警告音の鳴り方・画面の縁の赤い点滅・計器(/500m・SR・距離・chrono)
│   航行後: 練習記録・GPX
├ 監視                              … 陸で見る人
│   監視スタート・艇の色と航跡・異常の件数表示と艇一覧・練習一括ログ(オフにできない)
├ 地図と警告音                      … 現行ページの中身を画面どおりに直して移す(1.3)
│   警告の3段階・地図の色(航行中/それ以外)・警告音の試聴
├ チームと危険区域                  … 管理する人
│   招待コード・臨時危険区域の追加・既設危険区域の位置の調整・橋脚の登録
└ 故障かな？と思ったら              … A
```

「このアプリでできないこと」は独立ページにせず、トップの先頭に常に出す
(検出できるのはアプリで位置を共有している艇と登録済みの危険区域だけ、衝突回避は保証しない)。
ページを分けると開かれなくなるため。

### 4.2 ファイル

- `lib/screens/usage_guide_screen.dart`: 目次に変える。数値の引数はそのまま受け取り、下位ページへ渡す。
- `lib/screens/usage_guide/`: 各ページと共用部品(`_Section` などを移す)。
- `lib/screens/device_status_screen.dart`: 末尾に「故障かな？と思ったら」への行を足す。
- `lib/screens/home_map_screen.dart`: メニューの「使い方」の副題を目次に合わせて直す。

## 5. C: 初回の案内

### 5.1 出す条件

- 地図が出て待機中のときに1回だけ出す。航行中・監視中には出さない。
- 一度表示したら、最後まで見てもスキップしても再表示しない(Apple の指針どおり)。
  使い方のトップから何度でも開ける。
- 既存の利用者には出さない。保存済みの航行設定(名前)がある端末は表示済みとして扱う。
  監視しかしたことのない端末には1回出るが、スキップできるので許容する。
- フラグは `SharedPreferences` の `first_run_guide_seen_v1`。読み書きに失敗しても地図は普通に使える
  (失敗時は表示しない側に倒す。案内が毎回出るほうが邪魔になる)。

### 5.2 画面(4枚)

1. このアプリでできること・できないこと
   同じチームで位置を共有している艇と、登録済みの危険区域に近づくと音で知らせる。
   衝突回避は保証しないので、周りは自分の目で確かめる。
2. 使い方を選ぶ: 「航行する(艇に乗る)」/「監視する(陸から見る)」
   選択は次の1枚の中身を変えるだけで、記憶もしないし機能も制限しない。
3. 選んだ役割の最初の手順
   - 航行: 端末を艇に固定する → 音量を上げる → 「航行スタート」。航行中は画面を触らなくてよい
   - 監視: 「監視スタート」→ 全艇の位置と航跡が出る。記録は自動で残る
4. 警告の聞き方: 連続音・3秒ごと・表示のみの違いを3行で示し、「他艇に注意」の試聴ボタンを置く。
   画面の縁が相手のいる側で赤く点滅することも1行で添える

各画面の右上に「スキップ」、下に「次へ」、最後は「はじめる」。

バックグラウンド位置情報の説明は、今までどおり航行スタート時に出す。
ストア審査上、許可を求める直前に説明する必要があるため、案内の中へは移さない。

### 5.3 ファイル

- `lib/screens/first_run_guide_screen.dart`: 案内本体(`PageView`)。
- `lib/services/first_run_guide_store.dart`: 表示済みフラグの読み書き。
- `lib/screens/home_map_screen.dart`: 待機中の初回だけ案内を開く。

## 6. テスト

- 使い方画面: 目次から各ページへ進めること。既存テスト(秒数が設定値どおり出る・橋脚の登録の文言)は
  移動先のページで通るように直す。古い説明(「太い枠」「右 5秒」)が消えたことも確かめる。
- 故障かな？と思ったら: 秒数・速度が設定値から出ていること。
- 初回案内: 未表示なら1回出る・スキップで二度と出ない・保存済みの名前がある端末では出ない・
  フラグの読み書きが失敗しても例外を出さない。
- `dart analyze lib test tool` と `flutter test`。

## 7. 進め方

B・A・C を1本のPRにまとめる。いずれも表示だけの変更で、C の「もう一度見る」は B の目次に置くので、
分けると目次を2回触ることになる。コミットは B+A と C に分ける。

## 8. 計画の見直しで直した点(2026-10-20)

- 現行の使い方画面の警告と地図の説明が、刷新後の航行画面と合っていないことをコードで確かめ、1.3 に表で残した。
  当初は「照合が要る」としていた。
- 「止まっていると鳴らない」と「ゆっくりだと鳴らない」を1項目にまとめた。利用者からは区別がつかない。
- 陸上判定の帯にある「音を戻す」ボタンを、すること欄に入れた。
- 監視中の異常が無音であること(`coachAudibleAnomalyKindNames` が空)を項目に足した。
- 「常に許可」を求められる理由は故障に見える挙動ではないので、航行の章へ移した。
- 「このアプリでできないこと」を独立ページからトップの常設1行へ変えた。
- PRを2本から1本にした。

範囲外で見つけた点: CLAUDE.md の「橋は連続音まで上げない(`bandCappedCategories`)」は、
現行コードでは `bandCappedCategories` が空集合になっており、記述が古い。
