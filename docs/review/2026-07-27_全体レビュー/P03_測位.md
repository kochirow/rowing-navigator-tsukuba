## 1. Kalman フィルタを手で検算した

`RobustPositionEstimator` は 4状態（east, north, vEast, vNorth）を、east ブロックと north ブロックの独立した 2×2 として保持する。**予測式・更新式をすべて展開して確認し、誤りはなかった。**

### 1.1 予測（`_predict`）

離散白色加速度雑音モデル（DWNA）の標準形

```
Q = q · [[dt⁴/4, dt³/2], [dt³/2, dt²]]
```

に対し、実装（`:465-480`）は

```
P_pp += 2·dt·P_pv + dt²·P_vv + 0.25·dt⁴·q
P_pv += dt·P_vv + 0.5·dt³·q
P_vv += dt²·q
```

これは `P ← F P Fᵀ + Q`（F = [[1, dt], [0, 1]]）の展開と**完全に一致する** ✓

### 1.2 位置更新（`_updateEastPosition` / `_updateNorthPosition`）

H = [1, 0] のスカラー更新。実装は `P_pv' = P_pv(1 - K_pos)` と書いているが、教科書形は `P_pv' = P_pv - K_vel·P_pp`。

```
K_vel = P_pv/(P_pp+R) なので
P_pv - K_vel·P_pp = P_pv·(1 - P_pp/(P_pp+R)) = P_pv·R/(P_pp+R) = P_pv·(1 - K_pos)
```

**恒等的に等しい** ✓ 対称性も保たれる。

### 1.3 速度更新（`_updateEastVelocity` / `_updateNorthVelocity`）

H = [0, 1] で同様に確認。`P_pv' = P_pv(1 - K_vel)` と教科書形 `P_pv - K_pos·P_vv` も同じ変形で一致する ✓

### 1.4 共分散の非負性

- 位置更新後 `P_pp' = P_pp(1 - K_pos) ≥ 0` ✓
- 速度更新後 `P_pp' = P_pp - K_pos·P_pv = P_pp - P_pv²/(P_vv+R)`。共分散行列が半正定値なら `P_pv² ≤ P_pp·P_vv < P_pp(P_vv+R)` なので **正** ✓

逐次スカラー更新は厳密演算では半正定値を保つ。3変数（P_pp, P_pv, P_vv）で持つ構造上、対称性は自動的に保たれる。

### 1.5 プロセスノイズの非等方化

`_predict:454-457` は surge/sway の分散を east/north 軸へ射影し、east-north 間の相関項を落とす（対角近似）。

```
Var_east  = surge·sin²θ + sway·cos²θ
Var_north = surge·cos²θ + sway·sin²θ
```

これは回転後の共分散行列の**対角成分そのもの**なので、周辺分散は厳密。失われるのは相関だけで、結果として不確実性の楕円が艇の向きに沿わず軸平行になる＝**真の楕円を含む過大側**になる。安全側であり、コメントにも「対角近似」と明記されている ✓

### 1.6 方位の符号系

- `_velocityObservation`: east = v·sin(θ), north = v·cos(θ)（北基準・時計回り）
- `_result.headingDegrees`: `atan2(vEast, vNorth)`
- `_predict`: `sinHeading = vEast/speed`, `cosHeading = vNorth/speed`

3箇所すべて同じ規約 ✓ `_normalizeHeading` / `_normalizeLongitude` も正しい。

### 1.7 再捕捉ロジックの追跡

「単発の外れ値でフィルタがリセットされてしまうのでは」と疑って追跡したが、**そうならない**。

1. 外れ値が hard gate を超える → `_recordReacquisitionCandidate` で `_pendingCount = 1`、`rejected` を返す
2. 次の正常な測位 → `_pendingCount > 0` なので候補として記録（2）。ただし 3 未満なので再捕捉せず、**hard gate 内なので `:325` の `_clearPendingReacquisition()` が走り 0 に戻る**
3. 結果、再捕捉が起きるのは **3回連続で hard gate を外れ、かつその3点が互いに 12m/s 以内で整合している**場合だけ

意図どおり ✓

## 3. 指摘

### P3-01（S3・要確認）`accuracy <= 0` の測位を2箇所で無条件に棄却している

- `gps_position_filter.dart:55` — `position.accuracy <= 0` なら `accepts` が false
- `robust_position_estimator.dart:365` — `accuracyMeters > 0` を必須条件にする

iOS では `horizontalAccuracy < 0` が「無効」を意味するので棄却は正しい。一方 **Android の一部端末・エミュレータは accuracy を `0.0` として報告する**ことがある。その場合、座標自体は妥当でも全ての測位が落ち、`GpsHealthMonitor` が `unusable` へ落ちて `gps_unavailable` の system fault（音声つき）が 10 秒後に鳴り始める。

- 原則6（データ欠損は安全の根拠にならない）の観点では「精度が不明」を「使えない」と同一視している。
- 妥当な代替は、`accuracy <= 0` を「不明」として `assumedGpsAccuracyMeters`（5.0m）や `minimumAccuracyMeters`（4.0m）で置き換え、縮退運転として続けること。
- **どの端末で実際に 0 が来るかは実機でしか分からない**ため、判断は利用者に委ねる（下記4）。

### P3-02（S3）再捕捉用の定数が GNSS 速度観測の妥当性ゲートに流用されている

- `robust_position_estimator.dart:558` — `speedMetersPerSecond > maximumReacquisitionSpeedMetersPerSecond` なら速度観測を捨てる。
- この定数（既定 12 m/s）の宣言コメントは「再捕捉候補間で許容する最大速度」（`:94`）であり、**GNSS が報告する速度の妥当範囲という意味は書かれていない**。
- 再捕捉のしきい値を調整すると、GNSS 速度観測を受け入れる範囲まで黙って変わる。艇の現実的な最大速度（`maxAcceptedGpsSpeedMetersPerSecond` = 10 m/s が `navigator_config` にある）とも別の値になっている。
- 設定値の意図と実効値の乖離であり、CLAUDE.md「設定値には前提を書く」（原則7）に触れる。

### P3-03（S3）共分散に数値的な下限クランプがない

- `_updateEastPosition` などは理論上は非負を保つ（1.4）が、`double` の桁落ちで `P_pp` がわずかに負になる可能性は排除されていない。
- 負の分散になると `normalizedInnovationSquared` の分母が小さくなり、正常な測位が hard gate で棄却され続ける経路がありうる。
- 現実には `measurementVariance`（最低 4² = 16）が分母に必ず加わるので、分母が 0 以下になるにはかなりの桁落ちが要る。**予防的な指摘。**

### P3-04（S3・記録のみ）長い予測ギャップで不確実性が大きく育つ

- `maximumPredictionGap` = 5 秒。ギャップ 5 秒・等方ノイズ 1.2 m/s² のとき、位置分散の増分は `0.25·dt⁴·q = 0.25·625·1.44 ≈ 225 m²`（σ ≈ 15 m）。
- `uncertaintyMeters` は 95% 相当（×2.448）なので 36 m 程度になりうる。この値がどこで安全判定に使われるかは P8 で確認する。
