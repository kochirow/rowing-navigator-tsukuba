## 1. 確認した範囲

### 1.1 練習ログは端末内に留まる（プライバシー）

`session_store_service.dart:9` — 「練習セッションの永続化（**端末内JSONファイル**）」。
外部送信の経路は見当たらない。CLAUDE.md の「サーバー送信なし」と一致 ✓
アカウント削除用に全記録を消す経路もある（`:84`）✓

### 1.2 監視（コーチ）機能の既定が無音

`coach_config.dart` の `coachAudibleAnomalyKindNames` が空集合。
DESIGN_PRINCIPLES 1.3「コーチ艇はいない」・1.4「監視者は陸上にいる」から導かれた選択で、
「実運用ではトランシーバーアプリ（Buddycom）の音声と干渉し、艇庫周辺の近隣にも響く」という
現地の事情まで根拠として書かれている ✓

トレードオフ（監視者が画面から目を離している間、沈・電池切れへの気づきが遅れる）も明記され、
種類ごとに音を有効化できる形（`{'stopped'}` など）が残されている ✓

### 1.3 `lostAlertSec` = 90秒 の根拠

「45秒では、停止中送信10秒 + 画面OFF + 通信ジッタで日常的に成立し、
実機テストで『細かいエラーを大きく伝えすぎ』という指摘につながった」と、
**実機テストのフィードバックが設定値の根拠として残っている** ✓ 原則4 の実践例。

### 1.4 config が hooks を import しない工夫

`coach_config.dart` が `BoatAnomalyKind`（`use_coach_watch.dart` にある enum）を
**String の集合**で持つ理由が詳細に書かれている:
レイヤーの逆流（Presentation → Hooks → Services → API → Models）を避け、
設定値1つを読むために Flutter/hooks 一式を巻き込まないため。かつ循環 import を避けるため。
綴り誤りは `use_coach_watch_test.dart` が検出する ✓

**アーキテクチャ規約を守るためのコストと、その埋め合わせ（テスト）が両方書かれている。**
