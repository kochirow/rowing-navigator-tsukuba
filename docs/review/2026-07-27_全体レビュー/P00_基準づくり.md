## 3. 指摘

### F-01（S2候補・P6で確認）警告時間を下限5秒にすると連続音バンドが予測地平を超える

- `defaultWarningTimeSeconds`=10.0 と `intermittentAudioDeadline`=10s を一致させる不変条件は、**既定値のときだけ**成立する。
- 利用者は `minWarningTimeSeconds`=5.0 まで下げられる（`risk_evaluator_config.dart:12`）。5秒にすると予測地平5秒 < `continuousAudioDeadline`=7秒となり、**連続音バンド(TTE≤7s)の上側2秒が原理的に空になる**。連続音は「予測が届く5秒以内」でしか鳴らなくなる。
- 25秒に上げた場合は逆に、10〜25秒の脅威が `monitoring`（表示のみ）に落ちる。こちらは意図通りに読めるが、**設定画面が「何秒前に警告」と説明しているなら、音が鳴るのは10秒前のままである**という乖離がある。
- 再現条件: 設定で警告時間を5秒にする → 7秒後に到達する他艇が検知されない → 連続音が鳴らない。
- 確認先: `alert_presentation_config` の deadline が保存設定値と連動しているか（P6）。連動していなければ設定値の意図と実効値の乖離。

### F-02（S3・P0で確定）`boat_config.dart` に根拠コメントが一切ない

- 他の15ファイルは全て「なぜこの値か」を書いてある。`boat_config.dart` だけが裸の数値。
- 特に `stoppingDistanceFormula` の第2項の係数（3.45 / 3.10 / 3.18 / 4.65）は艇種ごとに異なるのに出典がなく、**変更してよいか誰も判断できない**。
- 排他領域の `s`（1x: 4→5.8、8+: 16→18.88）の増分も艇種ごとにばらばらで、不変条件9（`s <= h` で凸を保つ）との関係が読めない。
- CLAUDE.md「設定値には前提を書く」（原則7）に反する唯一の箇所。

### F-03（S1候補・P9で確認）アプリ版が違う艇は互いに完全に見えなくなる

- `supportedPositionAppVersions = {currentPositionAppVersion}` = `{'1.0.0'}`（`protocol_config.dart:10`）。
- `RemoteBoatMessage.tryParse` は `appVersion` が集合に含まれないと `unsupportedAppVersion` で**メッセージ全体を捨てる**（`remote_boat_message.dart:96`）。
- `grep` の結果、`unsupportedAppVersion` を扱うコードは `remote_boat_message.dart` の外に**存在しない**。捨てたことを利用者へ伝える経路がない。
- 帰結: 1.0.1 を配信した瞬間、更新した艇と未更新の艇は**通信仕様が同一でも互いに地図から消え、衝突警告の対象から外れる**。同じ艇庫から同時に出る2〜12艇（1.3）で版が揃う保証はない。
- コメントは「差し戻し再申請（+2, +3...）で互換性を壊さない」ことは考慮しているが、**利用者間の版ずれ**は考慮していない。
- 原則6「データ欠損は安全の根拠にならない」に抵触する可能性が高い。確認先: 拒否時に system fault が立つか、`other_boat_receive_unavailable` に計上されるか（P9）。
- **利用者確認（2026-07-27）: この挙動は意図したものではない。S1 として記録し、P15 の修正候補に入れる。**

### F-04（S3・P0で確定）`supportedPositionProtocolVersions` が実効を持たない

- `protocol_config.dart:9` で定義しているが、`tryParse` の既定引数は `const {currentProtocolVersion}` とインラインで書かれている（`remote_boat_message.dart:67`）。
- 現状は両方 `{1}` なので挙動は同じだが、**config 側を広げても何も起きない**。設定値と実効値の乖離そのもの。
- `lib` 内・`test` 内ともに参照0。
