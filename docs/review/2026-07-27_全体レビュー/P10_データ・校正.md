### 1.2 P4-01（逆向き航行で中心線予測が効かない）— **実運用で確実に発生することを確認**

- `sakuragawa_obstacles.json` のトップレベルキーは
  `version / area / source / notice / howToEdit / defaultObstacleProximityCautionMeters /
  practiceArea / operationalCoveragePolygon / dangerZoneBaselines / obstacles`。
  **`channelCenterline` キーは存在しない。**
- したがって `preset_obstacle_service.dart:606` の `fromShorelines(firstShore: shores[0], secondShore: shores[1])`
  が常に使われ、**中心線の向きは `dangerZoneBaselines` の最初の岸の digitize 方向で一意に決まる**。
- 桜川は往復コースなので、**復路は必ず `alongSpeed < 0` になり、直線予測へ縮退する**。

**P4-01 は「起こりうる」ではなく「航行時間の約半分で必ず起きている」。** S2 を維持する。

なお、`channelCenterline.points` を明示すればこの向きを制御できるが、
**向きを変えても「片方向だけが恩恵を受ける」構造は変わらない。** 修正すべきは
`channel_path_predictor.dart:94` の条件そのものである。

### P10-02（S3）中心線が「導出」に依存しており、その向きが安全挙動を変える

- 1.2 のとおり、中心線の向きは岸基準線の digitize 順という**データ入力時の偶然**で決まる。
- その向きが `alongSpeed <= 0`（P4-01）と `reverseGuidanceHeadingErrorDegrees`（逆走判定）の
  両方に効く。**データの並び順が安全挙動を変える**という依存は、`howToEdit` に書かれていない。
- 逆走判定については `crossMeters > 0 ? tangent : tangent + 180`（`collision_risk_evaluator_service.dart:862`）
  で左右レーンから規定方位を導くため、中心線の向きが反転しても判定は対称に保たれる ✓
  **影響を受けるのは予測（P4-01）だけ。**
