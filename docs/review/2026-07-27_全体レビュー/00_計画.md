# 全体レビュー計画（2026-07-27 開始）

## 目的

実装全体を、抜け漏れなく、複数回に分けてレビューする。
1回のセッションで全部を見ようとすると必ず抜けるため、スコープを区切って積み上げる。

## 対象

現在のワーキングツリー全体（HEAD との差分ではない）。
設計原則との整合を見るには差分レビューでは足りないため。

## 運用ルール

- **段ごとに実行する**（2026-07-27 に方針変更。当初は1パスずつ報告だった）。
- **指摘のみ。修正はしない。** 全パス完了後、P15 で優先度を確定してから修正に入る。
  レビュー中にコードが動くと、後のパスの前提が崩れるため。
- 記録は `docs/review/2026-07-27_全体レビュー/PXX_<スコープ>.md` に1パス1ファイル。
- 各パスの手順:
  1. 対象ファイルを**全行読む**（抜粋読みはしない。境界条件は抜粋の外にある）
  2. 該当する不変条件・設計原則を明示的に列挙してから照合する
  3. 指摘は `S1 安全に直結 / S2 正しさ・堅牢性 / S3 保守性` で分類し、
     **再現条件（入力 → 誤った出力）を必ず書く**
  4. 「テストがない」は指摘とは別枠で記録する（修正とテスト追加は別作業）
  5. 次パスへ持ち越す疑問（他ファイルを見ないと判断できない事項）を明記する

## 前提として使う事実

- CI（`.github/workflows/ci.yml`）が analyze / format / test / hazardハッシュ / 音圧 を担保している。
  **CIが見られない層に集中する。**
- 中核4ファイルは1パス1ファイルにする（各1,200行超）。
