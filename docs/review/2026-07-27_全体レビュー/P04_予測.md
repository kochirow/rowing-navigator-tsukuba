## 1. 検証して正しかったこと

### 1.1 曲線座標の符号系が3箇所で整合している

`crossMeters` は「接線から見て右が正」と定義されている（`channel_centerline.dart:181`）。3つの実装を突き合わせた。

| 箇所 | 式 | 確認 |
| --- | --- | --- |
| `project:233` | `cross = oE·tN - oN·tE` | 北向き接線 (0,1) に対し東 (1,0) の点 → +1 = 右 ✓ |
| `toLatLng:190-191` | `right = (cos θ, -sin θ)` | 前方 (sinθ, cosθ) を時計回り90度 → (cosθ, -sinθ) ✓ |
| 両者の関係 | `cross = offset · right` | 展開すると `oE·cosθ - oN·sinθ` で `project` と一致 ✓ |

**`project` と `toLatLng` は互いの逆変換として整合している。**

### 1.2 `_bearingOfSegment` の規約

`atan2(dx, dy)`（dx = east, dy = north）→ 北基準・時計回り ✓
`_toLocal` / `_toLatLng` も east/north の順で一貫している。

### 1.3 P1 持ち越し3（`getHeading` の -180〜180）は解決済み

`channel_path_predictor.dart:232-236` に専用の `_bearing` ラッパがあり、コメント付きで 0〜360 へ正規化している。

```dart

```

**呼び出し側が符号系の違いを認識して明示的に処理している。** 良い形。

### 1.4 曲率マージンの式

`_segmentsFromPoints:189-190` の `segmentLength · turnRadians / 8` は、円弧を弦で近似したときのサジッタ（弦の中央のずれ）である。

```
s = R(1 - cos(θ/2)) ≈ R·θ²/8、L = R·θ  →  s ≈ L·θ/8
```

**近似として正しい** ✓ `maxChannelCurvatureMarginMeters`（3.0m）で頭打ちにしている。

### 1.5 `fromPolyline` の重複頂点処理

`:82-95` — `step < 1e-3` のとき `continue` するが、`cumulative.add` はその前段の分岐内にあるため、**3つのリスト（east / north / cumulative）が同期を崩さない** ✓ 読みにくいが正しい。

### 1.6 縮退経路（不変条件4）

`ChannelPathPredictor.predict` は次のすべてで等速直線1区間へ縮退する。

- `enableChannelAwarePrediction` が false
- 中心線が null
- 速度 0 / 地平 0 / `maxSegments <= 1`
- 投影が端点へ張り付いた（`isInsideCoverage == false`）
- 中心線から `maxChannelProjectionOffsetMeters`（80m）超
- 中心線の終端を超えた（以降は直線で伸ばす `_appendStraightTail`）

`ChannelCenterline.fromPolyline` / `fromShorelines` も、条件を満たさなければ null を返す設計（`:66` / `:143`）。**「中心線が作れなければ従来経路」が徹底されている** ✓

`_appendStraightTail` の時間配分も検算した。`consumedSegments = index - 1` の時点で `points.length == index`（＝ index-1 区間）なので、`remainingSeconds = horizon - step·(index-1)` を最終区間へ与えると合計が正確に `horizon` になる ✓

## 2. 指摘

### P4-01（S2）中心線と逆向きに進む艇は、常に直線予測へ縮退する

これが本パス最大の所見。

- `channel_path_predictor.dart:94` — `alongSpeed <= 0` なら直線予測を返す。
- `alongSpeed = speed · cos(heading − tangentBearing)` なので、**中心線の digitize 方向と逆向きに漕いでいる艇は必ず負**になる。
- `test/services/channel_path_predictor_test.dart:152`「川を横断・逆行する向きでは直線予測へ戻す」が、`heading: tangent + 180` すなわち**完全な逆向き**でこの挙動を固定化している。

**なぜ問題か。**

桜川の練習は、艇庫から出て上流（または下流）へ行き、折り返して戻ってくる。つまり**航行時間のおよそ半分は中心線と逆向き**である。その半分の時間、航路中心線予測は一切効かない。

CLAUDE.md の提示ポリシーは、この機能が無い場合に何が起きるかを明記している。

> 直線予測のままだと、5m/sで7〜10秒先(35〜50m)はカーブで外岸へ5m以上膨らみ、蛇行区間のたびに音が鳴ってしまう。

`risk_evaluator_config.dart:160-171` も同じ趣旨で「カーブでは外岸へ突っ込む予測になって誤警告を生み、曲がった先の危険は見落とす」と書いている。**つまり折り返して戻る側の航程では、この機能が解決したはずの過剰警告がそのまま残っている。**

**幾何的には制限する理由がない。** 曲線座標の積分 `along = frame.along + alongSpeed·t` は `alongSpeed` が負でも正しく中心線を逆向きに辿る。`toLatLng` も `along` の値だけを見るので符号を問わない。終端を超える場合は既に `:116` で `along < 0` を検査して `_appendStraightTail` へ落ちるようになっており、**負方向の受け皿はすでに実装されている**。

- 再現条件: 中心線が上流→下流の順で定義されている川で、下流→上流へ漕ぐ（またはその逆）。カーブ区間で 7〜10 秒先の直線予測が外岸の危険区域と重なり、`approaching`（3秒間隔の断続音）以上が鳴る。
- 帰結の分類: **過剰警告**（原則4「過剰警告は安全機能の破壊である」）。警告漏れ方向ではない。
- 「横断」（heading ⊥ tangent、`alongSpeed ≈ 0`）を除外するのは妥当。除外すべきは `alongSpeed ≈ 0` であって `alongSpeed < 0` ではない。

**テストが現在の挙動を固定しているため、修正するならテストの意図から見直す必要がある。** テスト名が「横断・逆行」と2つを一括りにしている点も、この2つを区別すべきという判断を妨げている。

### P4-02（S3）`_shortestHeadingDelta` の第2分岐が到達不能

- `channel_path_predictor.dart:224-229`。
- Dart の `%` は除数が正なら結果が非負なので、`(to - from) % 360` は `0 ≤ delta < 360`。
- したがって `if (delta > 180) delta -= 360;` の後は `-180 ≤ delta ≤ 180` が確定し、**`if (delta < -180)` は決して成立しない**。
- 実害なし。ただし「Dart の `%` が非負を返す」ことに気付かずに書かれた可能性があり、同じ誤解が他所にあると符号バグになる。

### P4-03（S3）折れ線の区間速度が弦長ベースで、艇速よりわずかに小さい

- `_segmentsFromPoints:181` — `segmentSpeed = segmentLength / duration`。`segmentLength` は弦の長さ（`distanceMeters(from, to)`）。
- 曲線を弦で近似すると弦 < 弧なので、予測される移動距離が実際よりわずかに短くなる。
- 大きさ: 1区間あたりの旋回角 θ に対し `sin(θ/2)/(θ/2)`。θ = 20° で 0.5%、θ = 40° で 2%。予測地平 10 秒・5 m/s（50m）で最大 1m 程度。
- 方向としては**検知がわずかに遅れる側**（警告漏れ方向）。`maxChannelCurvatureMarginMeters`（3m）の横マージンとは別軸なので、これで吸収されているとは言い切れない。
- 実害は小さいが、警告漏れ方向の系統誤差なので記録する。

### P4-04（S3）`_toLocal` / `_toLatLng` が呼び出しごとに `cos(origin.latitude)` を再計算する

- `channel_centerline.dart:286` / `:299`。`origin` は不変（`final`）なのに、変換のたびに `cos` を計算している。
- `fromShorelines` は `steps` 回のループで `pointAt`（→`_toLatLng`）と `project`（→`_toLocal`）を呼ぶため、生成時に数百回。航行中も `project` が毎秒呼ばれる。
- `fromPolyline` は同じ値を `originCosLatitude` としてローカル変数で持っている（`:69`）のに、インスタンスには保存していない。**フィールドとして持てば済む。**
