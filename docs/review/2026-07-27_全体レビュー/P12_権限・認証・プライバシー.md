> 航行は利用者がフォアグラウンドで明示的に開始する。Androidは location foreground service、
> iOSはBackground Location modeにより、whileInUse権限のまま画面消灯・別アプリ表示中の更新を継続する。
> 停止中の自動起動は行わないため、**「常に許可」は必須にしない**。

## 3. データ削除

`account_data_deletion_service.dart:15-18`:

> Firebase匿名アカウントと、端末内の関連データを削除する。
> 個人の位置と危険区域更新を残したまま Auth だけを削除しないよう、
> **リモート整理 → Auth削除 → 端末内削除**の順で実行する。

**順序に理由がある。** Auth を先に消すと、残ったデータを消す権限を失う。
`database.rules.json` に `ownerUid` を `'deleted-account'` へ置換する専用の書き込みルールがあり、
削除フローがルール側でも支えられている ✓

## 4. セキュリティルール

詳細は [P09](P09_通信.md) 第3.2章に記載。要点のみ:

- ルート `.read` / `.write` = false、必要な枝だけ開く
- チーム参加は team_meta / team_invites / team_users / team_members の**相互参照**で検証。
  招待コードを知っているだけでは参加できない
- 位置は `auth.uid === $boatId` で自分の枝のみ書き込み可
- 全フィールドに型・範囲バリデーション、`$other: {".validate": false}` で未知フィールドを拒否
- Firestore 側も `allow list: if false`、`request.query.limit <= 100` でスキャンを制限
- `test/firebase_rules_contract_test.dart` がパス構造とプロファイルハッシュをピン留め

**この規模の個人開発アプリとしては例外的に堅い。**
