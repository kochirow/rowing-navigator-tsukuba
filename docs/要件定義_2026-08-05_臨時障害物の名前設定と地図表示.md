# 要件定義・実装計画: 臨時障害物の名前設定と地図表示

- 作成日: 2026-08-05
- 状態: **要件定義・計画のみ。実装は未着手**
- 対象: 臨時危険区域（Firestore の `temporary_obstacles`）
- 上位規範: [docs/DESIGN_PRINCIPLES.md](DESIGN_PRINCIPLES.md)

## 0. 結論

臨時危険区域には、チーム内で共有・編集できる表示名を持たせる。名前は、警告の
画面表示と地図上の短いラベルに使う。ただし、名前は障害物の種類や危険度を変更する
ものではない。

推奨する初期仕様は次のとおり。

1. 追加時・編集時に名前を入力できる。未入力時は既存互換の「臨時危険区域」を保存する。
2. 警告バナーは、名前が設定されていれば「工事船」「係留ロープ」のように名前を表示し、
   警告タイトルも「工事船に接近」とする。
3. 警告音は既存の汎用危険区域音を使い続ける。現在のアプリは実行時読み上げではなく
   事前生成音声なので、任意名を音声へ混ぜない。
4. 地図ラベルは名前付きの臨時危険区域だけに出す。待機・編集時は拡大時、航行中は
   自艇から近い区域を優先し、画面をラベルで埋めない。
5. 名前表示は表示専用であり、衝突判定・警告距離・警告レベル・音声選択には影響させない。

## 1. 背景と現状確認

### 1.1 既存コードで確認できたこと

| 現状 | 根拠 |
| --- | --- |
| `StaticObstacle` に nullable な `name` が既にある | `lib/models/static_obstacle_model.dart` |
| Firestore の臨時区域は `name` を必須・1〜40文字として検証している | `firestore.rules` の `validTemporaryShape` |
| 新規円形区域は `name: '臨時危険区域'` を固定保存している | `StaticObstacleService.addTemporaryCircle` |
| 既存円形区域の更新APIは中心・半径・頂点だけを更新する | `StaticObstacleService.updateTemporaryCircle` |
| 警告評価の内部には `obstacleName` がある | `ThreatInfo` と `NavigationWarningService` |
| しかし `AlertCandidate` 経由では名前が警告表示まで一貫して運ばれていない | `SafetyOrchestrator._fromRiskThreat` → `NavigationWarningService.fromCandidate` |
| `SafetyBanner` はカテゴリ単位でまとめ、表示時に「岸」「橋」などへ戻す | `SafetyBanner._groupByCategory` / `_displayLabel` |
| 臨時危険区域のポリゴンは描画されるが、障害物名のMarker層はない | `HomeMapScreen` の障害物描画処理 |
| 艇Marker描画がMarker集合を更新するため、障害物ラベルは既存の艇ラベルと統合が必要 | `UseNavMap.renderBoatMarkers` |
| Rulesは名前の変更を更新許可リストに含めていない | `firestore.rules` の `affectedKeys().hasOnly(...)` |

### 1.2 この計画で変更しないもの

- `CollisionRiskEvaluatorService` の判定式、閾値、警告距離、警告レベル
- `SafetyOrchestrator` の警告優先順位・音声再生制御そのもの
- 障害物ポリゴンの座標、固定危険区域profile、version、SHA
- `kind` の意味、種類別の色、種類別の標準警告音
- 臨時危険区域の自動失効を復活させること
- 既存レコードの一括移行・削除
- 警告音アセットの追加、動的TTSの導入

名前が欠けていても、ポリゴン表示・既存の汎用警告・危険区域データ受信は継続する。
名前表示の失敗を安全機能停止の理由にしない。

## 2. 機能要件

### F1. 名前の入力・編集

- 臨時危険区域の追加フローに「名前」入力欄を追加する。
- 既存の臨時危険区域を選択した編集カードにも「名前」入力欄を追加する。
- 追加時は、地図をタップしただけでは直ちにFirestoreへ保存せず、中心・半径・名前を
  確認できる下部カードを表示してから保存する。
- キャンセル時はFirestoreへ書き込まない。
- 保存中は名前・半径・中心の操作を無効にし、二重保存を防ぐ。
- 名前の変更は同じチームの全メンバーへ共有される。
- 編集者、作成者、更新日時の既存契約は変更しない。

### F2. 入力値

- 前後の空白を除去する。
- 空文字はエラーにせず、`臨時危険区域` を保存する。既存アプリと同じ意味で扱うためである。
- 改行・制御文字は許可しない。
- アプリの入力上限は、既存の艇名と揃えて20文字を目安とする。
- Firestore Rulesの保存上限40文字は、既存データ互換のため維持する。新アプリの入力は
  20文字以内に制限する。
- 20文字を超える既存データを受信しても、ポリゴンと警告を止めない。地図ラベルと警告
  チップでは表示幅に合わせて省略し、詳細・アクセシビリティには元の名前を残す。
- 名前に「橋」「岸」と入力しても、`kind` は `generic` のままにする。表示名と危険区域
  の意味を混同しないためである。

入力欄の例示は「工事船」「係留ロープ」「流木」「ブイ」などとし、ヘルプには
「短い名前にすると地図上で見やすくなります」と表示する。

### F3. 警告表示

名前が既定値以外に設定されている臨時危険区域は、警告で次のように表示する。

| 状態 | バナーの主表示 | 警告タイトル | 音声 |
| --- | --- | --- | --- |
| 名前なし・既定値 | 危険区域 | 危険区域に接近 | 既存の汎用音 |
| `工事船` | 工事船 | 工事船に接近 | 既存の汎用音 |
| `係留ロープ` | 係留ロープ | 係留ロープに接近 | 既存の汎用音 |

- 既存のカテゴリ色は `generic` の色を維持する。
- 名前変更で警告の安定IDを変えない。表示名の変更で警告が新規イベントとして再発火
  したり、音声が再武装されたりしてはならない。
- 異なる名前の臨時区域は、バナー上で別の対象として表示できるようにする。
- 同じ名前の区域をまとめる場合は、既存の `×件数` 表示を使う。
- 画面幅が足りないときは1行省略表示する。警告の出現・色・脈動・音の段階は変えない。
- 警告対象が名前付きでも、標準音声は「危険区域」相当のままとする。画面表示と音声の
  対応が食い違うことを説明できるよう、利用ガイドまたは入力ヘルプに記載する。

実装上は、名前を `ThreatInfo` → `AlertCandidate` → `NavigationWarning` へ明示的に
運ぶ。`category` は色・音・分類のために残し、表示名の代用にはしない。

### F4. 地図ラベル

- ラベル対象は、名前が設定された臨時危険区域だけとする。既定名の区域は、通常は
  ラベルを出さない。
- ラベルはMarkerとして描画し、ポリゴンそのものの塗り・輪郭と区別する。
- 円形区域は `circleCenter` を基準位置とし、ラベルの下端が中心付近に来るようにして、
  ポリゴンの頭上または内部に表示する。
- 将来、円形以外の臨時ポリゴンを受ける場合は、ポリゴン内の代表点を使う。単純な頂点の
  平均で陸上・区域外へラベルを置かない。
- ラベルは1行のコンパクトなピル型とし、最大幅・省略記号を設ける。ポリゴン面積より
  ラベルが大きく見える場合は、ラベルを縮めるか表示対象から外す。
- ラベルの色は名前を読める濃色背景＋白文字とし、危険区域の赤い塗りを隠し過ぎない。
- ラベルをタップしたときは、可能なら対応する臨時区域を選択して編集カードを開く。
  ラベル描画失敗やタップ非対応でも、ポリゴンのタップと警告は残す。

#### 表示条件

| モード | 表示条件 | 上限・優先順位 |
| --- | --- | --- |
| 待機・危険区域編集 | ズーム19.0以上。選択中は倍率に関係なく表示 | 選択中を最優先、次に画面内の近い区域。最大6件 |
| 航行中 | 自艇からポリゴンまで120m以内。選択中の編集表示は別画面で行う | 近い順に最大3件。自艇が使えないときは距離条件で新規表示しない |
| 監視中 | ズーム19.0以上 | カメラ内の近い区域を最大6件 |

航行中の120mは警告発報距離ではない。ラベルを見つけて目視へ移るための表示距離であり、
危険判定の値や警告音には渡さない。自艇からの距離は区域中心ではなく、ポリゴンまでの
最短距離を使う。

- ラベルの重なりが検出できない場合でも、上限件数と名前の短縮で画面占有を抑える。
- Google Mapsのカメラ移動・ズーム変更時はラベル条件だけを更新し、ポリゴンや艇Markerを
  不要に再生成しない。
- 艇Marker、危険区域ポリゴン、障害物ラベルを統合して管理し、ラベル更新で艇Markerが
  消えないようにする。
- 地図ラベルは表示専用で、ラベルが一時的に表示されなくても危険区域を非表示扱いに
  しない。航行中のポリゴン表示と安全判定は従来どおり継続する。

## 3. データ契約と互換性

### 3.1 Firestore

既存の `temporary_obstacles/{obstacleId}` の `name` フィールドをそのまま使用する。
新しいフィールド名やprotocol versionは追加しない。

追加・更新payloadのイメージ:

```text
name: "工事船"
shape: "circle"
kind: "generic"
center: GeoPoint(...)
radiusMeters: 5
points: [24個のGeoPoint]
既存の作成者・日時・更新者フィールド
```

必要なRules変更:

- `validTemporaryShape` の名前型・長さ検証は維持する。
- `affectedKeys().hasOnly(...)` に `name` を追加する。
- 同じチームのメンバーが名前だけ、または名前と中心・半径を同時に更新できるようにする。
- `createdBy`、`createdAt`、`source`、`expiresAt` の既存保護は維持する。
- 旧形式の `expiresAt` を持つレコードを削除・失効させない。
- 名前更新のためにRulesを緩め過ぎない。shape、kind、points、radiusの検証は残す。

### 3.2 アプリ側の互換動作

- `name` が欠落・空・不正な受信データは、名前だけを既定表示へフォールバックする。
- そのデータを編集保存するときは、正規化した既定名を含めて保存し、次回から契約を
  満たすようにする。
- 名前以外の臨時区域データが正常なら、名前の不備で区域全体を受信拒否しない。
- 旧アプリが中心・半径だけを更新しても、Firestore上の名前を消さない。
- 固定障害物・実データprofile・アカウント削除処理への追加移行は行わない。

## 5. テスト計画

### 5.1 純粋ロジック

- 名前のtrim、空文字、制御文字、上限、既定値フォールバック
- 既定名は地図ラベルを出さない、任意名は出す
- ズーム閾値の前後
- 航行中の120m境界、ポリゴン内、GPS不在
- 最大件数、近い順、選択中の優先
- ラベル表示の結果が警告判定値を変更しない

### 5.2 警告

- `工事船` がタイトル・バナーに出る
- `工事船` と `係留ロープ` が別チップになる
- 同名区域が件数表示へまとまる
- 名前変更でalert ID・警告音・緊急度が変わらない
- 名前付きでもgenericの色と音声が維持される
- 既存の「岸」「橋」「橋脚」「流木」表示が変わらない

### 5.3 UI・同期

- 追加タップだけでは書き込まれない
- 名前を入力して保存できる
- 取消で書き込まれない
- 既存区域の名前だけを変更できる
- 保存失敗時に未保存状態を表示できる
- 同チームの別端末で名前が反映される
- 旧アプリの中心・半径更新で名前が消えない

### 5.4 Rules Emulator

- 名前付きcreateが成功する
- 同チームmemberのname updateが成功する
- 空、41文字、非文字列、余計なフィールドが拒否される
- 別チーム・未所属のread/writeが拒否される
- `expiresAt` 付き旧レコードを編集・削除できる
- `createdBy`、`createdAt`、`source`を改ざんできない

## 6. 検証コマンドと外部ゲート

### コード・ローカルRulesの検証

日本語パスのため、ローカル解析は `flutter analyze` ではなく次を使う。


### 本番Rulesの手動作業

Rules Emulatorが通っても、本番Rulesが変更された証拠にはならない。実装後、デプロイを
行う場合は対象Firebaseプロジェクトを確認してから、リポジトリ直下で次を実行する。

```bash
firebase deploy --only firestore:rules
```

実行後に、Firebase CLIの成功出力とFirebase ConsoleのFirestore Rulesの公開時刻を確認する。
このデプロイは外部サービスの状態を変更するため、この計画段階では実行しない。

### 実機・水上の確認

本番Rulesの公開後に、少なくとも同一チームの2端末で次を確認する。

1. 端末Aが「工事船」を登録する。
2. 端末Bの共有地図へ名前とポリゴンが反映される。
3. 端末Bが「係留ロープ」へ変更し、端末Aの警告表示・地図ラベルが更新される。
4. 低倍率、拡大、航行中の接近、警告発生中でラベルの出方を確認する。
5. 名前付き警告でも、音声は既存の汎用音であり、音声経路が途切れないことを確認する。
6. ラベルが多い場所、通信一時断、GPS劣化、航空写真で、ポリゴンと警告が残ることを確認する。

コード解析・テスト、Rules Emulator、本番Rules、署名済みArchive、実機、水上確認は
それぞれ独立したゲートとして記録する。前のゲートを通しても後のゲートの完了とはみなさない。

## 7. リリース順序と切り戻し

1. P1〜P5のコードと単体/UIテストを作る。
2. Rules Emulatorと全体テストを通す。
3. 本番Firestore Rulesを承認後に公開する。名前更新機能を含むアプリより先に公開する。
4. 同一チーム2端末で共有更新を確認する。
5. 署名済みビルド・TestFlight等の配布ゲートを別途通す。
6. 実機・水上でラベル表示と警告表示を確認する。

切り戻し時は、名前表示だけを既定表示へ落とせるようにし、臨時危険区域のポリゴン・
警告判定・音声を停止しない。Firestoreの名前フィールドは既存互換のため削除しない。

## 8. 未決定ではなく、実装前に固定しておく判断

- 初期表示距離は120m、ラベル上限は航行中3件・その他6件とする。実機で多過ぎる場合は
  表示専用設定だけを調整し、警告距離は変更しない。
- 初期名は「臨時危険区域」とし、名前未設定区域は地図ラベルを出さない。
- 任意名は画面表示に使うが、現在の音声アセットには使わない。
- 名前は安全判定の入力ではなく、表示・共有・編集の属性として扱う。
