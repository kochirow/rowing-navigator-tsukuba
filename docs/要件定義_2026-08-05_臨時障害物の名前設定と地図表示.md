# 要件定義・実装計画: 臨時障害物の名前設定と地図表示

- 作成日: 2026-08-05
- 状態: **要件定義・計画のみ。実装は未着手**
- 対象: 臨時危険区域（Firestore の `temporary_obstacles`）
- 上位規範: [docs/DESIGN_PRINCIPLES.md](DESIGN_PRINCIPLES.md)

## 0. 結論

臨時危険区域には、チーム内で共有・編集できる表示名を持たせる。名前は、警告の
画面表示と地図上の短いラベルに使う。ただし、名前は障害物の種類や危険度を変更する
ものではない。

推奨する初期仕様は次のとおり。

1. 追加時・編集時に名前を入力できる。未入力時は既存互換の「臨時危険区域」を保存する。
2. 警告バナーは、名前が設定されていれば「工事船」「係留ロープ」のように名前を表示し、
   警告タイトルも同じ単語だけとする。「〜に接近」は表示しない。
3. 警告音は既存の汎用危険区域音を使い続ける。現在のアプリは実行時読み上げではなく
   事前生成音声なので、任意名を音声へ混ぜない。
4. ホーム画面では、追加済みの臨時危険区域ポリゴンを名前の有無に関係なく表示する。地図ラベルは
   名前付きの臨時危険区域だけに出し、ホーム・危険区域編集・監視時は拡大時、航行中は自艇から
   近い区域を優先して、画面をラベルで埋めない。
5. 名前表示は表示専用であり、衝突判定・警告距離・警告レベル・音声選択には影響させない。

### この機能の不変条件

実装・レビュー・切り戻しでは、次を満たしていることを確認する。

1. **名前は識別子ではない。** Firestore文書ID、`StaticObstacle.id`、警告の
   `alertId`、音声の`audioEventId`は、名前の追加・変更・欠落で変わらない。
2. **名前の受信・描画に失敗しても安全経路を止めない。** ポリゴン、衝突判定、既存の
   汎用音、画面警告、位置共有は従来どおり継続する。失敗時に省略するのは名前ラベルだけである。
3. **未保存の下書きは共有しない。** 地図タップで作るプレビューは端末内だけに置き、
   明示的な保存成功後にだけFirestoreへ書き込む。
4. **表示名はチーム共有データであり、個人情報を入力しない。** 船名・物体名・場所の
   短い説明だけを入力する。電話番号や人名など、共有不要な情報を名前に使わない。

この機能は、実在する対象を目視で素早く特定するための補助である。衝突回避を保証せず、
名前やラベルを見なければ安全に航行できない設計にはしない。

## 1. 背景と現状確認

### 1.1 既存コードで確認できたこと

| 現状 | 根拠 |
| --- | --- |
| `StaticObstacle` に nullable な `name` が既にある | `lib/models/static_obstacle_model.dart` |
| Firestore の臨時区域は `name` を必須・1〜40文字として検証している | `firestore.rules` の `validTemporaryShape` |
| 新規円形区域は `name: '臨時危険区域'` を固定保存している | `StaticObstacleService.addTemporaryCircle` |
| 既存円形区域の更新APIは中心・半径・頂点だけを更新する | `StaticObstacleService.updateTemporaryCircle` |
| 警告評価の内部には `obstacleName` がある | `ThreatInfo` と `NavigationWarningService` |
| しかし `AlertCandidate` 経由では名前が警告表示まで一貫して運ばれていない | `SafetyOrchestrator._fromRiskThreat` → `NavigationWarningService.fromCandidate` |
| `SafetyBanner` はカテゴリ単位でまとめ、表示時に「岸」「橋」などへ戻す | `SafetyBanner._groupByCategory` / `_displayLabel` |
| 臨時危険区域のポリゴンは描画されるが、障害物名のMarker層はない | `HomeMapScreen` の障害物描画処理 |
| 艇Marker描画がMarker集合全体を更新するため、障害物ラベルを直接追加すると次の艇描画で消える | `UseNavMap.renderBoatMarkers` |
| Rulesは名前の変更を更新許可リストに含めていない | `firestore.rules` の `affectedKeys().hasOnly(...)` |
| 受信側は `name as String?` を直接キャストするため、文字列でない旧・不正データはその1件全体を読み飛ばす | `StaticObstacleService._parseTemporaryObstacles` |

### 1.2 この計画で変更しないもの

- `CollisionRiskEvaluatorService` の判定式、閾値、警告距離、警告レベル
- `SafetyOrchestrator` の警告優先順位・音声再生制御そのもの
- 障害物ポリゴンの座標、固定危険区域profile、version、SHA
- `kind` の意味、種類別の色、種類別の標準警告音
- 臨時危険区域の自動失効を復活させること
- 既存レコードの一括移行・削除
- 警告音アセットの追加、動的TTSの導入

名前が欠けていても、ポリゴン表示・既存の汎用警告・危険区域データ受信は継続する。
名前表示の失敗を安全機能停止の理由にしない。

## 2. 機能要件

### F1. 名前の入力・編集

- 臨時危険区域の追加フローに「名前」入力欄を追加する。
- 既存の臨時危険区域を選択した編集カードにも「名前」入力欄を追加する。
- 追加時は、地図をタップしただけでは直ちにFirestoreへ保存せず、端末内の
  `TemporaryObstacleDraft`（仮称）として中心・半径・名前を持つプレビューを表示する。
  下部カードの「保存」で初めてFirestoreへ書き込む。
- 追加下書きの初期値は、中心=タップ位置、半径=5m、名前=空欄とする。空欄のまま保存した
  ときだけ、保存値を既定名の`臨時危険区域`に正規化する。
- 「取消」は下書き・プレビュー・追加モードを破棄し、Firestoreへ書き込まない。保存失敗後も
  下書きは残して再試行または取消を選べるようにし、成功したようには見せない。
- 保存中は名前・半径・中心移動・保存・削除を無効にし、二重保存を防ぐ。失敗時だけ再び編集可能にする。
- 名前の変更は同じチームの全メンバーへ共有される。
- 既存区域の編集開始時は、受信した正規化済み表示名を下書きへコピーする。名前だけ、中心だけ、
  半径だけの変更も保存できる。
- 編集者、作成者、更新日時の既存契約は変更しない。保存成功時だけ`updatedAt`、`updatedBy`、
  `confirmedAt`を更新し、`createdBy`、`createdAt`、`source`、旧形式の`expiresAt`は保持する。
- 同じ区域を別端末が更新している間に保存しようとした場合は、静かに上書きしない。保存前の
  `updatedAt`を基準にトランザクションまたは同等の楽観ロックを行い、競合時は「他の端末で更新
  されました。最新内容を確認してください」と表示して、受信済みの最新値を表示する。

### F2. 入力値

- 追加・編集・表示の境界で同じ純粋Dartの正規化関数を使う。UIだけで検証して保存APIで
  受け入れる、という二重基準にしない。
- 正規化は前後のUnicode空白を除去する。改行、Unicodeの行・段落区切り、C0/C1制御文字、
  双方向制御文字は拒否する。見えない文字によるラベルのなりすまし・複数行化を防ぐためである。
- 空文字はエラーにせず、`臨時危険区域`を保存する。既定名と完全一致する名前は「任意名なし」と
  同じ扱いにし、地図ラベルを出さない。
- アプリの入力上限は、既存の艇名と揃えて**20書記素クラスタ**とする。絵文字・結合文字を
  `substring`で分断しないよう`characters`を使って数え、UI上の省略も同じ単位で行う。さらに
  Firestore Rulesの`size() <= 40`を満たすかを保存前に同じ正規化関数で確認する。20書記素でも
  結合文字列がRulesの数え方で40を超える場合、保存ボタンを有効にしてから失敗させない。
- Firestore Rulesの保存上限40文字は、既存データ互換のため維持する。新アプリの入力は
  20文字以内に制限する。
- 20文字を超えるがRules上は有効な既存データを受信しても、ポリゴンと警告を止めない。
  地図ラベルと警告チップでは表示幅に合わせて省略し、詳細・アクセシビリティには元の名前を残す。
- `name`が欠落・空・非文字列・正規化不能な受信データでは、その**名前だけ**を既定名として
  扱う。`StaticObstacleService`は安全な型判定をして、1件の名前不備で区域全体を読み飛ばしては
  ならない。受信・描画中にFirestoreへ自動修復書き込みもしない。
- 上記の不備を持つ既存区域を利用者が明示的に保存したときだけ、正規化後の既定名を含めて保存し、
  次回から正規の契約へ戻す。
- 名前に「橋」「岸」と入力しても、`kind` は `generic` のままにする。表示名と危険区域
  の意味を混同しないためである。

入力欄の例示は「工事船」「係留ロープ」「流木」「ブイ」などとし、ヘルプには
「短い名前にすると地図上で見やすくなります」と表示する。

### F3. 警告表示

名前が既定値以外に設定されている臨時危険区域は、警告で次のように表示する。

| 状態 | バナーの主表示・警告タイトル | 音声 |
| --- | --- | --- |
| 名前なし・既定値 | 危険区域 | 既存の汎用音 |
| `工事船` | 工事船 | 既存の汎用音 |
| `係留ロープ` | 係留ロープ | 既存の汎用音 |

画面の警告は「接近したから表示されている」ことを前提に、対象・状態だけを短く出す。
したがって、臨時区域に限らず物理的な警告の`NavigationWarning.title`、バナー主表示、
アクセシビリティの主ラベルには「〜に接近」を含めない。例は「岸」「橋」「中洲」「工事船」で
あり、時間・件数・system faultの補足は別の表示要素へ置く。上位方針は
`DESIGN_PRINCIPLES.md` の「原則5.1」に従う。

- 既存のカテゴリ色は `generic` の色を維持する。
- 名前変更で警告の安定IDを変えない。表示名の変更で警告が新規イベントとして再発火
  したり、音声が再武装されたりしてはならない。
- 異なる名前の臨時区域は、バナー上で別の対象として表示できるようにする。同じ名前の
  区域だけは既存の`×件数`表示でまとめる。
- バナーの集約キーは、単なる`category`ではなく、`category + 表示グループキー`とする。
  `generic`の既定名なしは`generic/default`、名前付きは`generic/name/<正規化名>`とする。
  これにより「工事船」と「係留ロープ」が同じ`generic`色でも互いを上書きしない。
- 表示グループキーはUI専用であり、`alertId`、`audioEventId`、状態機械の観測IDには使わない。
  名称変更中に警告が出ている場合は、同じ警告エピソードの文字だけを更新し、確認時間・
  解除猶予・音声再生の状態を作り直さない。
- 画面幅が足りないときは1行省略表示する。警告の出現・色・脈動・音の段階は変えない。
- 警告対象が名前付きでも、標準音声は「危険区域」相当のままとする。画面表示と音声の
  対応が食い違うことを説明できるよう、利用ガイドまたは入力ヘルプに記載する。

実装上は、名前を `ThreatInfo` → `AlertCandidate.displayLabel`（仮称）→
`NavigationWarning.displayLabel`（仮称）へ明示的に運ぶ。`category` は色・音・分類のために
残し、表示名の代用にはしない。旧経路の`NavigationWarningService.fromAssessment`も同じ表示名
規則を使い、候補経路と直接変換経路で文言が食い違わないようにする。

### F4. 地図ラベル

- ラベル対象は、正規化後に既定名以外となる臨時危険区域だけとする。既定名・欠落名・
  不正名の区域は、通常は
  ラベルを出さない。
- ラベルはMarkerとして描画し、ポリゴンそのものの塗り・輪郭と区別する。
- 円形区域は`circleCenter`を基準位置とする。旧データなどで中心が無い場合は、ポリゴンの
  内部点をフォールバックにする。ラベルの下端が代表点に来るようにし、領域を隠しすぎない。
- 将来、円形以外の臨時ポリゴンを受ける場合も、必ずポリゴン内の代表点を使う。単純な
  頂点平均は凹形状で区域外・陸上へ出るため使わない。内部点が算出できない場合はラベルを
  省略し、ポリゴンを残す。
- ラベルは1行のコンパクトなピル型とし、最大幅・省略記号を設ける。ポリゴン面積より
  ラベルが大きく見える場合は、ラベルを縮めるか表示対象から外す。
- 初期の視覚契約は、高さ28 logical px、本文14sp相当、左右余白8px、最大幅132 logical px
  とする。本文は1行・末尾省略、`Semantics`とMarkerの`InfoWindow`には省略前の名前を渡す。
  実機の日光下で読めない場合は色・太さ・コントラストを調整し、警告距離や表示対象距離を
  読みやすさの代償として変えない。
- ラベルの色は名前を読める濃色背景＋白文字とし、危険区域の赤い塗りを隠し過ぎない。
- ラベルをタップしたときは、可能なら対応する臨時区域を選択して編集カードを開く。
  ラベル描画失敗やタップ非対応でも、ポリゴンのタップと警告は残す。

#### 表示条件

| モード | 表示条件 | 上限・優先順位 |
| --- | --- | --- |
| ホーム・危険区域編集 | ズーム19.0以上。選択中と追加下書きは倍率に関係なく表示 | 選択中を最優先、次に画面内の近い区域。最大6件 |
| 航行中 | 自艇からポリゴンまで120m以内。選択中の編集表示は別画面で行う | 近い順に最大3件。自艇が使えないときは距離条件で新規表示しない |
| 監視中 | ズーム19.0以上 | カメラ内の近い区域を最大6件 |

航行中の120mは警告発報距離ではない。ラベルを見つけて目視へ移るための表示距離であり、
危険判定の値や警告音には渡さない。自艇からの距離は区域中心ではなく、ポリゴンまでの
最短距離を使う。

- **通常のホーム画面の臨時危険区域ポリゴンは、この変更の必須対象である。** `HomePhase.ashore`
  の待機中でも、Firestoreから取得できた臨時区域を固定区域と同じGoogleMapへ重ねて描く。名前が
  既定値でも、ラベルがなくても、ポリゴンは表示する。
- ホーム画面の初回表示時、チーム・匿名Authの準備が終わった後に臨時区域を1回取得する。取得結果は
  `defaultObstacles + temporaryObstacles`として原子的に差し替え、初回の固定区域読込みが完了した
  だけで臨時区域を捨てない。
- 「危険区域を追加」画面からホームへ戻ったときは、保存成功・取消・削除のいずれでもホーム画面の
  表示用一覧を再評価する。保存したポリゴンがアプリ再起動なしで見えることを必須とする。
- アプリ復帰、チーム切替、通信復旧時にも通常ホームの臨時区域を再取得できるようにする。ただし
  取得失敗時に、直前まで表示できていた臨時区域を固定区域だけの一覧へ置き換えて消してはならない。
  直前の区域を残し、受信不能状態だけを表示する。
- ホーム画面の**ポリゴン表示条件と名前ラベル表示条件を分離**する。ズームや自艇との距離で
  ラベルを隠しても、取得済みの臨時区域ポリゴンは隠さない。
- ホーム画面の名前ラベルは、名前付き区域だけをズーム19.0以上・最大6件で表示する。既定名の
  区域はポリゴンだけを表示する。
- ラベルの重なりが検出できない場合でも、上限件数と名前の短縮で画面占有を抑える。選択中は
  表示上限を数えず必ず残すが、選択以外を減らして合計7件を超えないようにする。
- Google Mapsのカメラ移動・ズーム変更時は、`onCameraIdle`で増える表示専用のカメラ世代を
  入力として、ラベル条件だけを再評価する。ポリゴン・艇Markerを不要に再生成しない。
- `UseNavMap`は少なくとも艇、障害物ラベル、編集用の3つのMarkerレイヤーを所有し、最後に
  和集合だけをGoogleMapへ渡す。`renderBoatMarkers`が全Marker集合を置換する現在の方式へ
  ラベルを直接混ぜない。Marker IDは`boat/`、`temporary-label/`、`editor/`のように用途別の
  接頭辞を付け、ID衝突を防ぐ。
- ラベル用Bitmapのキャッシュは文字列・配色・DPRをキーにし、上限を設ける。任意名の変更で
  無制限にキャッシュが増えないよう、画面に必要な分と小さなLRU（例: 64件）だけを保持する。
- 非同期Bitmap生成にはラベル専用の最新要求ゲートを使う。画面破棄・カメラ移動・次の要求後に
  古い生成結果を反映しない。艇Markerの描画ゲートと共有しない。
- 地図ラベルは表示専用で、ラベルが一時的に表示されなくても危険区域を非表示扱いに
  しない。航行中のポリゴン表示と安全判定は従来どおり継続する。

### F5. ホーム画面の臨時危険区域ポリゴン（今回追加）

- アプリ起動後の通常ホーム画面（`HomePhase.ashore`）で、固定危険区域と臨時危険区域を同じ
  地図レイヤーへ重ねて表示する。臨時区域が名前未設定・既定名でも、ポリゴン表示は省略しない。
- 初回の固定危険区域読込みと臨時区域読込みの順番を固定し、固定区域だけが先に描かれたまま
  臨時区域が追加されない状態を完了とみなさない。
- `refreshTemporaryObstaclesForMap()` の取得が成功したとき、`navigator.obstacles`へ一式を反映し、
  `HomeMapScreen`の障害物ポリゴン描画が再実行されることを確認する。
- 「危険区域を追加」画面から戻った直後は、保存成功なら新しいポリゴン、削除成功なら削除済みの
  一覧がホーム画面へ反映される。再起動・再ログインを要求しない。
- 追加画面でキャンセルした下書き、保存失敗した下書き、未認証・未所属の区域は、共有一覧へ
  混ぜてホーム画面に表示しない。
- 通信失敗・一時的なFirestore受信停止時は、直前の臨時区域ポリゴンを消さずに保持する。新しい
  値が取得できたときだけ、一式を原子的に差し替える。
- 監視・航行へ移行したときも、同じ臨時区域集合を安全評価・ホーム地図表示の両方へ渡す。
  モード切替のために臨時区域だけをクリアしない。
- ホーム画面のポリゴンは名前ラベルの表示条件、ズーム、GPSの有無に依存しない。ラベルだけが
  一時的に生成できなくても、赤い臨時危険区域ポリゴンは残す。

この要件は「名前付きラベルが見えること」と別の必須要件である。ラベルが読める倍率まで拡大
していなくても、登録済みの危険区域が地図上に存在することを確認できなければならない。

## 3. データ契約と互換性

### 3.1 Firestore

既存の `temporary_obstacles/{obstacleId}` の `name` フィールドをそのまま使用する。
新しいフィールド名やprotocol versionは追加しない。

追加・更新payloadのイメージ:

```text
name: "工事船"
shape: "circle"
kind: "generic"
center: GeoPoint(...)
radiusMeters: 5
points: [24個のGeoPoint]
既存の作成者・日時・更新者フィールド
```

必要なRules変更:

- `validTemporaryShape` の名前型・長さ検証は維持する。
- `affectedKeys().hasOnly(...)` に `name` を追加する。
- 同じチームのメンバーが名前だけ、または名前と中心・半径を同時に更新できるようにする。
  `name`の追加以外に更新可能キーを増やさない。
- `createdBy`、`createdAt`、`source`、`expiresAt` の既存保護は維持する。
- 旧形式の `expiresAt` を持つレコードを削除・失効させない。
- 名前更新のためにRulesを緩め過ぎない。shape、kind、points、radiusの検証は残す。
- Rulesは20文字というUI上の上限を信頼せず、従来どおり空文字・非文字列・40文字超を拒否する。
  改行等の細かな正規化はクライアントの責務だが、Rulesの最大長・型検証は防御線として残す。

### 3.2 アプリ側の互換動作

- `name` が欠落・空・不正な受信データは、名前だけを既定表示へフォールバックする。
- そのデータを利用者が編集保存するときだけ、正規化した既定名を含めて保存し、次回から
  契約を満たすようにする。受信処理・地図描画・警告処理はデータを自動修復しない。
- 名前以外の臨時区域データが正常なら、名前の不備で区域全体を受信拒否しない。
- 旧アプリが中心・半径だけを更新しても、Firestore上の名前を消さない。
- 新アプリは、名前だけの変更でも`shape`、`kind`、`points`を勝手に作り直さない。保存時は
  下書きで実際に変更した属性だけを更新する。ただし中心または半径が変わった場合は、既存契約
  どおり`center`、`radiusMeters`、対応する24点の`points`を同じ原子的更新でそろえる。
- 更新は`updatedAt`を比較するトランザクションで行う。競合したら最新値を再取得し、利用者が
  改めて編集する。名前と座標を別端末の操作で黙って失わせない。
- この機能では既存の同期上限（最大100件）を変えない。上限を超えると全臨時区域を受信・
  表示できない既存制約が残るため、練習前後に不要な臨時区域をチームで削除する運用を維持する。
  名前ラベルの追加を理由に自動失効や自動削除を復活させない。
- 固定障害物・実データprofile・アカウント削除処理への追加移行は行わない。

- 初期名は「臨時危険区域」とし、名前未設定区域は地図ラベルを出さない。
- 任意名は画面表示に使うが、現在の音声アセットには使わない。
- 名前は安全判定の入力ではなく、表示・共有・編集の属性として扱う。
