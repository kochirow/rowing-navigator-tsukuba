# 無料枠・可用性検証

最終更新: 2026-07-21  
想定: 12台、週6日、1回2時間、月27回（平均26.07回を切上げ）  
対象: Firebase Spark / Google Maps SDK / 端末内航行機能

## 結論

- **課金防止:** Firebase projectをSparkのままにすればFirebase利用料は発生しない。ただし上限超過時は対象productが停止するため、課金0と可用性は別問題である。
- **設計上の使用量:** 全12台が全時間最短2秒送信でも、位置payload本体は約3.50GB/月。自動テストは4GB/月以下を強制し、10GB枠の60%以上をprotocol・再接続・その他通信の余白にする。
- **運用上の使用量:** Firebase Console実測を1練習200MB以下、月換算6GB以下とする。この条件を満たさないbuildは公開しない。
- **障害時:** Firebase/App Check/RTDB/Firestoreが停止しても、検証済み端末では同梱固定危険区域、GPS、端末内1秒警告、警告音、マップ画面、航行記録を継続する。チーム位置共有と臨時危険区域同期だけを利用不可表示にする。
- **未証明:** Google Mapsの背景地図tileはnetwork/APIに依存し、完全offline表示はSDKが保証しない。圏外でも背景地図を必須とする場合、桜川のoffline base mapを別途同梱するまで「完全に盤石」とは判定しない。

## 公式無料枠と停止条件

| Product | 無料枠・上限 | 今回の想定 |
|---|---:|---:|
| Realtime Database | download 10GB/月、storage 1GB、Spark同時接続100 | 12接続、位置payload約3.50GB/月 |
| Cloud Firestore | read 50,000/日、write 20,000/日、delete 20,000/日、storage 1GiB | 危険区域100件でも約1,248 reads/練習日 |
| Firebase Authentication | 新規作成100アカウント/時/IP、匿名アカウント上限は想定を大幅に上回る | 初回12台のみ。以後は保存UIDを復元 |
| App Check | Firebaseのno-cost product | default TTLを維持 |
| Google Maps SDK | Maps SDK SKUはfree usage cap Unlimited | billing有効化は必要。Firebaseとはprojectを分離 |

Sparkは上限を超えても自動課金しない代わりに、該当productが残り期間停止し得る。Firebase projectへCloud Billing accountをリンクするとBlazeへ移行し得るため、Maps用billing projectとFirebase Spark projectを分離する。

## RTDB最悪値の再計算

位置payload上限250B、12送信端末、12受信接続、2時間、月27回、最短2秒:

```text
250B × 12送信 × 12受信 × (7,200秒 ÷ 2秒) × 27回
= 3,499,200,000B
= 約3.50GB/月
```

1練習は約129.6MB。Console合格値200MB/練習なら月5.4GBで、10GBに約4.6GBの余白を残す。Firebaseはpayload以外にprotocol、WebSocket、TLS、再接続、拒否requestもdownloadへ算入するため、実測なしの「確実」は宣言しない。

次の回帰防止をコード化した。

- クラウド送信の最短値を2秒に固定。端末内判定は1秒を維持
- RTDB Rulesで前回から1900ms未満のwriteを拒否
- payloadが250B未満であることをテスト
- 12台fan-outの位置payloadを4GB/月以下にするテスト
- Firebase writeは同時1件、待機は最新1件だけ
- 期限切れ・大量Firestore同期を防ぐため臨時危険区域queryは新しい順100件
- Rulesでlimitなし、100件超のqueryを拒否

## 故障モードと継続動作

| 故障 | 自動対応 | 継続する機能 | 停止・低下する機能 |
|---|---|---|---|
| App Check初期化失敗 | 起動待ちは3秒まで。5/15/30/60/300秒で再試行 | 端末内機能 | 成功までFirebase共有不可 |
| RTDB write ACK停止 | 5秒で共有不可表示、1/2/5/10秒backoff、最新1件だけ保持 | GPS、固定区域警告、音声、記録 | 自艇位置共有 |
| RTDB受信stream error/done | 1/2/5/10秒で再購読 | 自艇・固定区域警告 | 復帰まで他艇共有警告 |
| Firestore quota/拒否 | 同一Auth UIDの検証済み所属cacheで起動、listener再購読 | 同梱固定区域、GPS、記録 | 臨時区域同期・編集 |
| GPS stream error/done | 1/2/5/10秒で再購読 | 画面、通信状態表示 | 復帰まで位置判定不可を警告 |
| GPS無通知15秒 | streamを破棄して再購読 | 画面、異常警告 | 復帰まで新しい位置判定 |
| 不正な他艇1件 | その艇だけ拒否 | 他艇全体、固定区域、自艇機能 | 不正艇のみ |
| アプリ強制終了/通信断 | onDisconnectでprofile/位置削除、受信側TTLも使用 | 他端末の運用 | 終了端末の共有 |
| Firebase quota超過 | ローカル所属cache、同梱区域へ縮退 | 端末内警告・音声・記録 | 月/日リセットまで共有 |
| Google Maps tile取得失敗 | 現在はGoogle Maps SDK cache任せ | GPS値と警告処理 | 背景地図は保証不可 |

## 公開前の手動故障注入試験

同じ署名済みrelease candidateで、結果・時刻・端末・OS・Firebase Usage差分を記録する。

1. 12台を2時間接続し、開始前後のRTDB download差分が200MB以下であることを確認する。
2. 航行中に機内モードを30秒、5分、15分で切り替え、端末内警告・音声・記録が止まらず、復帰後30秒以内にprofileと位置が揃うことを確認する。
3. 航行中に位置情報サービスをOFF→30秒→ONにし、GPS異常表示後に自動復旧することを確認する。
4. App Check Enforce後の正規TestFlight/Internal buildで有効requestを確認し、未登録buildだけが拒否されることを確認する。
5. Firestore/RTDB Rulesを一時的に拒否する検証projectで、アプリが落ちず端末内固定区域を表示することを確認する。
6. 100件の臨時危険区域で、最新100件だけを取得し、起動時間・メモリ・read数が異常増加しないことを確認する。
7. 画面点灯、画面消灯、別アプリ表示、低電池、OS kill、端末再起動を各30分以上実施する。
8. 練習水域で圏外にし、Google Maps背景tileが必要な範囲で残るか確認する。残らなければoffline base mapをP0追加する。

## 運用停止基準

- 1練習のRTDB downloadが200MBを超える
- 月予測が6GBを超える、またはConsole実績が7GBへ到達する
- Firestore read/writeが通常操作数と一致せず連続増加する
- 2時間中に自動復旧しないGPS/RTDB/Firestore停止が1回でもある
- Firebase障害時に固定危険区域警告、音声、航行記録のいずれかが止まる
- 圏外で背景地図が消え、現場が背景地図を必須と判断する
