# 共有危険区域・固定流木更新仕様

- 作成日: 2026-07-16
- 対象: `rowing-navigator-tsukuba` の「障害物の追加」画面と危険区域同期
- 位置づけ: [警告システム包括再設計](./2026-07-14_警告システム包括再設計.md) のカテゴリ別必須仕様
- 状態: 2026-07-29に臨時危険区域の自動失効を廃止（Firestore Rules適用・複数実機確認待ち）

## 0. 決定事項

1. 臨時危険区域は、ログイン中の全利用者が作成・編集・削除できる。
2. 臨時危険区域は、手動で削除するまで残る共有情報とする。
3. 固定流木は閉じた外周の内側全体を危険区域として塗りつぶす。外周線に沿った細い帯の集合として扱わない。
4. 固定流木は消滅しない永続障害物とし、24時間の失効期限を持たせない。
5. 固定流木は「障害物の追加」画面で位置、大きさ、向きを更新できる。ただし削除はできない。
6. 通常航行中の定期書込は行わず、利用者が編集を確定した時だけFirestoreへ書き込む。

## 1. 危険区域の分類

| 分類 | 例 | 保存先 | 失効 | 共有編集 |
|---|---|---|---|---|
| 固定プリセット | 岸、橋、中洲 | 同梱JSON | なし | アプリ内では編集不可 |
| 永続更新対象 | 固定流木 | 同梱基準形状 + Firestoreの変形値 | なし | ログイン中の全利用者が更新可、削除不可 |
| 臨時危険区域 | 工事、臨時係留物、一時的な障害物 | Firestore | なし（手動削除まで） | ログイン中の全利用者が作成・編集・削除可 |

固定流木を臨時危険区域へ複製してはならない。固定流木は常に同じ安定IDを持つ1個の永続障害物として更新する。

## 2. 臨時危険区域

### 2.1. 共同編集

- 認証済みであれば、作成者に関係なく編集・削除できる。
- 匿名認証も「ログイン中」に含む。
- 編集後も `createdAt` と `createdBy` は変更しない。
- `updatedAt` と `updatedBy` は保存のたびにサーバー側の現在値へ更新する。
- 自動失効は行わない。不要になった区域はチームメンバーが手動で削除する。

### 2.2. 形状と操作

- 新規作成は、地図を1回タップするとその地点を中心とする半径5mの円を生成する。
- 同じ画面で複数の円を連続して作成できる。
- 円を選択すると、半径調整スライダー、位置移動、保存、削除を表示する。
- 保存成功をサーバーから確認するまで、画面遷移で編集済みに見せない。失敗時は区域を消さず、未保存表示と再試行を出す。

## 3. 固定流木の危険形状

### 3.1. 塗りつぶし

同梱JSONにある固定流木の閉じた外周を、1個の `Polygon` として扱う。危険判定、地図描画、将来経路との交差判定はすべて外周の内側全体を対象にする。

外周から内側へ一定距離だけ伸ばす帯方式では、流木中央に未判定領域が残る可能性があるため採用しない。安全余裕を追加する場合は、塗りつぶしたポリゴン全体を外側へ拡張する独立パラメータとして扱う。

### 3.2. 編集できる値

「障害物の追加」画面で固定流木を選択した場合、次を編集できる。

- 中心位置: 地図上のドラッグ、または中心マーカー移動
- 長さ倍率: 基準形状の長手方向の倍率
- 幅倍率: 基準形状の短手方向の倍率
- 向き: 基準形状に対する回転角
- 外側安全余裕: 塗りつぶし形状の外側へ追加する距離

頂点を個別に動かす自由変形は初版へ含めない。小さなデータで安全に共有でき、誤操作の検証もしやすい平行移動・縦横拡大縮小・回転に限定する。

### 3.3. 削除しない

固定流木には削除ボタンを表示しない。現地状態を基準形状へ戻す必要がある場合は「基準位置・サイズに戻す」を使い、同梱値と同じ変形値をFirestoreへ保存する。

## 4. 低通信・低容量の保存設計

### 4.1. 保存単位

Firestoreには外周の全頂点を毎回保存せず、端末内の基準形状に適用する変形値だけを、固定流木1個につき1文書で保存する。

```text
managed_hazards/fixed_driftwood_01
  kind: fixed_driftwood
  baseShapeVersion: 1
  center: GeoPoint
  lengthScale: number
  widthScale: number
  rotationDegrees: number
  outwardMarginMeters: number
  revision: number
  updatedAt: server timestamp
  updatedBy: uid
  previousState: one-step rollback data
```

`previousState` は直前の変形値だけを同じ文書へ保持し、無制限の履歴コレクションは作らない。これにより1回前への復元余地を残しながら、文書数を増やさない。

### 4.2. 読み込み

1. 起動直後は通信を待たず、同梱基準形状を塗りつぶして表示する。
2. 端末に前回確認済みの更新値があれば、基準形状へ適用する。
3. 起動直後は通信せずキャッシュを使い、匿名認証後の航行開始、監視開始、「障害物の追加」画面開始時だけ、固定流木の1文書を1回取得する。
4. 取得した `revision` が端末キャッシュより新しければ、検証後に適用して端末へ保存する。
5. 通常航行中は固定流木の常時listenerや定期pollingを行わない。

固定流木は少しずつ移動する前提であり、秒単位の同期を必要としない。利用者が今すぐ最新状態を確認したい場合は、「障害物の追加」画面に「最新状態を取得」を用意する。

### 4.3. 書き込み

- ドラッグ中やスライダー操作中は端末内プレビューだけを更新し、Firestoreへ書き込まない。
- 「保存」を1回押した時だけ1回のtransactionで、現行 `revision` の確認と更新を行う。
- 読み込み時と保存時を除き、位置情報や固定流木の状態をFirestoreへ送信しない。
- 保存成功後にだけ端末キャッシュと確定表示を更新する。

この方式では、通常利用時の固定流木通信は数回の1文書読取だけで、書込は現地で実際に位置・サイズを直した回数に限られる。

## 5. 競合と検証

### 5.1. 同時編集

編集開始時の `revision` と保存時の `revision` が一致する場合だけ更新する。別端末が先に保存していた場合は自動上書きせず、最新状態を取得して編集をやり直すよう表示する。

### 5.2. 入力検証

- `baseShapeVersion` が端末の基準形状と一致しない更新値は適用しない。
- 中心位置は桜川・河口周辺の運用ガード（緯度36.060〜36.100、経度140.195〜140.230）内に制限する。
- 長さ倍率、幅倍率、回転角、外側安全余裕に上下限を設ける。
- 数値でない値、無限値、欠損値、許容外の追加フィールドを拒否する。
- `revision` は更新ごとに1だけ増やす。
- 固定流木文書のdeleteをFirestore Rulesで拒否する。

この範囲は別地域への誤移動を防ぐ初期ガードである。実運用前に衛星写真と現地で確認し、必要な場合だけアプリ定数とFirestore Rulesを同時に変更する。

## 6. Firestore権限

実装時は、現在の `static_obstacles` 用ルールではなく、実際に使用する次のパスへルールを設定する。

- `temporary_obstacles/{id}`: 認証済み利用者にread/create/update/deleteを許可し、形状・時刻・不変フィールドを検証する。
- `managed_hazards/fixed_driftwood_01`: 認証済み利用者にread/create/updateを許可し、deleteは禁止する。更新フィールド、数値範囲、`revision + 1`を検証する。

匿名認証は端末利用者を強く本人確認する仕組みではない。全ログイン利用者による共同編集を採用する代わりに、`updatedBy`、`updatedAt`、`revision`、直前状態を必ず残し、アプリ内で更新者と更新時刻を確認できるようにする。

現在提示されているRulesは `static_obstacles` と `messages` だけを許可しているため、この仕様の `temporary_obstacles` と `managed_hazards` への保存には使用できない。Firestoreの「データ」が空であることとも整合するが、原因の最終確認は実装後の実機ログとRulesエラー表示で行う。

## 7. 手動で必要になる作業

アプリ側の実装は完了している。利用開始前に、Firebaseコンソールで次を手動実施する必要がある。

1. Firestore Rulesを `temporary_obstacles` と `managed_hazards` の実パスへ更新して公開する。
2. 匿名Authenticationが有効なことを確認する。
3. `managed_hazards/fixed_driftwood_01` の初期文書は、アプリの初回保存で作成するか、管理用手順で1回だけ作成する。
4. 2台の実機で、他人が作成した臨時区域の編集・削除、固定流木の更新競合、オフライン時の基準形状表示を確認する。

現在提示されている旧Rulesのままではアプリからの保存が拒否される。実機確認前に、実装済みフィールドに合わせた完成版Rulesを適用する。

## 8. 受入基準

- 固定流木の外周中央へ艇位置を置いても、危険区域内として判定される。
- 固定流木の地図表示に未塗りつぶし部分がない。
- 固定流木を移動・拡大縮小・回転し、別端末の再取得後に同じ形状になる。
- 編集操作中に通信書込が発生せず、保存1回につき更新transactionが1回だけ実行される。
- Firestoreが空またはオフラインでも、同梱の固定流木が消えない。
- 固定流木は24時間経過しても消えず、削除操作も許可されない。
- ログイン中の利用者Bが、利用者Aの臨時危険区域を編集・削除できる。
- 臨時危険区域は、削除操作が行われるまで残り、編集を続けられる。
- 同時編集の古い画面から、より新しい固定流木状態を無言で上書きできない。
