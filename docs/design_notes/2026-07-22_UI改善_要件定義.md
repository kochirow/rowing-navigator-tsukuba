## 1. 背景・目的

前回のUI刷新以降、アプリは「チーム招待制・監視/航行の2モード・GPS/通信の劣化表示・危険区域の共同編集・プライバシー画面」を備えた運用システムへと拡張された。その結果、以下の実運用上の摩擦が生じている。

1. マップ画面の操作ボタンが増え、監視モードでは右側に最大6個(デバッグ時7個)が縦積みされ、小型端末やテキスト拡大時にオーバーフロー・重なりのリスクがある。
2. 岸で新メンバーを迎える際、20文字の招待コード手入力が導入のボトルネックになっている。
3. 色・角丸・余白がハードコードで散在(hex色リテラル49箇所、`BorderRadius.circular`29箇所、`withOpacity`23箇所)し、見た目の一貫性と保守性が低い。
4. マップ上に複数のボタン表現(濃紺円・写真タイル・小さい黒ピル)が同居し、視認負荷が高い。
5. 計器パネルが主数値(ペース・レート)と補助情報・状態バッジ・注意文を同列に扱い、一瞬のチラ見で主数値が読みにくい。
6. ローディング/空/エラー画面の表現が画面ごとにばらついている。
7. 「設定」ボタンが開く画面は「危険区域・警告設定」で、ラベルと内容が一致していない。
8. 記録画面が単発セッションの羅列のみで、週・月単位の練習量を把握できない。

本改善の狙いは、**安全機能の応答性・正確性を一切損なわずに**、屋外・移動中・濡れた手・一瞬のチラ見という実利用条件下での操作性と視認性、および導入体験を底上げすることにある。

## 2. 全体設計原則・横断制約

以下は全項目に共通して適用する。個別要件の受け入れ基準にも含める。

### 2.1 UI原則(`ui-design-principles.md` を踏襲・拡張)

- 実操作前提: 直射日光・濡れた手・揺れる艇上・一瞬のチラ見。主要タップターゲットは最小48dp、主計器は大型・等幅数字(`FontFeature.tabularFigures`)。
- UI文言・コメントは日本語。
- 破壊的・不可逆操作(航行終了・記録削除・危険区域削除・アカウント削除)は確認ダイアログ必須、危険色は danger トークン。
- 誤操作で位置共有・警告が止まらないこと。

### 2.2 技術・品質ゲート(全項目の完了条件)

- `flutter analyze`: 新規の error / warning を出さない(既存 info 相当と同種に留める)。
- `flutter test`: 既存テスト(現行約40ファイル)を**全て緑のまま維持**。特に以下のガードレールを壊さないこと。
  - `test/widget_test.dart`: SafetyBanner(警告対象なしで非表示/対象名の省スペース表示/推測と現在の複数警告の区別)、NavStatusCard(通信・対応水域の能力低下バッジを常時表示)、NavigationStatusPanel(経過時間の1秒更新)、NavSettingModal(名前必須・SPM OFF・二重押し無視)、main(Firebase初期化失敗の再試行)。
  - `test/widgets/boat_list_panel_test.dart`、`test/widgets/background_location_disclosure_dialog_test.dart`。
- 新規の純ロジック(例: 記録集計)には単体テストを追加する(リポジトリ慣習)。
- `dart format` 済み。ファイル名・命名は既存慣習(hooks は `useXxx.dart`、widget はパスカルケース)を踏襲。
- 依存追加は pubspec に明記し、プラットフォーム設定(Info.plist / AndroidManifest)への影響を要件に記す。
- 無料枠運用を維持(新たな定常通信・課金要素を持ち込まない)。

### 2.3 対象デバイス・堅牢性の基準

- 最小想定: iPhone SE 第2/3世代相当(論理375×667)およびシステムのテキストサイズ拡大 **1.3倍** まででレイアウト破綻(オーバーフロー・重なり・主要ボタンの画面外)を起こさない。
- 縦横のセーフエリアを尊重(全画面マップ + SafeArea オーバーレイの構造は維持)。

各項目は「現状/課題 → ゴール → 機能要件(FR) → UI仕様 → 非機能 → 影響範囲 → 受け入れ基準(AC) → テスト観点 → リスク・留意」で記述する。

### B-1. 色・角丸・余白のデザイントークン化 【基盤・最優先】

#### 現状/課題
- `lib/main.dart` にブランド色(`0xFF095372` ほか)、各widgetに danger/warning/caution 等の色が直書き。hex色リテラル49・`BorderRadius.circular`29・`withOpacity`23箇所。
- 同じ「赤(危険)」でも `0xFFC62828` / `0xFFB71C1C` / `Colors.red` が混在。角丸は 8/10/12/14/16/999 が混在。
- `SafetyBanner` は対象カテゴリ色(shore/bridge/island/driftwood/other_boat/curve/reverse/testZone)を独自に持つ。

#### ゴール
- 意味(セマンティック)で参照できる中央トークンを定義し、本改修で新規・変更する箇所は全てトークン経由にする。将来のダークテーマ追加を構造的に可能にする。

#### 機能要件(FR)
- **FR-B1-1**: `ThemeExtension` ベースのトークンを定義する。最低限、以下のカテゴリを持つ。
  - ブランド: `primary` / `primaryLight` / `primaryDark` / `onPrimary`
  - セマンティック状態(各 `main` と、必要なら `container`/`on`): `danger`(緊急・削除)、`warning`(警告)、`caution`(注意)、`ok`(正常・安全)、`info`
  - 面: `canvas`(scaffold背景)、`card`、`mapPanelScrim`(マップ上パネルの半透明濃色)、`mapControlSurface`(マップ操作ボタン面)
  - テキスト: `textPrimary` / `textSecondary` / `textDisabled` / `onDark`
- **FR-B1-2**: 余白スケール(8ptグリッド基準)と角丸スケール、標準elevation/影を定義する。
  - 余白例: `space1=4, space2=8, space3=12, space4=16, space5=24, space6=32`
  - 角丸例: `radiusSm=8, radiusMd=12, radiusLg=16, pill=StadiumBorder`
- **FR-B1-3**: `main.dart` のブランド色定義をトークンへ移設し、`ThemeData` はトークンから構築する。既存の `primaryColor` / `primaryColorDark` 参照は当面互換を保つ(段階移行可)。
- **FR-B1-4**: セマンティック状態色は既存の実値と視覚的に一致させる(下表)。安全表示の色が変わって見えないこと。
- **FR-B1-5**: `SafetyBanner` のカテゴリ色は当面据え置き可。ただし共通色(危険=danger)はトークンを参照し、二重定義を避ける。

#### 現行値 → トークンの対応(移行表・初期値)

| トークン | 初期値(現行実値に合わせる) | 現行の出所例 |
| --- | --- | --- |
| primary | `#095372` | main.dart |
| primaryLight | `#4D9CBF` | main.dart |
| primaryDark | `#002E4D` | main.dart |
| danger | `#C62828` | 航行終了・削除・異常 |
| warning | `#EF6C00` / `#E65100` | 警告バナー・復旧注意 |
| caution | `#F9A825` / `#F57F17` | 注意・安全注記枠 |
| ok | `Colors.green` 相当 | 艇一覧の正常アイコン |
| canvas | `#F4F6F8` | scaffold背景 |
| cautionSurface | `#FFF8E1` / `#FFF3E0` | 注意カード背景 |
| mapPanelScrim | `black @ 0.6–0.88` | 監視チップ・計器カード |

> 注記: caution/warning は現状2値ずつ揺れているため、本改修で各1値に正規化する(例: warning=`#E65100`、caution=`#F9A825`)。最終値は視認確認で微調整可。

#### 非機能
- `Theme.of(context).extension<AppColors>()!` で全画面から参照可能。ダーク版を後から追加できるよう、明暗2セットを差し込める構造(まずはライトのみ実装)。
- `withOpacity` は将来の非推奨化を見据え、可能な箇所は `withValues(alpha:)` を用いる(既に一部採用済み)。

#### 影響範囲(想定)
- 追加: `lib/theme/app_colors.dart`、`lib/theme/app_dimens.dart`、`lib/theme/app_theme.dart`(構成は実装時に決定)
- 変更: `lib/main.dart`。以降 B-2/B-3/B-4/A-1/C-2/C-3 で新規・変更する箇所。
- CLAUDE.md 整合: 「警告関連の**設定値**はハードコードせず `lib/config/` に置く」は維持。本トークンは**色・寸法という視覚値**を扱い、警告の**しきい値・時間**は従来どおり `lib/config/` に残す。相互参照をコメントで明記。

#### 受け入れ基準(AC)
- **AC-B1-1**: トークンが `ThemeExtension` として定義され、サンプル1画面(例: 記録画面ヘッダ)で参照されている。
- **AC-B1-2**: 本改修で新規追加・変更したwidgetに、状態色・角丸・主要余白のハードコードが**新規に増えていない**(トークン経由)。
- **AC-B1-3**: 既存の安全表示(SafetyBanner/計器カード/危険区域色)の見た目が実質同一(色差が視認できない)。
- **AC-B1-4**: `flutter analyze` / `flutter test` 緑。

#### テスト観点
- トークン定義自体は単純だが、`AppColors.lerp` を実装する場合はスモークテスト。既存widgetテストが色変更で落ちないこと。

#### リスク・留意
- 全49箇所の一括置換は差分過大・レビュー困難になるため、**本改修で触る箇所のみトークン化**し、全面移行はしない(移行表を残し将来機械的に置換可能にする)。

### B-4. ローディング/空状態/エラー表示の統一

#### 現状/課題
- ローディングが画面ごとに異なる: `FirebaseBootstrap`(素のスピナーのみ)、`AppEntryGate`(漕ぐアイコン+スピナー+文言)、`HomeMapScreen`(漕ぐアイコン+スピナー+文言)、`area/danger/record`(素のスピナー)。
- エラー画面も個別実装: `FirebaseBootstrap`「サービスを開始できませんでした」、`AppEntryGate`「チーム情報を確認できませんでした」、`HomeMapScreen` initError、`area_setting_screen` の位置情報カード。
- 空状態は記録一覧・艇一覧にそれぞれ個別実装。

#### ゴール
- ローディング・空・エラーの3種を共通コンポーネント化し、全画面で一貫した表現(ブランドの漕ぐアイコン、丁寧な日本語、トークン準拠の余白)にする。ロジックは変えない(純粋に表示の統一)。

#### 機能要件(FR)
- **FR-B4-1**: `AppLoadingView({IconData icon = Icons.rowing, String? message})` を追加。アイコン+スピナー+任意メッセージ。文言は各呼び出し側が渡す(文脈固有の情報は消さない)。
- **FR-B4-2**: `AppEmptyView({IconData icon, String title, String? message, Widget? action})` を追加。記録一覧・艇一覧の空表示を置換。
- **FR-B4-3**: `AppErrorView({IconData icon, String title, String message, String primaryLabel, VoidCallback onPrimary, String? secondaryLabel, VoidCallback? onSecondary})` を追加。初期化失敗・チーム復元失敗・現在地取得失敗の再試行画面を統一。
- **FR-B4-4**: 以下を共通部品へ置換する。
  - ローディング: `FirebaseBootstrap` / `AppEntryGate` / `HomeMapScreen`(初期化) / `AreaSettingScreen` / `DangerZoneSettingsScreen` / `RecordListScreen`
  - エラー/再試行: `FirebaseBootstrap` / `AppEntryGate` / `HomeMapScreen` initError
  - 空: `RecordListScreen` / `BoatListPanel`
- **FR-B4-5**: `area_setting_screen` の `_LocationIssueCard`(地図に重ねる注意カード)は全画面エラーではないため、共通化は任意。少なくとも色・角丸はトークンに合わせる。

#### UI仕様
- ローディング: 縦中央、`icon(56, primary)` → `space5` → `CircularProgressIndicator` → `space4` → message(textSecondary, 16)。
- 空: `icon(56, textDisabled)` → title(16, textSecondary) → message(13, textDisabled) → 任意アクション。
- エラー: `icon(52, danger または textSecondary)` → title(20 bold) → message(中央寄せ, textSecondary) → 主ボタン(FilledButton.icon 再試行) → 任意副ボタン(端末設定を開く等)。

#### 非機能
- メッセージ引数は必須ではなく任意にし、既存の具体的メッセージ(例: 「位置情報を取得しています…」「チーム情報を確認しています…」)を維持する。
- 表示のみで、非同期処理・リトライロジックは既存のまま。

#### 影響範囲
- 追加: `lib/widgets/`(例: `app_state_views.dart` もしくは個別ファイル)。
- 変更: 上記各画面の該当ブロック。

#### 受け入れ基準(AC)
- **AC-B4-1**: 起動〜チーム参加〜ホームのローディングが同一の見た目・文言トーンで表示される。
- **AC-B4-2**: 記録一覧・艇一覧の空表示が `AppEmptyView` に統一されている。
- **AC-B4-3**: 初期化失敗・チーム復元失敗・現在地取得失敗が `AppErrorView` に統一され、再試行が従来どおり機能する。
- **AC-B4-4**: 既存の main テスト(Firebase初期化失敗の再試行)が緑。

#### テスト観点
- `AppErrorView` の主ボタン押下でコールバックが呼ばれるwidgetテストを追加(任意だが推奨)。既存の main.dart 失敗テストが新コンポーネントでも通ること。

#### リスク・留意
- `FirebaseBootstrap` は `App`(MaterialApp/テーマ)より外側で描画されるため、`AppLoadingView` がテーマ未適用でも破綻しない実装にする(色はフォールバック可)。

### B-2. マップ操作ボタンの見た目言語の統一

#### 現状/課題
- マップ上に3系統の表現が同居: `RoundedIconButton`(濃紺円+黒半透明ラベル)、`MapTypeSwitcher`(写真タイル)、`_CompactMapActionButton`(小さい黒ピル「詳細」)。加えて下部の主要アクションは `RoundedButton`(塗りつぶしピル)。
- トグル状態(艇一覧の開閉、追跡ON/OFF、地図種別)の視覚表現がない。

#### ゴール
- マップ操作系ボタンを1つの視覚言語に統一する。主要アクション(航行/監視スタート・終了)の塗りつぶしピルとは**意図的に別階層**として整理する(2階層に整理し、各階層内で一貫)。

#### 機能要件(FR)
- **FR-B2-1**: マップ操作用の共通ボタン部品(例: `MapControlButton`)を定義する。仕様:
  - 形状: 円(直径56dp目安)、面色 = `mapControlSurface` トークン、影 = 標準elevation。
  - 内容: アイコン + 直下に小ラベル(pill、`mapPanelScrim` 背景)。
  - 状態: 通常 / 押下 / 無効 / **選択(トグルON)**。トグルONは面を primary 塗りに反転。
- **FR-B2-2**: `RoundedIconButton` を `MapControlButton` に統合または置換する(APIは `icon` / `label` / `color` / `onPressed` / `active` を持つ)。回転(`angle`)対応は「追跡」アイコン用に維持。
- **FR-B2-3**: `MapTypeSwitcher` を同一サイズ・角丸・ラベル様式に合わせる。写真サムネは維持してよいが、寸法・ラベル位置・影を共通仕様に揃える。地図種別は「トグル/切替先明示」の現行仕様を維持。
- **FR-B2-4**: `_CompactMapActionButton`(デバッグ「詳細」)は A-1 のメニューへ集約し廃止する。残す場合も `MapControlButton` 様式に統一する。
- **FR-B2-5**: トグルON表示を「艇一覧(パネル表示中)」「追跡(track中)」「地図種別」に適用する。

#### UI仕様
- サイズ・余白・角丸・影・ラベル様式はトークン(B-1)を用いて1箇所に定義。
- ラベルは常時表示(直射日光下の識別性のため)。

#### 影響範囲
- 追加: `lib/widgets/map_control_button.dart`(名称は実装時決定)。
- 変更: `lib/widgets/rounded_icon_button.dart`(統合/置換)、`map_type_switcher.dart`、`home_map_screen.dart`、`area_setting_screen.dart`。

#### 受け入れ基準(AC)
- **AC-B2-1**: マップ上の操作ボタンが1系統の見た目(サイズ・角丸・面・ラベル)に統一されている。

### B-3. 計器パネル(NavStatusCard)の情報階層整理

#### 現状/課題

#### ゴール
- 主計器(ペース・レート)を最優先で読ませ、補助・状態・注意を明確に下位化する3階層に整理。安全上の常時表示要件(能力低下バッジ・目視確認注記)は保持しつつ視覚的重みを下げる。

#### 機能要件(FR)
- **FR-B3-1**: 3階層を明確化する。
  1. 主計器: `ペース(/500m)` と `レート(spm)`。最大・高コントラスト・等幅。
  2. 補助: `距離` / `経過時間`。中サイズ。
  3. 状態: `GPS鮮度` と `能力低下バッジ`。**異常時のみ強調**、正常時は最小(小さな正常アイコン)。
- **FR-B3-2**: 固定注意文「…周囲を目視確認」は**削除せず**、最下部・最小ウェイトのキャプションに留める(警告色にはしない)。安全メッセージのため常時視認可能を維持。

#### UI仕様

### A-3. 招待コード参加のオンボーディング改善(短縮・共有)

> 2026-07-22 方針変更: QRコード表示・アプリ内読取は一旦見送る。新規発行コードを12文字へ短縮し、既存20文字コードとの後方互換と共有シートを優先する。

#### 現状/課題
- `team_screen` は整形コード表示+「コピー」のみ。参加は `team_onboarding_screen` の手入力(`XXXXX-XXXXX-XXXXX-XXXXX`)。岸で新メンバーに20文字入力させるのは大きな摩擦。

#### ゴール
- 新規コードを現実的な長さへ短縮し、コピーまたはOS共有シートで受け渡せるようにする。既存チームはそのまま利用でき、カメラ権限や新規通信は追加しない。

- **FR-A3-1**: 新規チームは読み違いにくい30文字集合から12文字（約59bit）を生成し、`XXXX-XXXX-XXXX` で表示する。
- **FR-A3-2**: 更新前に発行済みの20文字コードも正規化・表示・参加・復元・共有で受理する。既存チームのコードや保存データを移行しない。
- **FR-A3-3**: コード予約のRTDB transactionとFirestoreの衝突確認を維持する。RTDB/Firestore Rulesは12文字と既存20文字だけを受理する。

- 新規12文字は4文字ごとに区切り、入力欄のヒントも `XXXX-XXXX-XXXX` に合わせる。

#### 影響範囲
- 変更: `team_service.dart`、`team_screen.dart`、`team_onboarding_screen.dart`、`firestore.rules`、`database.rules.json`、関連テスト・説明文書。

### C-3. 記録画面の集計(期間別サマリー)
