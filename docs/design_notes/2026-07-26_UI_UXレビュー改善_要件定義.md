# UI/UX レビュー改善 要件定義

作成日: 2026-07-26

## 1. 目的

2026-07-26 の UI/UX レビューで検出した、以下の課題を解消する。

1. 画面の視覚的優先順位が安全と逆転している(計器がもっとも大きく、警告が小さい)
2. 音の緊急度バンド(連続音・断続音・表示のみ)が画面に出ておらず、
   音が聞こえない状況で切迫度を判別できない
3. 地図上の危険区域がすべて同じ赤で描かれ、種類の区別がつかない
4. 自艇の予測領域と実在する危険区域が同じ塗りで区別できない
5. 状態通知が消えるトーストに載っており、しかも主要操作ボタンを覆う
6. 触覚フィードバックが存在せず、濡れた手・揺れる艇上で操作結果が分からない
7. 待機中でも「監視モード」と表示され、同時に「監視スタート」ボタンが出る
8. 暗所・早朝夕方向けのダークテーマがない

本アプリは衝突回避を保証しない。**本要件は表示・入力・操作の層だけを対象とし、
安全判定、警告候補の生成、音声の鳴り方、しきい値は一切変更しない。**

## 2. スコープ

### 2.1 対象

- 警告バナーの切迫度表示と読み上げ
- 航行計器カードの視覚的比重
- 地図ポリゴン(危険区域・船舶領域)の配色
- 状態通知の提示先(トースト → 常設バッジ)
- 触覚フィードバック
- マップ操作メニュー・モードチップ・開始シートの操作性
- デザイントークンの適用漏れと最小文字サイズ
- ダークテーマ、高コントラスト地図、使い方、端末情報

### 2.2 対象外

- 衝突判定・リスク評価・警告候補の生成ロジック
- 音声アセット、音の鳴り方、`AlertPresentationConfig` のしきい値
- `lib/config/` の安全設定値
- Firebase プロジェクト設定・課金・認証方式
- 既存テストが固定している文言・書式
  (`他艇受信: 利用不可` 等の能力低下バッジ、経過時間 `0:00`、`右 5秒`)

### 2.3 レビュー時点で既に実装済みだったため対象外

- 警告バナーへの残り秒数表示(`右 5秒` の2行目)
- 警告バナーへの相対方向表示(`NavigationWarning.directionLabel`)
- 同種警告のグループ化と件数表示(`×3`)
- 計器カードの文字1.3倍時のレイアウト検証

## 3. 機能要件

### FR-UI2-01 緊急度バンドの可視化

- `NavigationWarning` に画面用の切迫度 `WarningDisplayUrgency` を持たせる。
- 値は既存の `AlertBehavior` から導出し、**新しい判定を追加しない**。
  - `continuousAction`(連続音) → `imminent`
  - `singleAction` / `entryEvent`(単発・断続音) → `action`
  - `visualOnly`(表示のみ) → `monitoring`
  - `persistentSystemFault`(周期音) → `action`
- バナーは切迫度ごとに見た目を変える。
  - `imminent`: 最大文字・太枠・警告色の脈動(1Hz)
  - `action`: 濃色・通常枠
  - `monitoring`: 淡色・細枠
- 脈動は表示のみで、音声・判定・送信には影響しない。
- `RiskAssessment` 経由の警告(`fromAssessment`)は既定 `action` とする。

### FR-UI2-02 警告時の視覚的優先順位

- `imminent` の警告が1件でも存在する間、計器カードの主計器(ペース)を
  縮小し、SPM 欄を隠す。距離・時間・状態表示は維持する。
- 警告が解除されたら元の寸法へ戻す。
- 計器カードの既定動作は変更しない(引数の既定値は従来表示)。

### FR-UI2-03 警告の読み上げ

- 警告バナーの `Semantics` を `liveRegion: true` にし、警告の出現・変化を
  スクリーンリーダーが即時読み上げられるようにする。
- 読み上げ文言は既存(対象・方向・秒数・件数・詳細)を維持する。

### FR-UI2-04 危険区域のカテゴリ別配色

- 危険区域の色定義を `lib/theme/hazard_palette.dart` へ一元化し、
  警告バナーと地図ポリゴンが同じ定義を参照する。
- 岸は常時存在する背景であるため塗りを薄く(不透明度 0.18)し、
  流木・中州・臨時区域は濃く(0.45)する。
- 橋・カーブ・逆走は案内区域として中間(0.28)とする。
- 塗りの薄い区域には輪郭線を付け、塗りだけに依存しない。

### FR-UI2-05 予測領域と危険区域の区別

- 自艇・他艇の船舶領域(予測)は**塗りを主体にせず輪郭線主体**で描く。
- 「塗り = 実在する危険」「線 = 予測」という規則を全画面で守る。
- 停止距離内・警告距離内の色分け(赤・黄)は維持する。

### FR-UI2-06 状態通知の提示先

- 継続する状態(受信不可・未検証水域)は常設の能力低下バッジで示し、
  同じ内容を重ねてトーストで出さない。
- 一時的な出来事(電池低下・監視異常・操作結果)はトーストのままとする。
- トーストは画面下部の主要操作ボタンを覆わない位置に出す。
- 能力低下バッジは固定2列グリッドをやめ、文言が省略されない折返しにする。

### FR-UI2-07 触覚フィードバック

- 主要操作ボタン(`RoundedButton`)とマップ操作ボタン(`MapControlButton`)は
  タップ時に選択触覚を返す。
- 警告が `imminent` へ遷移した瞬間に強い触覚を1回返す。
  同じ警告が続く間は繰り返さない。
- 触覚の失敗は握りつぶし、航行・警告・音声を止めない。

### FR-UI2-08 モード表示の一貫性

- 「監視モード」チップは監視を開始しているときだけ表示する。
- 監視していない待機状態ではチップを出さない。

### FR-UI2-09 メニュー項目の恒常性

- 航行中に利用できない項目は、消さずに無効表示で残す。
- 無効な項目には理由(「航行終了後に利用できます」)を添える。
- 無効項目はタップしてもシートを閉じず、画面遷移もしない。

### FR-UI2-10 開始シートの入力

- 航行開始シートを `isScrollControlled` で開き、キーボード表示時に
  名前入力欄が隠れないようにする。
- 保存済みの既定値がある場合、シート先頭に「前回と同じ設定で開始」を置き、
  スクロールなしで航行を開始できるようにする。
- 詳細(艇種・シート位置・SPM)は従来どおり変更できる。

### FR-UI2-11 デザイントークンの適用

- 画面・ウィジェット内へ直接書かれた色を `context.colors` へ置き換える。
- 危険色は `colors.danger`、注意色は `colors.warning` を使う。
- 最小文字サイズを 12px とする(従来 10〜11px の補助文言)。

### FR-UI2-12 ダークテーマ

- `AppColors.dark` を追加し、`ThemeMode.system` で自動追従する。
- 面・文字・境界のトークンを暗色向けに定義し、
  セマンティック色(danger/warning/caution/ok/info)は暗所で沈まない明度にする。
- ダーク時は地図も夜間スタイルへ切り替える。
- トークン経由で描かれていない箇所が残る場合、その画面は
  明色固定として破綻させない。

### FR-UI2-13 高コントラスト地図

- 地図を淡いグレースケールにし、危険区域・艇・航跡だけ彩度を残す
  表示モードを追加する。
- 切替はマップメニューから行い、端末内に保存する。
- 地図スタイルの適用に失敗しても通常表示のまま航行を継続する。

### FR-UI2-14 使い方

- マーカー・危険区域の色・警告の3段階を説明する画面を追加する。
- 警告音を種類ごとに試聴できるようにする。
- マップメニューから開ける。

### FR-UI2-15 端末情報

- リリースビルドでも、GPS 精度・最終測位からの経過・送信間隔・
  警告処理の状態を読み取り専用で確認できるようにする。
- 現地でのトラブルシュートを目的とし、設定変更機能は持たせない。

## 4. 非機能要件

- 安全判定は 1 Hz を維持し、表示変更が評価周期へ影響しない。
- 脈動アニメーションは警告表示中のみ動作し、非表示時はタイマーを止める。
- 触覚・地図スタイル・テーマの失敗が航行開始や警告経路を止めない。
- 既存のウィジェットテストが固定する文言・書式を変更しない。
- `dart analyze lib test` で error / warning 0 件を維持する。

## 5. 受け入れ基準

- 全単体・ウィジェットテストが成功する。
- `dart analyze lib test` が無警告である。
- 切迫度 `imminent` / `action` / `monitoring` が見た目で判別できる。
- 警告バナーが `liveRegion` として読み上げ対象になる。
- 岸と流木が地図上で別の色・濃度で描かれる。
- 船舶領域が輪郭線主体で、危険区域の塗りと混ざらない。
- 臨時危険区域の受信不可がトーストで重複表示されない。
- 監視未開始で「監視モード」チップが出ない。
- 航行中もメニュー項目が消えず、無効理由が表示される。
- 既定値保存済みの端末で、スクロールせずに航行を開始できる。
- ダークテーマで主要画面の文字が背景に埋もれない。
