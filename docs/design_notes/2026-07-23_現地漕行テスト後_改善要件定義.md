# 現地漕行テスト後の改善要件定義

作成日: 2026-07-23

## 1. 目的

2026-07-23 の桜川での実艇テストで確認された、過剰警告、休憩中の反復警告、
固定障害物の位置ずれ、横画面での地図縮小、SPM の誤計測、記録共有の無反応を
改善する。同時に、警告挙動の再現とトレーニング分析に使える診断記録を整備する。

本アプリは衝突回避を保証するものではない。安全評価の頻度や GNSS フィルターを
弱めず、警告の意味と提示方法を分離することで、警告漏れを増やさずに過剰な音声を
減らす。

## 2. スコープ

### 2.1 対象

- 固定障害物・案内区域の警告提示
- 休憩・安定停止中の音声制御
- 固定障害物の危険範囲設定と位置校正
- 固定障害物の位置校正・危険範囲のチーム共有
- 航行画面の縦・横向きレイアウト
- 警告バナーの視認性と艇マーカーの大きさ
- SPM の既定値、表示、実験機能としての扱い
- GPX・CSV の共有
- 診断記録、エクスポート、トレーニング分析

### 2.2 対象外

- Firebase プロジェクト、認証方式、課金設定の変更
- 診断データの自動アップロード
- SPM を正式なトレーニング指標として保証すること
- 実測していない橋脚・障害物座標を推測で本番プリセットへ反映すること

## 3. 機能要件

### FR-ALERT-01 警告段階

- リスク評価は航行中 1 Hz を維持する。
- 注意は画面表示を基本とし、早期候補だけで反復音声を開始しない。
- 行動警告は短い音声を一回再生する。
- 緊急は、衝突予測時間が緊急閾値以内、または物理危険領域へ接近しながら重なった
  場合に反復音声を許可する。
- 他艇と固定障害物の時間閾値を独立して設定できる構造にする。

### FR-ALERT-02 安定停止

- 速度 0.4 m/s 未満が 5 秒以上継続し、対象への接近が認められない状態を
  「安定停止」とする。
- 安定停止中も安全評価と画面表示は継続する。
- 同一脅威の反復音声は抑制する。
- 再航行、別脅威への遷移、または対象へ 2 m 以上接近した場合は再警告できる。
- 停止中でも他艇側が接近し得るため、他艇の緊急警告は抑制対象にしない。

### FR-ALERT-03 案内区域

- 逆走・カーブ案内は区域進入時に一回通知する。
- 区域外へ出て 5 秒以上経過するまで再通知しない。
- 橋は通航可能な橋下空間と物理障害物である橋脚・橋台を区別できるデータ構造を
  将来追加できるよう、案内と物理危険物の提示動作を分離する。

### FR-ZONE-01 危険範囲

- 設定画面の岸・橋・中州・流木の各スライダーを操作できる。
- 変更は保存直後から地図描画と警告判定の両方へ反映する。
- Release ビルドでも端末内設定を適用する。
- 設定範囲を 0〜30 m、刻みを 0.5 m とし、既定値へ戻せる。

### FR-ZONE-02 固定障害物の位置校正

- 固定障害物を一覧または地図から選択できる。
- 選択した障害物全体を北・南・東・西へ 0.5 m 単位で移動できる。
- 東西・南北の補正量を数値で確認できる。
- 変更は端末内に保存し、地図描画と警告判定へ即時反映する。
- 障害物単位のリセットと全件リセットを提供する。
- 誤操作防止の説明を表示し、航行中の操作を前提にしない。
- 元のプリセット座標、プリセット版、補正量を診断記録へ残す。

### FR-ZONE-03 チーム共有の下書きと公開

- スライダーと 0.5 m ボタンの操作は端末内下書きだけを変更し、自動で共有しない。
- 同じチームのメンバーが「チームに公開」を明示的に押したときだけ
  共有確定版を更新する。
- 公開前に、対象障害物名、北・東の補正量、補正前後の中心座標、参照した航行記録を
  確認する。
- 公開は位置校正全体を一つの revision として行い、別端末による先行更新を
  transaction で検知する。
- 危険範囲の公開と位置校正の公開は別操作とし、片方の公開で他方を上書きしない。
- 同じチームのメンバーは共有確定版を読み取り、現地で発見した位置ずれや
  危険範囲を公開できる。別チームおよびチーム未参加者は読み書きできない。
- 共有確定版には、基準プリセットの version と SHA-256 を保存する。一致しない
  アプリでは共有値を適用せず、更新が必要であることを表示する。
- リセットは文書削除ではなく、0 m の補正または既定の危険範囲を新しい revision
  として公開し、オフライン端末にも解除を伝播させる。

### FR-ZONE-04 低使用量同期と航行中反映

- 位置校正と危険範囲をチーム単位の一つの Firestore 文書へ格納する。
- 監視開始または航行開始時に限り、共有文書一件へ listener を一つだけ接続する。
- 監視・航行の終了時に listener を解除し、重複 listener を作らない。
- listener は文書が変更されない限り周期的な get を行わない。
- 新しい revision を受信した場合だけ共有キャッシュを更新し、短時間の連続更新は
  5 秒以内に一回へ集約する。
- 航行中に新しい revision を受信した場合、固定障害物を再生成し、次の 1 Hz
  安全評価から新しい位置と危険範囲を使用する。
- 共有取得・再生成に失敗しても、最後に検証済みの障害物と 1 Hz 安全評価を維持し、
  小さな一回性通知だけを表示する。
- オフライン時は端末に保存した最後の共有確定版を使用する。共有キャッシュがない
  場合は、同梱プリセットと端末既定値を使用する。
- 同一 revision、古い revision、基準プリセット不一致、壊れた値は適用しない。
- 共有更新の診断イベントへ revision、受信時刻、適用結果を保存する。

### FR-ZONE-05 Firebase 使用量上限

- 一つの共有更新は Firestore 一文書 write とする。
- 一台の端末が一回の監視・航行で行う通常の初期同期は一文書 read とする。
- 文書が変更された場合だけ、接続中の各端末で一文書 read が追加される。
- 12 台が一回の練習で接続し、共有更新を 10 回行う試算を、
  最大 `12 × (初期 1 + 更新 10) = 132 document reads` とする。
- Security Rules のチーム所属確認に伴う依存 read と再接続を含めても、
  一回の練習で 1,000 reads 未満を設計上限とする。
- さらに厳しい「12台、共有更新4回、端末ごと20回再接続」では、listener、
  Rules依存read、公開transactionを合わせて608 readsと試算する。
- Firestore の利用量計算を定数化した単体テストを用意し、listener 本数、
  初期 read、更新 read、再接続 read の増加を検知する。

### FR-UI-01 航行計器の省スペース表示

- 縦向き・横向きとも、航行情報を左上のコンパクト表示にする。
- 横向きでは地図を画面の概ね 80% 以上見える状態にする。
- 経過時間、距離、ペースを表示する。
- SPM がオフの場合は SPM 欄や「SPM オフ」という占有表示を出さない。
- SPM がオフの場合は、計器カードの幅もさらに縮める。
- 縦向きのペース主表示は従来からわずかな縮小に留め、即読性を維持する。
- 警告バナーは航行情報とは独立した細い表示にする。

### FR-UI-02 警告バナーの視認性

- 画面上の主表示は「岸」「橋」「中洲」「流木」「他艇」「カーブ」「逆走」など、
  危険種別だけを短く表示する。
- 「接近中」など状況から自明な語と予測秒数は主表示へ重ねない。
- 短文化で確保した領域を使い、主表示の文字を従来より大きくする。
- 詳細な警告名、説明、予測秒数は読み上げ用のセマンティクスに保持する。
- 予測・現在・緊急の区別は、文字量ではなく色とアイコンでも維持する。

### FR-UI-03 艇マーカー

- 自艇と他艇は同じ基準寸法を使用する。
- 通常の航行ズームで従来より一段階だけ小さくし、障害物と航路を隠しにくくする。
- ズーム量に応じた最小・最大寸法の制御は維持する。

### FR-SPM-01 SPM の扱い

- 新規利用者と設定未保存の利用者は既定でオフにする。
- オンにする設定には「実験機能」と明記する。
- オフ時は加速度センサー購読と解析タイマーを停止する。
- 既存記録に SPM がある場合、そのデータは削除しない。
- 低信頼度・停止・旋回を数値として誤表示しないための研究改善は別段階とする。

### FR-EXPORT-01 GPX・CSV 共有

- 共有中の進捗を表示し、二重押下を防ぐ。
- 一時ファイルの存在と非空を確認する。
- iOS/iPadOS 用の共有元矩形と適切な MIME type を指定する。
- 共有の完了・キャンセル・失敗を判別する。
- 失敗時は画面にエラーを表示し、再試行できる。

### FR-DIAG-01 診断記録

- セッション本体との後方互換性を保ちつつ、スキーマ版を付与する。
- 1 Hz の航行記録に、GNSS 品質、フィルター結果、安全判定の主要結果を保存できる。
- 警告候補、採用脅威、危険度、重なり、状態遷移、音声動作をイベントとして保存する。
- 画面方向、位置精度低下・復帰、ライフサイクルをイベントとして保存できる。
- SPM 実験機能の生 IMU は通常記録へ含めず、明示的な診断モードだけを対象にする。

### FR-DIAG-02 診断エクスポート

- 診断パッケージは `manifest.json`、`track.csv`、`alerts.jsonl`、
  `events.jsonl` を ZIP にまとめる。
- 正確な航路と端末情報を含む旨を共有前に説明する。
- 自動送信せず、利用者が明示的に共有操作を行う。
- 他艇の永続的な識別子は診断ファイルへ直接保存しない。

### FR-TRAIN-01 記録分析

- 移動時間と休憩時間、250 m・500 m 区間、ペース推移を表示する。
- 航跡と警告エピソードを関連付ける。
- 警告エピソードへ「早すぎる」「適切」「誤警告」「位置ずれ」「鳴りすぎ」の
  評価を端末内で付与できる。
- 検証前の SPM からパワーを推定しない。

## 4. 非機能要件

- GNSS による安全評価を 1 Hz で維持する。
- 航行中の Wakelock と既存の記録復旧を維持する。
- 診断記録の失敗で航行や安全評価を停止しない。
- 保存形式はスキーマ版を持ち、既存セッションを読み込める。
- 位置補正と危険範囲設定は端末内で完結し、通信不能でも利用できる。
- 共有同期は一文書・一 listener とし、障害物数に比例して read を増やさない。
- 新しい通知は小さく、一回性で、航行操作を妨げない。
- 画面表示の短文化や縮小によって、安全判定、警告候補、音声判定は変更しない。

## 5. 受け入れ基準

- 全単体・ウィジェットテストが成功する。
- `dart analyze lib test` で error と warning が 0 件である。
- `git diff --check` が成功する。
- 危険範囲スライダーを変更すると、再起動後も値が維持される。
- Release 相当の設定でも、変更した危険範囲と位置補正がプリセットへ反映される。
- チームメンバーの公開後、同じチームの別端末へ同じ revision が反映される。
- 別チームおよびチーム未参加者は共有確定版を更新できない。
- 航行中に共有 revision が変わると、次回の安全評価から新しい障害物が使われる。
- 同じ revision の再通知では障害物を再生成しない。
- 12 台・共有更新・再接続・Rules依存readを含む使用量試算が
  1,000 reads 未満である。
- 安定停止中、同一固定障害物の音声が連続再生されない。
- 逆走・カーブ案内は同じ区域内で反復しない。
- SPM オフ時、センサー購読と表示領域が存在しない。
- GPX・CSV 共有の失敗が無反応にならない。
- 既存記録を破損せず読み込める。

## 6. 実機確認項目

- 問題のある橋を両方向に 2 回以上通過する。
- 橋下と岸際でそれぞれ 60〜90 秒停止する。
- 障害物へ接近後、衝突前に旋回して離れる。
- 逆走区域へ一度入り、区域内に留まり、退出後に再進入する。
- 横向きで地図、航行値、警告が同時に読めることを確認する。
- 縦向きで SPM オフ時とオン時の計器幅を比較し、オフ時に地図が広く見えることを
  確認する。
- 日中の屋外で短い警告ラベルが読め、自艇と他艇のマーカーが地図を隠しすぎないことを
  確認する。
- GPX、CSV、診断 ZIP を iPhone の共有シートと「ファイルに保存」で確認する。
- 位置校正は橋下の単一点だけで決めず、両方向の複数航跡と航空写真を照合する。

## 7. Firebase設計根拠

- Cloud Firestore Standard は document read 50,000件/日、write 20,000件/日の
  無料枠を持つ。
  <https://firebase.google.com/docs/firestore/pricing>
- listener は接続時間ごとの周期課金ではなく、初回結果と文書の追加・更新・削除、
  および条件に該当する再接続で read が発生する。このため、短い周期の `get()` より
  一文書listenerの方が、変更頻度が低い共有校正に適する。
  <https://firebase.google.com/docs/firestore/pricing#listening_to_query_results>
- transaction は読んだ文書が競合更新された場合に再実行され、途中のwriteを
  部分適用しない。共有revisionの競合防止に使用する。
  <https://firebase.google.com/docs/firestore/manage-data/transactions>
