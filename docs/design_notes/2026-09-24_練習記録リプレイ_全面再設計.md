# 練習記録の全面再設計 ——「リプレイ」

作成日: 2026-09-24
状態: **確定(2026-09-24、試作 v8 で利用者が確認)。** 実装は [実装計画](../実装計画_2026-09-24_練習記録リプレイ.md) に従う。
動く参照物: [tool/prototypes/record_replay/](../../tool/prototypes/record_replay/)
対象: `lib/screens/record_list_screen.dart`(1,185行)/ `lib/services/session_analyzer_service.dart` /
`lib/models/session_model.dart`、および新設する表示専用の部品。
前身: [2026-08-20_練習記録の見せ方_再設計.md](2026-08-20_練習記録の見せ方_再設計.md)。
その指標の定義(ペース・レート・1漕距離の3点セット、除外を黙らない、上り/下り)は**そのまま引き継ぐ**。
変えるのは画面の骨格で、「区間の表を入口にする」構成を**「地図と時間軸で記録を再生し、見たい区間を自分で切り出す」**構成に置き換える。
安全経路には一切触れない(§11)。

## 0. 結論

1. **記録画面を「再生できる1枚」にする。** 地図・時間軸・数値の3つが
   **同じ1つの時刻(カーソル)と同じ1つの区間(選択)** を共有し、どれを触っても残りの2つがついてくる。
2. **最初に見せるのは地図と4つの数字と時間軸だけ。** グラフは区間を選んだときに**1枚だけ**出す。
   いまの「ピースごとの折れ線が縦に並ぶ」画面はなくす。
3. **区間の選び方は何通りあってもよいが、選んだ結果は必ず同じ1つの「区間」になる。**
   ピースをタップ、時間軸をなぞる、「ここから/ここまで」、分:秒の入力、地図上の2点、
   ベスト区間・橋から橋の固定区間。**どの入口から入っても、同じ数字と同じグラフが出る。**
4. 桜川は**毎回同じ川を漕ぐ**。これを使い、Strava のセグメントにあたる
   **「橋から橋」の固定区間**を自動で切り出し、日をまたいでタイムを比べられるようにする(R4)。
5. 監視端末の練習一括ログがあれば、**全艇を同じ時間軸で同時に再生**できる(R5)。

動く試作は `tool/prototypes/record_replay/`(v8)。§6.3a 以降の確定事項は試作で利用者が操作して決めた。

## 1. いま何が困っているか

利用者の言葉(2026-09-24):

- 「スプリットごとにグラフを出しているが、多すぎて見ていられない」
- 「シンプルさと、痒いところに手が届く感じを両立したい」
- 「何分から何分と、スマホ上でシンプルに指定して、その区間のスピード推移を見たい」
- 「地図に航跡を出し、時間スライダーを動かすと、航跡上をアイコンが動いてほしい」
- 「それを使って、欲しい区間を見ながら選べるようにしたい」

コードで確かめた事実(2026-08-20 ノート §1 と同じ。今日の `main` でも変わっていない):

| 事実 | 場所 |
| --- | --- |
| セッション全体の折れ線1枚+ピースごとの折れ線 N 枚を縦に並べている | `record_list_screen.dart:756`、`:817` |
| 折れ線の横軸は実時刻で、90分のうち漕いでいない時間にも幅を割く | `_PaceTrendPainter`(`:1084-`) |
| 遅いサンプルを黙って捨て、捨てた点をまたいで線をつなぐ | `session_analyzer_service.dart:181-233` |
| 500m/250m スプリットは計算しているが画面に出していない | `session_analyzer_service.dart:110-150` |
| 1漕距離などのストローク指標は記録しているが画面に出していない | `TrackPoint.distancePerStrokeMeters` 他 |
| **地図がない。** 航跡は GPX に書き出すだけ | `record_list_screen.dart` に地図の widget がない |
| 詳細画面は開くたびに `points` から再解析している | `record_list_screen.dart:492-500` |

最後の行は**良い知らせ**である。新しい画面を作れば、**過去の記録もそのまま新しい画面で見られる。**
移行処理は要らない。

## 2. 他の運動アプリから借りるもの

「記録を見る画面」の作り方として、大きな運動記録アプリには共通の型がある。
そのうち、このアプリの前提(1秒ごとの記録・毎回同じ川・部員どうし・端末内のみ)に合うものだけを借りる。

| 借りる型 | 代表例 | このアプリでの形 |
| --- | --- | --- |
| **地図とグラフの連動**(グラフをなぞると地図上に点が出る) | Strava の分析グラフ、Garmin Connect | カーソル1本を地図・時間軸・グラフで共有する(§3) |
| **グラフ上で範囲を選ぶとその範囲の統計が出る** | TrainingPeaks、GoldenCheetah | 選択区間の4つの数字+1枚のグラフ(§5) |
| **自動で出てくる「ベスト」** | Strava のベストエフォート | 最速500m・1000m・2000m(§7) |
| **セグメント**(決まった区間の毎回のタイム) | Strava のセグメント | 桜川の「橋から橋」固定区間(§7) |
| **ルートをペースで色分けする地図** | Apple フィットネス、Strava | 航跡の色=ペース(任意の表示。§6) |
| **記録の再生** | Relive、Strava の Flyby | 再生ボタン・時間軸・全艇リプレイ(R5) |
| **区間の表**(ラップ・インターバル) | NK LiNK Logbook、rowsandall、Garmin のラップ | ピースの表と、区間内の250m表(2026-08-20 ノートを継承) |
| **動画編集アプリのトリミング** | iOS 写真の動画トリム | 選択区間の両端を指でつまむ/拡大して1秒単位で合わせる(§5.2) |
| **カレンダーと週・月の量** | Strava のトレーニングログ、Garmin | 一覧の上に週ごとの距離の帯(§8) |

**借りないもの。** 公開のリーダーボード、フォロー、いいね、心拍ゾーン、カロリー、
サーバーでの解析。このアプリは端末内で完結し、部員どうしの比較は監視ログの領分である
(2026-08-20 ノート §10)。

## 3. 設計の芯

### 芯1: 時刻は1つ、区間は1つ

画面の状態は次の2つだけで表す。

```
cursor   : 今見ている時刻(1点)
selection: 今選んでいる区間 [開始, 終了](なければ全体)
```

- 地図の艇アイコン、時間軸の赤い線、グラフの縦線は、**すべて `cursor` を描いているだけ**。
- 地図の太線、時間軸の青い帯、4つの数字、グラフは、**すべて `selection` を描いているだけ**。
- どこかを触ったら `cursor` か `selection` を書き換え、全部を描き直す。
  **部品どうしが直接やり取りしない。** これで「地図では3分、グラフでは4分」のような食い違いが原理的に起きない。

### 芯2: 最初は少なく、選んだら深く

| 画面を開いた直後 | 区間を選んだ後 |
| --- | --- |
| 地図(航跡)・4つの数字(距離・時間・ワーク・ピース本数)・時間軸・ピースの表 | 選択区間の4つの数字(ペース・レート・1漕距離・距離/時間)+グラフ1枚+区間内の250m表 |

グラフは**選んだ区間について1枚だけ**描く。指標はチップで切り替える(ペース/レート/1漕距離/速度)。
**グラフを増やして情報を足すことはしない。** 同じ1枚の中身を切り替える。

### 芯3: 入口は多く、出口は1つ

区間の選び方は §5 の6通りを用意するが、どれも最後は `selection = [開始, 終了]` を書き換えるだけ。
**入口ごとに別の画面や別の集計を作らない。** 数字の計算は `RangeAnalyzer`(§10)の1か所だけで行う。

### 引き継ぐ原則(2026-08-20 ノート)

- **ペース・レート・1漕距離は3点セットで出す**(同じペースをどう作ったかが分かるのは3つ並べたときだけ)。
- **除外を黙らない。** 停止・回頭・測位不良で除いた秒数を内訳付きで出し、除外をまたいで線をつながない。
- **上り/下りを区別する。** 川では同じ出力でもペースが違う。ピースと固定区間には必ず方向を付ける。

## 4. 画面構成

縦持ちのスマホ1画面。上から順に:

```
┌──────────────────────────────┐
│ 9/20(土) 06:10  4x          [共有]      │ ← 見出し(日時・艇種)
│ 8.84km ・ 34:00 ・ ピース4本              │
├──────────────────────────────┤
│                                          │
│      地図(航跡・艇アイコン・選択区間)    │ ← 画面の約35%。ピンチで拡大、2本指で移動
│                                          │
├──────────────────────────────┤
│ [▶ 再生]                12:34  1:58/500m r31 │ ← カーソルの時刻と、その瞬間の値
│ ▁▁▁▁████▁▁▁████▁▁▁████▁▁▁████▁▁▁     │ ← 時間軸。濃い帯=ピース、青=選択、赤線=カーソル
│ 0    5    10   15   20   25   30         │
│ [ここから][ここまで]  5:00 〜 9:00 [指定]  │
│ (本1 下り)(本2 上り)(本3 下り)(本4 上り)(全体) │
├──────────────────────────────┤
│ 選択区間 5:00〜9:00(4:00)              │
│ 1:56     31      8.1m     1032m         │ ← 大きな数字4つ
│ ペース   レート  1漕距離  距離            │
│ (ペース)(レート)(1漕距離)(速度)   [時間|距離] │
│ ╭─────────────────────╮       │
│ │    グラフ1枚(選択区間だけ)           │       │
│ ╰─────────────────────╯       │
│ ▸ 250mごとの表                            │ ← 既定は閉じる
│ ▸ 除外した時間 0:12(回頭0:12)           │
├──────────────────────────────┤
│ 自動で見つけた区間                         │
│  最速500m 1:52(本3の中)  最速1000m 1:55  │
│  水郷橋→桜川橋(下り) 3:41  今季ベスト    │

└──────────────────────────────┘
```

- **地図と時間軸は画面上部に固定し、下の数字・グラフ・表だけをスクロールする。**
  下を読んでいる間も、いまどこを見ているかが地図と時間軸から外れない。
  (固定部分は画面高の約55%まで。狭い端末では地図を縮める。)
- 既存の警告エピソード・評価・書き出しは**下へ移すだけで残す**(機能を削らない)。
- 数字は大型・等幅(`FontFeature.tabularFigures`)、タッチ領域48dp以上、ラベルは日本語
  (`ui-design-principles` のメモ)。色はトークン経由で、ダークテーマでも確認する。

## 5. 区間の選び方

### 5.1 6つの入口

| # | 入口 | 操作 | 向いている場面 |
| --- | --- | --- | --- |
| 1 | **ピースをタップ** | 時間軸の濃い帯、またはピースのチップ・表の行をタップ | まず1本ずつ見る。**一番よく使う** |
| 2 | **ここから/ここまで** | 時間軸・地図・再生でカーソルを動かし、「ここから」「ここまで」を押す | 見ながら決めたい。片手で完結する |
| 3 | **分:秒で指定** | 「5:00〜9:00」を入力して「指定」。入力はホイール式の選択にもできる | 「何分から何分」が先に決まっている |
| 4 | **時間軸をなぞる** | 時間軸を長押ししてから横へなぞると、その幅が区間になる | ざっと範囲を切りたい |
| 5 | **地図上の2点** | 地図の航跡を長押し → 開始、もう一度長押し → 終了 | 「あの橋からあのカーブまで」を場所で決めたい |
| 6 | **自動で見つけた区間** | 最速500m・橋から橋の固定区間・警告エピソードをタップ | 何を見ればいいか決まっていないとき |

**表示の優先度(2026-09-24 利用者の判断)。** 2・3(と±1秒・±30秒)は使う場面が少ないので、
「区間を細かく調整」の折りたたみに入れ、既定は閉じる。ボタンは「再生位置を開始にする/終了にする」と動作が分かる言葉にする。

**経過時間の基準。** 「何分」は**航行開始からの経過時間**で表す(`TrackPoint.elapsedMs`、なければ `t` の差)。
時計の時刻(06:15)は見出しと小さな補助表示にだけ使う。コーチの「10分過ぎのあたり」という会話と一致させるため。

### 5.2 指先の精度の問題と解き方

34分の練習を幅332pxの時間軸に並べると、**1pxが約6秒**になる。90分なら約16秒。
指で端を合わせると、**狙いから10〜30秒ずれる**。ここを放置すると「痒いところに手が届かない」。

解き方(動画編集アプリのトリミングと同じ):

1. **端をつまむと時間軸が拡大する。** 選択の端(つまみ)を触っている間だけ、その周辺±60秒を
   時間軸いっぱいに広げる(1px≈0.4秒)。離すと元の縮尺に戻る。
2. **±1秒・±30秒ボタン。** 開始・終了それぞれに −30秒 / −1秒 / +1秒 / +30秒(2026-09-24 利用者指定)。
3. **ピースの端に吸い付く。** つまみがピースの開始・終了の±5秒に入ったら、そこへ吸着する
   (軽い触覚フィードバック。`tactile_feedback.dart` の `selection()`)。
4. **区間の中へ潜る。** 選択中に「この区間に絞る」を押すと、時間軸そのものがその区間の縮尺になる。
   上に「全体 › 本3 › 2:10〜3:40」の階層を出し、タップで戻る。

### 5.3 選んだ区間を残す(マイ区間)

- 選択中に「残す」を押すと、名前(任意・既定は「5:00〜9:00」)を付けて保存する。
- 保存した区間は、ピースのチップの並びの後ろに出る。
- **共有テキスト**を1タップで作れる。LINE にそのまま貼れる形にする:

```
9/20(土) 4x 桜川 5:00〜9:00
1032m 1:56/500m r31 8.1m/漕(下り)
250m: 0:58 / 1:00 / 1:00 / 1:00
```

## 6. 地図・時間軸・グラフの細部

### 6.1 地図

- 航跡の全体を細い灰色、**選択区間を太い色線**で描く。選択の開始は白丸、終了は塗り丸。
- 艇アイコンはカーソル時刻の位置。**向き(方位)の矢印を付ける**。回頭の様子が一目で分かる。
- **航跡をペースで色分けする**表示を切り替えで用意する(既定はオフ)。
  ピース中だけ色を付け、休憩中は灰色のまま(休憩まで色を付けると、遅い区間が全部同じ色で埋まる)。
- 橋・艇庫の名前を小さく出す(`assets/data/sakuragawa_obstacles.json` の `dangerZoneBaselines` の橋7本、
  `ashoreAreas`)。危険区域の塗りは**既定では出さず**、オンにしたときだけ航行画面と同じ描き方で出す(§10.2)。
- 開いたときは航跡全体が収まる倍率。区間を選ぶと、その区間が収まる倍率へ寄る。
- 地図をタップすると、**タップ位置に最も近い航跡点**へカーソルが飛ぶ。往復で同じ場所を2回通るので、
  近い点が複数あるときは**いまのカーソルに時刻が近いほう**を選ぶ。

### 6.2 時間軸

- 帯の3段階: ピース=濃い、ゆっくり漕ぎ=中間、停止=背景色。**警告エピソードの位置に小さな印**。
- 目盛りは5分ごと(練習が60分を超えたら10分ごと)。
- 再生ボタン: 速さ ×10 / ×30 / ×60 / ×100 / ×200 を切替(2026-09-24 利用者指定)。再生中も区間は変えない。
  再生はカーソルを進めるだけで、区間の端に着いたら止まる(区間の外へ勝手に出ない)。

### 6.3 グラフ

- **選択区間だけを1枚。** 縦線=カーソル。グラフをなぞるとカーソルが動く(地図も動く)。
- 指標のチップ: ペース(既定)/ レート / 1漕距離 / 速度。**同時に出すのは1つか、主+薄い副の2つまで。**
- 横軸は「時間」と「距離」を切替。距離にすると 250m 表の行とグラフの位置が一致する。
- 縦軸は**選択区間の範囲で決め、最小幅を持たせる**(ペース±5秒、レート±2、1漕距離±0.5m)。
  セッション全体の最速・最遅には引っ張られない。
- **ペースは上が速い**(漕手の感覚に合わせ、数値の大小と逆向き)。
- 停止・回頭・測位不良は**線を切る**。つながないことで「起きていない変化」を描かない。
- 平滑化の窓は既存の考え方(15秒窓の距離から算出)を引き継ぎ、選択区間が短い(2分未満)ときだけ
  5秒窓に狭める。**窓の長さを画面に小さく書く**(「15秒平均」)。

#### 6.3a 2026-09-24 利用者フィードバックでの確定事項

- 指標は スプリット / SR / DPS の3つ。**艇速は出さない**(低速もスプリットで見る)。
- **縦軸(スプリット)**: 上端=練習中(本・区間の中、最初と最後の8秒を除く)の速い側2%、
  下端=そこから最大40秒(かつ遅い側10%まで)。それより遅い値(パドル・減速・ターン)は下端に張り付く。
  UTのように風向きで20秒以上ばらつく練習でも、1本の中の数秒の変化が見える縦幅を保つため。
  SR・DPSは5〜95パーセンタイル。
- **横軸**: 本(区間)ごとに0から始める。目盛りは30px以上あく「きりのよい」間隔
  (時間 5秒〜30分 / 距離 25m〜5km)で、各本の右端にはその本の長さを必ず書く。
- 本と本の間は固定幅のすき間にして、**レストの時間と距離**を書く(レストも練習強度の要素)。
  内訳の表のレスト欄にも距離を併記する。
- 横軸の切替は「横軸 [時間|距離]」のセグメントボタン。
- **その瞬間の値**は時間軸の下に常設の4マス(経過・時刻 / スプリット / SR / DPS)で大きく出す。
- セットのカードは「区間数」を出さず、漕いだ時間(ハイレートは本数)・距離・SRを出す。

#### 6.3b 2026-09-24 追加の確定事項

- **グラフの操作:** 2本以上あるセットでは、本(区間)をタップするとその本を選んで拡大する
  (「‹ Nセット目の全体に戻る」で戻る)。2本指のピンチで横軸を拡大縮小(×1〜×25)、ダブルタップで戻す。
  区間の選択を変えると拡大は元に戻る。
- **本と本の間の呼び方:** 中身を見て決める。向きが120°以上変わった=**ターン**、
  6割以上止まっていた=**停止**、それ以外=**パドル**(軽く漕いでつないだ)。
  ハイレートのセットでは「レスト」の下にこの3つのどれかを添える。
  実データでは、UTの「間」はほぼすべてターン(向きの変化144〜178°)で、
  ハイレートのレストには止まらずパドルでつないだものがあった。
- **縦軸の目盛り:** きりのよい値。スプリットは5秒(範囲が45秒を超えたら10秒)、SRは2、DPSは0.5m。
  範囲も目盛りに合わせて外側へ丸める。
- **漕いでいた時間:** セットの本・区間の合計時間(練習の強度で漕いだ時間)。「各セット」の表に列を足す。
- **全体のサマリ:** 「全体」を選んだとき、漕いでいた時間・練習時間(艇が動いていた時間)と、
  内訳(UT / AT / ハイレート / パドル・アップ等 / 停止)を帯グラフと表で出す。

### 6.4 比べる(R3)

- 「比べる」を押し、2つ目の区間を選ぶと、**同じグラフに2本目を薄く重ねる**。
  横軸は「区間開始からの経過」にそろえる。本1と本3、今日と先週の同じ固定区間、などを比べる。
- 4つの数字は2段になり、差(+2秒、−1spm)を出す。**良い・悪いの言葉は付けない**。


### 6.5 艇速の推定(タイムの誤差を吸収する)

2026-09-24 に実データで確認した事実: 8/6 の4xで、SR20のまま 2:00→1:44 に跳ぶ区間があった。
原因は 1.1.2 の位置補正(filtered)が2秒で12〜13m跳んだこと(速度換算6.2〜6.7m/s)。
同じ時刻の生GPS位置とGPSが直接測った速度(ドップラー)は、どちらも 3.9〜4.1m/s で安定していた。
**位置を差分してタイムを出すと、位置の跳びがそのままタイムの跳びになる。**

#### 方式(表示専用。安全経路の推定器は変えない)

**候補を版で決め打ちしない。** アプリが記録した値も候補に入れ、記録ごとに当たり具合を測って選ぶ
(2026-09-24 利用者の指摘:「新しいアプリの記録値が良い可能性を、今から切り捨てたくない」)。

| 候補 | 中身 | 独立性 |
| --- | --- | --- |
| GPS位置 | 生GPS位置(前後1点で平滑化)の前後5秒の**弦**÷時間。点ごとの距離を足すとジグザグで距離が伸びるため弦を使う | 擬似距離由来 |
| GPS速度 | `raw_gnss_speed_mps`(`speed_accuracy_mps` ≤ 1.5 のときだけ) | ドップラー由来。位置の跳びと独立 |
| アプリ推定艇速 | `speed_mps`(アプリの推定器の出力) | GPSから作った推定。GPS位置と誤差が相関しうる |
| IMU | `distance_per_stroke_m` × SR ÷ 60 | **GPSと独立ではない。** GNSS艇速の指数平均+IMUのストローク内変化(`rowing_motion_fusion.dart:223-240`) |
| SR×DPS | SR × DPS基準 ÷ 60。DPS基準は前後60秒でGPS位置とGPS速度が一致した点の中央値 | GPS由来の値を「SRが同じなら艇速もほぼ同じ」で延ばしたもの |

1. **全候補を同じ10秒の中心平均にそろえる。** GPS速度は瞬間値で、ストローク内の本物の速度の波
   (数%〜十数%)を含む。時間の細かさが違うまま比べると、本物の波を誤差と取り違える。
2. 各候補の「ほかの候補の中央値からの相対ずれ」の中央値を、この記録の漕行中について測る。
3. **一番ずれの小さい候補の1.6倍(最低2%)以内の候補だけを採用する。** 固定の閾値(例: 一致率60%)は
   候補全体の質が低い記録で良い候補まで外したため採らない(8/6 4x で GPS位置が外れた)。
4. 採用した候補の点ごとの中央値 → 艇種別2000m世界最高(男子)の平均速度×1.02で上限 →
   加速度 0.3 m/s² の制限(前後両方向) → 10秒の中心移動平均。
5. **距離はこの艇速の時間積分、DPS は `艇速×60/SR`。** スプリット・SR・DPSが必ず整合する。
6. どの候補を使ったかを画面に出す(「タイムの推定に使った記録」)。

#### 検証(`scratchpad/speed_eval`、2026-09-24)

**ものさし:** 8/6 の8+に同時に載っていた2台(cox・7番、間隔1.5〜2m)。真の艇速は共通で、
GPS誤差は端末ごとに独立なので、**2台の推定が一致するほど誤差を消せている。**
評価点は両端末とも漕いでいる936時刻に固定し、方式ごとに点数が変わらないようにした。

| 方式 | 2台のスプリット差 中央 / p90 / p99(秒/500m) |
| --- | --- |
| 旧表示(アプリ補正後位置の15秒窓) | 4.52 / 46.1 / 87.4 |
| アプリ推定艇速のみ | 8.94 / 385 / 742 |
| IMU(DPS×SR)のみ | 41.6 / 516 / 711 |
| GPS位置のみ | 1.81 / 5.47 / 16.8 |
| 位置+GPS速度+SR×DPS の中央値(試作 v3) | 1.77 / 5.28 / 17.8 |
| 位置+GPS速度+アプリ推定艇速 の中央値(固定で加える) | 2.42 / 7.14 / 38.4 |
| **全候補+記録ごとの採否(採用案)** | **1.54 / 4.85 / 16.8** |
| 同上+合成の「良いアプリ値」(σ0.04m/s) | 0.94 / 3.03 / 12.8 |
| 同上+合成の「時々大きく外れる値」 | 1.62 / 5.22 / 16.4(自動で除外、悪化なし) |

分かったこと:

- **1.1.2 のアプリ推定艇速・IMU由来の値は、固定で加えると悪化する**(中央値 1.8→2.4秒)。
  採否を記録ごとに決める方式なら自動で除外され(ずれ4〜7%)、悪化しない。
- **良いアプリ値が来れば採用され、精度が上がる**(合成試験。合成値は評価に使う2台の値から作っているため
  改善幅は楽観的。**示せたのは「採用される・悪化しない」という仕組みまで**)。
- SR×DPS は単独でも候補として一定の精度があり、記録によって採用・除外が分かれた(8/5 4x・8/6 8+ で採用)。
- **SRそのものは信頼できる**(2台のSR差 中央0.15 / p99 1.65 spm)。
- 旧版の「SR × DPS上限」は効果が測れず、SRの誤検出で本物の速度を削る危険があるので**削除した**。
  世界最高による上限と加速度制限も、この3記録では効果が測れなかったが、ありえない値への保険として残す。
- 8/6 4x の総距離は 14.97km → 14.44km。旧表示は補正後位置の跳びで距離を約3.5%多く数えていた。

**残る課題:** 8/7以降(推定器を作り直した後)のアプリの記録で、アプリ推定艇速が採用されるかを確かめる。
2台同乗の記録をもう一度取れれば、同じものさしで検証できる。

## 7. 自動で見つけた区間

### 7.0 セットの判定(2026-09-24 利用者と合意)

**単位:** 記録は「セット」に分ける。セットは同じ強度で続けた練習のかたまりで、種類は
UT / AT / ハイレートの3つ。ハイレートのセットの中身は「N本目」、UT・ATのセットの中身は
ターンや停止で切れた「区間」と呼ぶ。**セットの平均は、本・区間の中だけで計算する**
(レスト・つなぎのパドル・ターンの停止は入れない)。

**強度の区分**(British Rowing の5区分 UT2 SR18-22 / UT1 22-26 / AT 26-28 / TR・AN 32-40 を参考に、
部の言い方「UTはSR16〜24(たまに28)、ハイレートはSR28以上でインターバル」に合わせた):

| 種類 | 平均SR | 典型 |
| --- | --- | --- |
| UT | 24未満 | 長い距離を一定のペースで。桜川ではターンで数分おきに止まる |
| AT | 24以上28未満 | 中レートの一定ペース |
| ハイレート | 28以上 | 短い本とレストの繰り返し |

**手順**(ハイレートを先に探す。インターバルのつなぎはSR20前後のパドルで、艇速だけ見ると
「漕いでいる」に入ってしまうため):

1. SRは動いているとき(艇速0.5m/s以上)の値だけを使い、前後4秒の中央値でならす。
   陸上で艇を運ぶ揺れでSR60前後が記録されるため。10〜50の範囲外は捨てる。
2. **ハイレートの本:** SR28以上が15秒・60m以上続いた部分。途切れは6秒まで許す。
   直前のSR25以上(立ち上がりの数ストローク)は本に含める。
3. **インターバルのセット:** ハイレートの本を、間が5分以内ならまとめる。間の時間はパドルでも
   イージーでもすべてレスト。
4. **UT・ATの区間:** 残りの時間から、艇種別の表示基準より速い区間(既存のピース判定。
   60秒・250m以上)を探す。平均SRで種類を決め、同じ種類で停止が4分以内ならまとめる。
5. 各セットに、本・区間の合計から平均を、セットの長さ−漕いだ時間からレスト(停止)を出す。

**画面:**

- 上部のカードはセット単位(「4セット目 ハイレート / ave. 1:49 / 5本・SR34」)。
- セットを選ぶと、選択カードに**内訳**(各本の時間・距離・平均スプリット・SR・次のレスト)を出す。
  行をタップするとその本だけを選ぶ。「‹ セットの全体に戻る」で戻る。
- 時間軸をタップするとセットを選び、選ばれたセットの中をもう一度タップするとその本を選ぶ。
  時間軸の下の細い色帯がセットの範囲(色=種類)。
- 推移グラフは、2本以上あるセットでは**レストを詰めて漕いだ時間だけを並べる**
  (Concept2 のインターバル表示と同じ)。本の境目に点線と番号を出す。
  縦軸の範囲は、各本の最初と最後の6秒(加速・減速)を除いて決める。

**実データでの結果:**

| 記録 | 判定 |
| --- | --- |
| 8/6 4x | UT 8:15〜50:28(6区間・平均2:20・SR20)、UT 2セット、**ハイレート 1:16:51〜1:25:54(5本・各38〜45秒・平均1:49・SR34、レスト計5:32は平均から除外)** |
| 8/5 4x | UT 5セット、ハイレート 2セット(2本ずつ。セット間の5分21秒が「5分以内」をわずかに超えて分かれた) |
| 8/6 8+ | UT 4セット(SR20) |

**調整の余地(利用者の確認待ち):** セットをまとめる間隔(ハイレート5分・UT4分)、
ハイレートの閾値(SR28)、本の最短(15秒・60m)。8/5 の2セットを1セットと見るべきかで5分の妥当性が決まる。


利用者が選ばなくても、候補を出しておく。**どれもタップすれば `selection` になるだけ**(芯3)。

| 種類 | 定義 | 備考 |
| --- | --- | --- |
| ピース | 既存の `detectPieces` | 方向(上り/下り)を付ける |
| **ベスト区間** | 最速の 500m / 1000m / 2000m(距離で区切る。ピースの中に限る) | 距離の累積和+2本の指で O(n)。停止をまたがない |
| **橋から橋** | 航路中心線の上の、橋の位置で区切った区間を通過した時間 | 桜川の「セグメント」。方向別に日をまたいで比べられる |
| 警告エピソード | 既存の `detectAlertEpisodes` | 「そのとき何が起きていたか」を地図で再生できる |

**橋から橋の作り方。** 航路中心線(`channelCenterlines`)に沿った距離(along)へ、
各橋の基準線の中点を投影して「中心線上の何m地点にどの橋があるか」を1回だけ作る。
航跡の各点も along へ変換し、along がある橋の地点を越えた時刻を線形補間で求める。
隣り合う2つの橋を**同じ向きに、止まらずに(途中の停止が一定秒数以下で)**通過したら1回の区間とする。
中心線が引けない場所・水域では作らない(**縮退**。他の機能は止めない)。
`ChannelCenterline` は安全経路の部品だが、**読み取りで使うだけ**で、変更しない(§11)。

## 9. 監視端末の全艇リプレイ(R5)

監視中の練習一括ログ(`PracticeLogPoint`: 全艇の時刻・位置・速度・針路)には、
**全艇が同じ時間軸で入っている**。これを同じリプレイ画面で開けば:

- 時間軸を動かすと、**全艇のアイコンが同時に動く**(艇ごとの色は `assignBoatTrackColors` と同じ)。

- 「本3のとき、各艇はどこにいたか」「すれ違いがどこで起きたか」を、練習後のミーティングで見せられる。

制約:
- 監視ログは2〜3秒間隔で、艇側の1秒記録より粗い。レート・1漕距離は入っていない。
  **全艇リプレイでは位置と速度だけを扱う。**
- 受信の欠測(`gap`・`recorder_gap`)は**線を切り、アイコンを灰色にする**
  (空白を「そこにいなかった」と読ませない。CLAUDE.md の練習一括ログの節)。
- 記録された警告状態(`presentationState`)は、振り返りの印として時間軸に出すだけ。
  **衝突評価や航行中の地図へは戻さない**(不変条件12)。

## 10. 実装の構成

### 10.1 新しい部品(すべて純Dart、表示専用)

| 部品 | 役割 | 計算量の目安(2時間=7,200点) |
| --- | --- | --- |
| `SessionTimeline` | 点列を経過時間で引く(二分探索)・区間の点を切り出す・欠測の区切りを持つ | 構築 O(n)、引くのは O(log n) |
| `RangeAnalyzer` | 区間の距離・時間・ペース・平均レート・1漕距離・除外秒数・区間内250m表 | 累積和で O(1)〜O(区間長) |
| `MetricSeriesBuilder` | 区間のグラフ用の系列(平滑化・欠測で切る・画面幅に合わせた間引き) | 間引き後300点程度 |
| `BestEffortFinder` | 最速500/1000/2000m | 2本の指で O(n) |
| `ChannelSegmentMatcher` | 橋から橋の通過区間 | O(n)、中心線は読み取りのみ |
| `ReplayController`(フック) | `cursor` と `selection` の2つの状態と、再生タイマー | 状態の持ち主はここだけ |

画面の widget は `ReplayController` の状態を読んで描くだけにする(芯1)。
**数字を widget の中で計算しない。** 計算は `RangeAnalyzer` だけに置き、単体テストを付ける
(CLAUDE.md「安全判定に関わる純粋ロジックは純Dartへ」と同じ作法を、表示にも使う)。

### 10.2 地図

- 既存の `google_maps_flutter` を使い、**航行画面とは別の `GoogleMap` を記録画面の中に置く**(2026-09-24 利用者と合意: 地図はアプリと同じもの)。
  危険区域と航路は航行画面と同じ描画データを使い、**「危険区域(全種類まとめて)」「航路」の2つのオンオフ**を付ける。既定は航路オン・危険区域オフ。
  航行用の `use_nav_map.dart` は使わない(警告用の描画ルールを持ち込まない)。
- 艇アイコンを動かす方法は2案あり、**R1の最初に試作して決める**:
  - 案A: 地図の `Marker` を動かす。単純だが、更新がプラットフォームとの往復になり、
    指で時間軸をなぞる速さ(1秒に数十回)に追いつかず引っかかる恐れがある。
  - 案B: 艇アイコンだけは地図の**上に重ねた Flutter の描画**で出し、画面上の位置は
    地図の投影から計算する。なぞりに追いつきやすいが、地図を動かしている間の追従に手当てが要る。
  - どちらでも、なぞっている間は更新を1秒に15回程度に間引き、指を離したら正確な位置に置き直す。
- iOS の Apple Maps 移行(`要件定義_2026-08-03_iOS版AppleMaps移行.md`)は未着手である。
  記録画面の地図は、線・円・アイコン・カメラ移動しか使わないので、移行時に差し替えやすいよう
  この4つだけに依存する小さな窓口を作っておく。

### 10.3 保存

- 選択の状態・再生位置は**保存しない**(開くたびに全体から始める)。
- マイ区間と★の固定区間だけを保存する。セッションの JSON に任意項目 `userRanges` を足す
  (前例: `alertEpisodeRatings`)。`schemaVersion` を上げ、旧版の記録はそのまま読める。
- 自動の区間(ピース・ベスト・橋から橋)は**保存せず、開くたびに計算する**
  (解析ロジックを直したとき、過去の記録にも反映されるように)。
  一覧・ダッシュボード用の要約だけは保存値を使う(一覧で全記録を再解析すると重い)。

## 11. 安全との境界

- **記録画面は表示専用で、安全経路へ何も戻さない。** 新しい部品は `lib/services/` の
  安全経路の部品を import してよいのは `ChannelCenterline`(読み取り)と `SessionAnalyzerService` だけ。
  逆方向(安全経路 → 記録画面の部品)の import は作らない。
- **航行中は開けない**(今も `home_map_screen.dart:641-644` で航行中はメニューに出さない。これを維持する)。
  ただし現状、メニューに出る条件は `isObserver`(`NavMode.observer`)**だけ**で、
  モードは `observer` / `navigator` の2つしかない(`lib/types/nav_mode.dart`)。
  つまり**漕手が陸へ上がって自分の記録を見るには、監視モードへ切り替える必要がある。**
  記録を見る場面を増やすなら、入口を「航行していないとき」へ広げる(§14-6)。
- **監視中は開ける。** 監視端末は記録画面を開いたまま練習一括ログの記録と監視表示を続けるので、
  2つ目の地図と解析が監視側を重くしないことを確かめる。解析は画面を開いたときに1回だけ走らせ、
  再生中に繰り返さない。**記録画面の失敗が監視表示・一括ログの記録を止めてはならない**(CLAUDE.md の練習一括ログの節)。
- 不変条件12・13を守る: 他艇の警告状態と1ストロークの波形は、記録画面でも衝突評価へ渡さない。

## 12. 段階計画

各段階で、**その段階だけで使える状態**にする。途中で止めても前より悪くならない。

| 段階 | 内容 | 使えるようになること |
| --- | --- | --- |
| **R1 骨格** | 地図+航跡+艇アイコン、時間軸(ピースの帯・カーソル)、ピースをタップして区間選択、選択区間の4つの数字+グラフ1枚。**古い折れ線(全体1枚+ピースごと N 枚)を撤去** | 利用者の要望の中心(地図・スライダー・区間のグラフ)がここで全部そろう |
| **R2 選び方** | ここから/ここまで、分:秒入力、時間軸のなぞり、端の拡大と±1秒、区間へ潜る、マイ区間、共有テキスト | 「痒いところに手が届く」部分 |
| **R3 数字の信用** | 回頭・測位不良の除外と内訳、線を切る、区間内250m表、上り/下り、比べる(重ね描き)、航跡のペース色分け | 数字を信じて議論できる |
| **R4 自動の区間と一覧** | ベスト区間、橋から橋、一覧のダッシュボード、固定区間の推移、再生の速さ切替 | 日をまたいだ伸びが見える |
| **R5 全艇リプレイ** | 監視ログを同じ画面で再生 | 練習後のミーティングで使える |

**最初に作るのは R1 だけ**。R1 の中で地図アイコンの動かし方(§10.2 の案A/B)を実機で決める。

## 13. テスト

- `RangeAnalyzer`: 区間の距離・時間・ペースが既存の `analyze` と一致すること(全体を選んだとき)、
  `ペース = 500×60 /(1漕距離×レート)` が±1%で閉じること、除外をまたがないこと、
  区間の端がピースの途中でも正しく切れること。
- `SessionTimeline`: 経過時間の引き当て、`elapsedMs` がない旧記録、時刻の飛び・逆行。
- `MetricSeriesBuilder`: 欠測で線が切れること、間引いても最速・最遅の点を落とさないこと。
- `BestEffortFinder`: 総当たりと同じ答えになること(ランダムな点列で比べる)。
- `ChannelSegmentMatcher`: 往復・途中停止・中心線なしの縮退。
- 画面: 区間を選ぶと4つの数字・グラフ・地図の太線が同じ区間を指すこと(芯1の回帰)。
- 既存の `test/services/session_analyzer_test.dart`・`gpx_export_test.dart` は維持する。
- 実機: 2時間の記録でなぞりが引っかからないこと、監視中に開いても監視表示が止まらないこと。

## 14. 利用者に決めてもらいたいこと

1. **R1 の範囲。** 上の R1 でよいか(ここから/ここまで・分:秒入力は R2 へ回している)。
   「分:秒で指定」を R1 に前倒しすることもできる。
2. **時間軸の「何分」の基準。** 航行開始からの経過(案)か、時計の時刻か。
3. **グラフの既定の指標。** ペース(案)か、速度(m/s)か。
   「スピード推移」という言葉を、ペースで出してよいか。
4. **マイ区間の共有範囲。** 端末内だけ(案)でよいか。部員への共有は共有テキストだけにするか。
5. **全艇リプレイ(R5)の優先度。** 監視端末でコーチ役が使う場面があるか。
6. **記録画面の入口。** 今は監視モードのときだけメニューに出る。
   航行モードでも「航行していないとき」は開けるようにするか(案: 開けるようにする。航行中は今どおり出さない)。

## 15. やらないこと

- 安全経路の変更。航行中に記録画面を開けるようにすること。
- サーバーへの送信・部員どうしのランキング・評価の言葉(「良い」「悪い」)。
- グラフの枚数を増やして情報を足すこと(1枚の中身を切り替える)。
- 手入力の強制。タグ・名前はすべて任意。
