# GPS品質別の警告解除確認時間仕様

作成日: 2026-07-16  
ステータス: 実装済み（自動テスト通過、実艇確認待ち）  
対象: 他艇接近、危険区域、案内区域、システム異常を含む全警告  

## 1. 目的

桜川は川幅が約40mと比較的狭く、GPSの一時的な揺れや他艇位置の境界判定によって、警告が頻繁に鳴る可能性がある。

現在の警告解除確認は一律で「3秒継続かつ3観測」である。この時間は安全側ではあるが、危険条件が解消した後も警告音・表示が残りやすい。

本仕様では、GPSおよび位置データの品質に応じて解除確認時間を短縮し、警告の信頼性と利用しやすさを両立する。

## 2. 現在の実装（変更前）

### 2.1. 評価周期

- GPSストリーム自体は端末によって1秒未満の間隔で位置を返す場合がある。
- アプリは高頻度の位置を最新1件へ集約し、リスク評価を約1秒周期に間引く。
- 通常の有効な自艇GPS評価1回が、解除確認上の新しい観測1件に相当する。
- GPSが欠測、棄却、使用不能の場合、その回は安全確認の観測として数えない。

関連実装:

- `lib/config/navigator_config.dart` の `positionUpdateInterval = 1`
- `lib/hooks/use_navigator.dart` の `processPosition()` による約1秒周期の間引き
- `lib/services/alert_state_machine.dart` の解除確認カウンタ

### 2.2. 現在の解除条件

本番の既定値は次のとおりである。

| 項目 | 現在値 |
|---|---:|
| 解除確認時間 | 3秒 |
| 必要な解除観測 | 3観測 |
| 条件 | 時間と観測回数の両方を満たす |

警告が安全候補になった最初の評価を時刻`t0`とすると、理想的な1Hz評価では次のようになる。

```text
t0:  解除確認1回目
t1:  解除確認2回目
t2:  解除確認3回目（観測回数は満たすが、経過時間は2秒）
t3:  3秒経過。解除可能
```

したがって、現在の設定は通常、解除確認開始から約3秒後に解除される。

## 3. 採用仕様

### 3.1. 品質別の解除確認条件

| 解除時のデータ品質 | 解除確認時間 | 必要観測 | 解除の意味 |
|---|---:|---:|---|
| `good` | 2秒以上 | 2観測以上 | 通常の解除ポリシー |
| `degraded` | 3秒以上 | 2観測以上 | 確認開始から最大3秒へ延長 |
| `unusable` | 最大3秒 | 追加の安全観測は不要 | 古い物理警告を終了し、継続中の異常警告へ切り替える |

### 3.2. 具体的な時系列

#### GPS品質が`good`の場合

```text
t0:  安全判定1回目
t1:  安全判定2回目、1秒経過。まだ解除しない
t2:  2秒経過
     -> 解除
```

時間と観測数の両方を満たす必要がある。高頻度GPSが届いても2秒より早くは解除しない。

#### GPS品質が`degraded`の場合

```text
t0:  安全判定1回目
t1:  安全判定2回目
t2:  2秒経過。まだ解除しない
t3:  3秒経過
     -> 解除
```

#### GPS品質が`unusable`の場合

```text
t0:  安全判定1回目。解除確認開始
t1:  unusable。観測数には加えないが、時計は止めない
t2:  unusable。3秒ポリシーを維持
t3:  3秒経過
     -> 古い物理警告は解除
     -> GPS異常・他艇通信途絶などが継続中なら、異常警告は継続
```

`unusable`時にアプリ全体を安全状態とは表示しない。衝突音を無限に鳴らす代わりに、3秒後は原因に応じたシステム異常警告へ切り替える。

## 4. 品質の決め方

### 4.1. 基本方針

他艇警告では、自艇GPSと対象他艇の位置データを含めて品質を決める。ただし、品質が変わるたびに解除確認をやり直すことはしない。

```text
確認時間 = 通常は2秒
確認中に自艇・他艇・評価処理のいずれかが劣化 = 最大3秒
```

例えば、自艇GPSが`good`でも、対象他艇の位置が古ければ`degraded`として扱う。

### 4.2. 品質区分

初期実装では、既存の品質区分を利用する。

- `good`: 有効なGPS評価が継続し、位置データの鮮度・精度に重大な問題がない
- `degraded`: GPSの精度低下、連続的な測位棄却、対象他艇データの不確実性などがあるが、評価自体は継続できる
- `unusable`: GPS途絶、位置データ使用不能、評価処理停止などにより、安全確認の根拠がない

`degradedGpsAccuracyThresholdMeters = 25m`は、ロバスト位置推定が有効な場合の
`good`と`degraded`の境界として使う。25mを超えた測位も一律には棄却せず、
accuracyに応じてKalman観測の重みを下げ、推定不確実性を広げたまま、
警告・危険判定・記録・位置共有を継続する。座標不正、時刻切れ、
mock測位など、推定器へ安全に渡せない測位だけを`unusable`側で扱う。

## 5. 状態遷移

### 5.1. 通常の解除

```text
alerting
  ↓ 危険候補なし + goodな解除根拠
clearing（2秒・2観測以上の確認）
  ↓ 条件達成
safe
```

```text
alerting
  ↓ 危険候補なし + degradedな解除根拠
clearing（3秒・2観測以上の確認）
  ↓ 条件達成
safe
```

### 5.2. 確認中に危険へ戻った場合

解除確認中に同じ警告対象が再び危険候補になった場合は、解除しない。

```text
clearing -> alerting
```

解除確認時間と観測カウンタはリセットする。これにより、GPSの一瞬の揺れで「警告停止→直後に再警告」となる点滅を抑える。

### 5.3. 確認中に品質が悪化した場合

- 解除確認の開始時刻と有効観測数は引き継ぐ。
- 確認中に一度でも`degraded`または`unusable`になった場合、必要時間を3秒に延長する。
- その後`good`へ回復しても、その確認窓は3秒ポリシーのまま継続する。
- `unusable`が続いても経過時間はリセットせず、3秒で古い物理警告を終了する。
- 原因となるGPS・通信・評価処理の異常がまだ存在する場合は、その異常警告は継続する。

## 6. 対象範囲

### 6.1. 対象にするもの

- 他艇接近警告の解除確認
- 危険区域警告の解除確認
- カーブ・逆走などの案内区域の解除確認
- GPS・通信・音声・評価処理などのシステム異常が復旧した後の解除確認
- 通信途絶後、他艇の新しい位置を受信した後の警告解除確認
- GPS揺れによる一時的な危険候補消失への解除遅延

### 6.2. 今回変更しないもの

- 警告を開始する条件
- `warningTime`および停止距離の計算
- 現在重なっている場合や行動期限2秒以下の即時警告
- 通信途絶と判定する条件と、異常が続く間の通信途絶警告の表示条件
- 警告音の種類、音量、再生方式
- 他艇への位置送信間隔
- 画面上に「解除確認中」と表示するUIの追加

## 7. 実装内容

全警告の解除確認を共通化し、通常は2秒、確認中に品質劣化があれば3秒とした。

実装箇所:

1. `AlertStateMachine`に全警告共通の解除ポリシーを定義した
   - 通常: 2秒・2有効観測以上
   - `degraded`: 3秒・2有効観測以上
   - `unusable`: 明示的な異常証拠が継続しても3秒で古い物理警告を終了
2. `SafetyOrchestrator`で自艇品質と対象他艇品質の悪い方を`AlertClearEvidence.dataQuality`へ反映する
3. 他艇データの鮮度が3秒未満なら`good`、3秒以上6秒未満なら`degraded`、6秒以上なら`unusable`とした
4. 解除確認中に品質が変わっても、開始時刻と有効観測を引き継ぎ、その窓で最も悪い品質の時間を使う
5. 同一観測IDは重複加算せず、高頻度GPSの受信で解除が早まらない既存制御を維持した

## 8. 必須テスト

### 8.1. 状態機械テスト

- `good`で1観測だけでは解除されない
- 通常品質で2秒未満では解除されない
- 通常品質で2秒かつ2有効観測以上で解除される
- 品質劣化があると3秒未満では解除されない
- `unusable`が続いても3秒で古い物理警告が終了し、異常警告は残る
- 品質が変化しても確認をやり直さず、最も悪い品質の3秒ポリシーで続行する
- `clearing`中に危険候補が戻ったら`alerting`へ戻る
- 同一観測IDの重複は観測回数に加えない

### 8.2. GPS・実機相当テスト

- 1Hzの正常GPSで、通常解除が約2秒後に完了する
- GPS更新間隔が1秒を超えた場合、解除が遅れても安全側に動く
- 高頻度GPSが届いても、約1秒周期の評価以上に解除が速くならない
- GPS測位が棄却された場合、その測位で解除されない
- 40m幅の水域で、警告の停止・再開が頻繁に発生しない
- 3m/s前後の艇速で、解除確認中の警告残留時間を計測する
- 2艇の相対速度が高い場合、解除短縮による警告漏れがないことを確認する

### 8.3. 回帰条件

- 現在の衝突警告の開始タイミングが変わらない
- 危険が継続している場合、GPS品質が`good`でも警告が解除されない
- 通信途絶を安全と誤認しない
- `flutter test`が通過する
- `dart analyze`で新たなエラーを発生させない

## 9. 受け入れ基準

次をすべて満たした場合に、実装を受け入れる。

1. 通常品質では、異なる2観測以上・2秒以上で解除される。
2. 解除確認中に品質劣化があれば、進捗をリセットせず3秒ポリシーで続行する。
3. `unusable`が続いても古い物理警告は3秒で終了し、原因となる異常警告へ切り替わる。
4. 解除確認中に危険が戻った場合だけ、警告状態へ戻り解除進捗をリセットする。
5. 高頻度GPSの受信によって解除だけが過剰に速くならない。
6. 40m幅の桜川で、現行3秒設定より警告残留時間が短くなる。
7. 短縮後も警告漏れ、通信途絶の安全誤認、警告の無音化が発生しない。
