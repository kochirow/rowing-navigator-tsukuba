# 衝突警告 安全レビュー報告 2026-07-26

対象: 2026-07-26 実機テスト後の過剰警告改善(要件定義
`docs/design_notes/2026-07-26_実機テスト後_過剰警告改善_要件定義.md`)一式。

変更の性質上、**このレビューは「鳴らす量を減らす変更が、鳴るべき警告まで消していないか」**を
主眼に置く。過剰警告の是正はすべて false negative を増やす方向に働きうるため、
減らした各経路について「どこまでなら消えてよいか」の上界を数値で押さえた。

## 1. サマリ

| 重大度 | 件数 |
| --- | --- |
| S1(警告漏れに直結) | **2**(いずれも本レビュー中に修正済み) |
| S2(条件が重なると寄与) | 3 |
| S3(品質・保守性) | 2 |

S1 は 2 件とも、6つの並行実装をまとめて配線した `lib/hooks/use_navigator.dart` で
発生していた。個々のサービスは正しく、**配線でデバウンス後の値・固着した状態を
安全判定へ流し込んでいた**のが原因。両方ともこのレビュー内で修正し、再検証済み。

## 3. 所見一覧

### S1-1: 受信faultのデバウンス値を送信間隔に使い、自艇が他艇から消える窓を作っていた

- 該当箇所: `lib/hooks/use_navigator.dart` 送信間隔算出(`sendIntervalSecondsFor` の呼び出し)
- 再現シナリオ: 他艇の受信ストリームが落ちる。デバウンスは15秒後に確定するため、
  その15秒間 `isDynamicReceiveUnavailable` は false のまま。受信が落ちているので
  `otherBoats` は TTL 経過で空になり `otherBoatNearby` も false。
  自艇が 0.5m/s 未満なら `sendIntervalStoppedSec` = **10秒送信**になる。
- 影響: 受信側の予測TTL(`boatPredictionTimeoutSeconds` = 6秒)を超えるため、
  **自艇が他艇の衝突評価から 10秒周期のうち約4秒間消える**。
  「他艇が見えない艇ほど、他艇からも見えなくなる」相関故障で、
  `send_policy.dart:15-22` が明示的に防いでいたはずの経路を再び開けていた。
  FN(自艇ではなく**相手艇側**の警告漏れ)。
- 修正: 送信間隔には**生の劣化フラグ**を渡す。デバウンスは
  「system fault として鳴らす」までの猶予であって、送信を遅らせてよい根拠ではない。
  落ちていないのに短い間隔で送るのは通信量だけの問題で安全側。
  ```dart
  receiveUnavailable: rawDynamicReceiveDegraded.value ||
      isDynamicReceiveUnavailable.value,
  ```

### S1-2: GPS途絶中に陸上判定が固着し、音声チャンネル全体が止まりうる

- 該当箇所: `lib/hooks/use_navigator.dart:637`(修正後のヘルパー), 呼び出し `:1361, :2075, :2094`
- 再現シナリオ: 艇庫で陸上判定が確定(`isAshore = true`)。出艇直後に測位が途絶する。
  陸上判定は `processPosition` の中でしか更新されないため、測位が来ない間は
  **直前の true が固着**する。
- 影響: 陸上ゲートは持続音(`:2933`)と単発キュー(`:1547`)の両方を止めるので、
  **水上にいるのに全警告音が GPS 復帰まで無音**になる。
  さらに `gps_unavailable` の system fault 自体も無音化されるため、
  「音が出ていないこと」に気付く手段も同時に失われる。
- 修正: GPSが使えない3経路すべてで陸上判定を解除する
  (`clearAshoreForUnusableGps()`)。`AshoreDetector` 自身も
  `gpsQualityUsable == false` では陸上と判定しない設計なので、
  「判定できない間は音を戻す」で一貫する。データ欠損を無音の根拠にしない(原則6)。

### S2-1: 斜めに寄せながら重なっている場合、最大5秒の無音窓ができる

- 該当箇所: `lib/services/safety_orchestrator.dart:700-735`
- 再現シナリオ: 自艇 0.5m/s(安定停止しきい値 0.4m/s より上)で、危険区域との
  距離が 0.2m/s で縮まっている。接近速度が 0.3m/s 未満なので連続音へ上げず、
  猶予 5秒の後に表示のみへ落ちる。再武装は 2m 接近時=10秒後。
  → **5秒間の無音**の後、再び連続音。
- 影響: FN 寄与。ただし上界は「2m の接近ごとに必ず1回鳴る」で閉じている。
- 重大度判断: 岸の危険区域は基準線から水面側5m あり、そこへ 0.2m/s で寄る状況は
  岸まで最短でも 25秒以上ある。連続音の信頼性を回復する利得の方が大きいと判断した。
- 対処方針: **修正しない。** 上界を本報告と `alert_presentation_config.dart` の
  コメントに明記して受け入れる。無音窓を縮めたい場合は
  `staticOverlapImminentGrace` を短くするのが唯一の調整点。

### S2-2: 陸上判定中に発行された単発合図はそのエピソードで失われる

- 該当箇所: `lib/hooks/use_navigator.dart:1547`
- 再現シナリオ: 陸上判定中に橋・カーブ・逆走の cue が `oneShotAudioCues` に載る。
  ゲートで再生をスキップするが、orchestrator 側は `eventId` を発行済みとして
  記録しているため、同じエピソードでは二度と出ない。
- 影響: 陸上判定が誤っていた場合、その1回の合図だけ失われる。
- 対処方針: **修正しない。** 区域進入は退出後に再武装し、橋は次の接近で
  新しいエピソードになるため、恒久的な喪失にはならない。
  誤判定そのものは S1-2 の修正と画面表示・手動解除で対処済み。

### S2-3: 岸の掃引横幅を縮めたぶん、岸へ真横から押される状況の余裕が減る

- 該当箇所: `lib/config/risk_evaluator_config.dart:83`
- 再現シナリオ: 強い横風・流れで、進行方向と無関係に真横へ 押される。
  横方向の検知余裕が片側 4.5m → 3.0m(+GPS帯)になる。
- 影響: 横方向の予告距離が 1.5m ぶん短い。5章の表で
  accuracy 5m のとき 10.10m → 8.60m。
- 重大度判断: 前提1.4「岸から数mを走るのは正常」であり、
  変更前は狭所レーン中央(11.25m)との余裕が **0.25m** しか無く、
  規定どおりの操舵で鳴っていた。これは原則4に照らして不具合である。
  横方向の漂流は近接注意(`shoreProximityCautionDistanceMeters` = 3.0m、未変更)が
  引き続き担当する。
- 対処方針: **意図した変更として受け入れる。** 実データ回帰テスト
  `test/services/static_sweep_clearance_test.dart` が実効値を固定している。

### S3-1: S1-1 / S1-2 はフック層のためユニットテストで固定できていない

`useNavigator` は Firebase・geolocator・音声に依存し、単体テストの
ハーネスが無い。両修正ともコードコメントで根拠を残したが、
自動回帰は無い。将来、送信間隔の決定と陸上ゲートを純関数へ切り出せば固定できる。

### S3-2: system fault 専用音が macOS 合成音声の仮アセット

`assets/audio/system_fault_warning.mp3` は他の録音アセットと声質が揃わない。
機能に影響しないが、同じファイル名で差し替えることを推奨。

## 4. 境界シナリオのトレース記録

1. **微速 0.3m/s で危険区域へ横向きに漂流** — 速度が安定停止しきい値 0.4m/s 未満のため
   `_stableStopped` が支配。脅威が停止前から存在すれば従来どおり表示のみ、
   停止後に新規出現すれば単発音。**今回の変更前後で挙動は同じ**
   (steady-overlap ゲートは低速帯では既存抑制に飲まれる)。
2. **8+(5.5m/s)と 1x(0.6m/s)の交差** — 他艇経路は未変更。連続SAT掃引のため
   相対移動量によるすり抜けは原理的に発生しない。
3. **2艇が並走、双方 GPS 誤差 10m** — 他艇経路は未変更。
   `pairGpsCenterDistanceGuardFactor` 0.20 × 合成誤差(上限 2.5m)がそのまま効く。
4. **停止中の艇に背後から接近** — `_canSuppressAtRest` が `other_boat` を除外
   (`safety_orchestrator.dart:704-707`)。steady-overlap ゲートは他艇に適用されず、
   重なれば即 imminent。`safety_orchestrator_presentation_test.dart:226` が固定。
5. **相手端末の時計が ±5秒ずれ** — 外挿・鮮度判定は未変更。
   受信fault のデバウンスは `at` に端末時計を使うが、
   これは fault の提示遅延にのみ影響し、鮮度階層には触れない。
6. **頂点2点・自己交差のポリゴン** — `points.length < 3` で `invalid_static_geometry`。
   三角分割が投げた場合も catch が距離ベースの円フォールバックへ落とす(C2)。
7. **警告距離の境界ちょうど** — 連続掃引に評価刻みが無いため、
   境界の取りこぼしが構造的に発生しない。
   岸の実効発報距離は 5章の表のとおり実データテストで固定済み。
